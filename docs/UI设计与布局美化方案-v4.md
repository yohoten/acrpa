### 1.2 问题 A：表面层级坍塌（最影响"高级感"）

`ui/theme.py` 定义了 **13 个表面键**，实测只有 **4 个可辨层级**，相邻两级 ΔL\* 普遍 < 3（人眼分辨阈值约 3）。

| 键 | 亮色值 | L\* | 与上一级 ΔL\* | 判定 |
| --- | --- | --- | --- | --- |
| `bgc` / `logbg` / `ebg` | `#FFFFFF` | 100.00 | — | 三个键**完全同色** |
| `surface_alt` / `zebra` | `#FAFAFA` | 98.27 | 1.73 | 不可辨 |
| `gutter_bg` | `#F6F6F6` | 96.88 | 1.39 | 不可辨 |
| `bg` / `row_hover` | `#F3F3F3` | 95.84 | 1.04 | 不可辨，且**行悬停 = 页面底色** |
| `heading_hover` | `#F0F0F0` | 94.80 | 1.05 | 不可辨 |
| `caption_hover` | `#E9E9E9` | 92.35 | 2.45 | 不可辨 |

深色侧同病：`bgc #2B2B2B`(17.53) → `surface_alt #262626`(15.16) → `bg #202020`(12.25)，ΔL\* 2.37 / 2.91，`heading_hover` 与 `caption_hover` **同为 `#333333`**。

**直接后果**：卡片、表格、日志面板、侧栏全都贴在同一个亮度面上 → 界面"平"、窗口边界靠 1px 边框硬撑、行悬停几乎看不出来。**这是"不好看"的第一原因，且它无法靠加阴影解决（tkinter 没有原生阴影）。**

亮色侧唯一成立的层次是 `bg #F3F3F3` ↔ `bgc #FFFFFF`（ΔL\* 4.16）——这说明 v1 的 page/card 两级是对的，问题在于后来往中间塞了 5 个近白色。

### 1.6 问题 E：符号语义不统一

**168 个符号字符**，同一语义存在两种写法：

| 语义 | 写法 A | 写法 B | 合计 |
| --- | --- | --- | --- |
| 成功 | `✔` × 25 | `✓` × 14 | 39 次，**两种字形混用** |
| 失败 | `✘` × 30 | `✗` × 3 | 33 次，**两种字形混用** |
| 警示 | `⚠` × 41 | — | 41 次，字号与基线未统一 |
| 其他 | `⚙`11 `☰`4 `★`4 `✚`4 `✉`4 `⚑`3 `☆`3 `✦`3 `⚒`3 `⛁`3 | | |

成因：`✔/✘` 是全角粗体（BMP Dingbats），`✓/✗` 是细笔画；两者字形重量差明显，同屏出现像两种字体。

### 1.7 问题 F：从窗口骨架欠账（v3 P1 未完成）

`ui/window_shell.py`（284 行）已就绪，但只迁移了 `dialogs.py` 的 2 个试点窗口。`help_window.py`（1,165 行，22 处符号）、`market_window.py`（1,838 行）、`ui/settings/window.py` 仍各自维护字面量几何与外边距。跨窗口的"同一种窗口该长什么样"仍未统一。

## 2. 设计原则（v4 新增五条）

1. **层级靠明度，不靠边框。** tkinter 画不出阴影，就让每一层表面 ΔL\* ≥ 3；边框只做"收边"，不承担分层。
2. **分类色不是文字色。** 分类色用于色块/色条时只需 3:1（图形对比度）；一旦配到文字上就必须 4.5:1。两者不能共用一套色值。
3. **一种语义一种颜色。** 强调蓝只允许 `#0078D4`（亮）/ `#4CC2FF`（暗）；`#2563EB` 一律退出客户端。
4. **4pt 网格 + 4 档间距。** 4 / 8 / 12 / 16，1px 仅用于发丝线。
5. **符号一种写法。** 每个语义只保留一个字形，字号跟随 `FONT_SMALL`，基线跟随 `icon_size()`。

### 3.3 为什么"染色悬停"比"加深灰"更好

`row_hover` 从 `#F3F3F3` 改 `#E5F1FB`：明度只变 ΔL\* 5.46，但**色相从灰变蓝**，比单纯加深更易识别，且与强调蓝同族，视觉上"选中感"更强。这是 Windows 资源管理器、VS Code 列表悬停的通行做法，也符合 v1「Windows 血统」定位。

### 3.4 风险与回退

- 改 `bd` / `row_hover` 会影响全应用观感，属于**有意的视觉变更**，需截图比对。
- 回退开关：`ui/theme.py` 增加 `_SURFACE_V4 = True`，置 `False` 时返回旧色表（保留旧值常量），无需回滚代码。

## 4. 方案 B：分类色与文字色分离（P0 + P2）

### 4.1 两条路

| 方案 | 做法 | 收益 | 成本 | 阶段 |
| --- | --- | --- | --- | --- |
| **B1 双套分类色** | 保留彩色命令名，为明/暗各出一套达 AA 的取值 | 可读性达标；改动仅 `colors()` + `_CMD_COLORS` 取值 | 低 | **P0** |
| **B2 色条承载分类** | 命令名统一 `fgb` 中性色；分类色只做行首 4px 色条 + 图例色块 | 同屏颜色噪声大降，表格更"专业"；色条只需 3:1 | 中（需改 tag 与图例渲染） | P2 |

**建议 B1 先做**（当天可完成、可量化验收），B2 作为设计升级单独评估——B2 更接近 Excel/IDE 的观感，但会改变现有"彩色命令名"的用户习惯，需要你确认。

### 4.2 B1：10 组双套分类色（已验证全部 ≥ 4.5:1）

按现有 10 个图例分组（`_LEGEND_ITEMS`），色相拉开并逐组验证：

| 键盘（按键/按下/释放） | `#6D28D9` | 7.10 | `#C4B5FD` | 7.67 |
| 热键 | `#B91C1C` | 6.47 | `#FCA5A5` | 7.46 |
| 输入 / 等待 | `#B45309` | 5.02 | `#FCD34D` | 9.82 |
| 坐标 | `#475569` | 7.58 | `#94A3B8` | 5.52 |

已知取舍：其中 4 组色相间距偏近（输入/悬停 8.5°、截屏/定位 9.0°、代码/滚轮 10.3°、截屏/坐标 14.0°）。作为**文字色**使用影响很小（不同行不同位置），但在图例色块上并排会比较接近。若要进一步拉开，建议把 10 组压到 7 组（合并「悬停/拖拽」入「坐标」、「滚轮」入「键盘」、「代码」独立），这属于信息架构调整，需另议。

### 4.3 实现方式

```python
# ui/theme.py 新增（不放 ACRPA.py，避免第二份色板）
CAT_GROUPS = {                      # 命令 → 分类（沿用现有 10 组）
    "找图": "locate", "区域找图": "locate",
    "点图": "click",  "区域点图": "click", ...
}
CAT_COLORS = {                      # 分类 → (亮色, 暗色)
    "locate": ("#1D4ED8", "#93C5FD"),
    ...
}
def cat_color(group, dark=None):
    light, darkv = CAT_COLORS[group]
    return darkv if (dark if dark is not None else state.DARK_MODE) else light
```

- `_CMD_COLORS` 保留为「命令 → 分类键」的映射（结构不变，宿主调用点不动）；
- `tree.tag_configure(name, foreground=theme.cat_color(group))`，主题切换时在 ThemeBus 回调里重配 10 个 tag（10 次调用，可忽略）；
- 图例色块同源取色，保证"图例色 = 行内文字色"。

### 4.4 同步修正两处语义色

## 10. 明确不做的事

1. **不引入图标字体 / 图片图标集。** 现有 BMP 符号够用，加字体文件会牵动 PyInstaller 打包与 DPI 缩放，收益不成比例。
2. **不做卡片化 / 圆角加大改版。** v1 的 Windows 血统定位是对的，`radius=6` 保持不变。加大圆角会让桌面工具变成网页观感，与本项目定位冲突。
3. **不加动效。** tkinter 无原生动画，`after` 模拟的淡入会在低端机掉帧；v3 刚把首帧优化好，不宜回退。
4. **不调整表格行高与列数策略。** v3 的 4/7/10 列方案与 `row_h=22` 已经过实测，不动。
5. **不改 `netlink/webui.py` 的色值。** 那是浏览器渲染的 HTML，Tailwind 色在其中合理，只做变量化。
