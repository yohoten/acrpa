# AutoTiny 界面与功能借鉴方案（视觉取证）

> 日期：2026-11-09 ｜ 对象：本机 `E:\applications\AutoTiny\AutoTiny.exe`（v5.0.0.3 64 位，.NET/WinForms + MahApps.Metro）
> 取证方式：启动实机 → 窗口句柄 `PrintWindow` 抓图（视觉模型读图）+ UI Automation 控件树枚举。
> 证据截图：`docs/analysis/assets/autotiny-main.png`（主窗完整三栏）、`docs/analysis/assets/autotiny-library.png`（右栏应用库展开态）。
> 本文档**只给借鉴结论与落点映射，本轮不改代码**；落地时仍以 v5/v6 设计令牌为唯一视觉真源。

---

## 0. 结论先行（5 条）

1. **视觉不学，信息架构学。** AutoTiny 是典型 WinForms 双行中文文字工具条 + 灰白面板，控件密度高、无层级、无焦点态，整体质感落后于 ACRPA v6；它的价值在于**三栏工作流**：左项目树 → 中步骤表 → 右「应用库」。
2. **ACRPA 最大的可借鉴缺口：脚本编辑没有「应用库」。** 这套「常驻模块面板 + 搜索 + 分类图标 + 双击/拖拽插入」AutoTiny 做成了一等公民；ACRPA 只在**工作流 Tab** 有等价物（操作库树），脚本编辑仍靠「+ 添加」对话框逐条挑命令。
3. **第二缺口：常用开关与检索的"常驻化"。** AutoTiny 把 `运行高亮 / 步骤日志 / 系统日志 / 慢速运行 / 项目变量箱 / 弹出日志` 做成底部一排勾选，把「步骤搜索」做成顶部一钮；ACRPA 多数需要进设置或打开对话框。
4. **第三项（可选）：运行模式就地切换。** AutoTiny 顶部常驻 `基础模式 / 硬件模式 / 后台模式`；ACRPA 的等价能力是 `state.INPUT_MODE`（前台 SendInput / DD 驱动 / 后台 SendMessage），只在设置卡里，切一次要开设置。此项涉及引擎行为，列为 P1 且有回归成本。
5. **明确不学的**：项目/子程序/网络子程序树、手机连接、导出 EXE、多开管理、购买/教程入口、双行文字工具条。ACRPA 的脚本切换器、设备互联、单实例、帮助中心已覆盖且更强。

### 1.2 控件树（UIA 枚举，节选）

- 运行条按钮：`运行`、`循环`、`基础模式`、`硬件模式`、`后台模式`、`步骤搜索`
- 底部：`CheckBox 运行高亮 / 步骤日志 / 系统日志 / 慢速运行 / 项目变量箱`
- 右栏：`ListItem ControlCategoryType` × 7（分类）+ `ListItem TestCaseStep` × 20+（模块）
- 左栏：`ListItem TestCase`（项目/子程序节点）
- 版本：`v5.0.0.3 64位`

### 1.3 设计层面的可复用规律（抽象后）

1. **命令面板与编辑区并列常驻**（不是弹窗）→ 降低"插入一条命令"的路径长度。
2. **分类图标 + 名称 + 组合动作**三层文本线索 → 同组内仍可区分（因图、因字、因鼠标动作而不同）。
3. **检索就地过滤，不换页**（模块库搜索、步骤搜索）→ 保持上下文。
4. **开关贴近结果**（底部开关条紧邻步骤表/日志）→ 即时反馈。
5. 反面教材：颜色只有「橙=当前模式 / 蓝=按钮」，其余全灰；按钮无 hover 层次，工具栏两行混杂。

## 3. 借鉴项与落地方案

> 视觉一律走 v6 令牌（`surface_alt / bd / fgm / fgd / ac`）与既有控件族，**不引入 AutoTiny 的灰白 WinForms 观感**。

### P0-A 脚本编辑「应用库」侧栏（核心）

**借什么**：AutoTiny 右栏 = 搜索 + 分类 + 模块条目，常驻、就地插入。

**怎么落**：
- 布局：脚本编辑 Tab 的编辑区（`ui/editor_view.py:98 build` 内 `tree_frame`）由「单表」改为 `PanedWindow[步骤表 | 应用库侧栏]`，侧栏默认收起为 32px 竖条（点击展开 200px），sash 可拖拽；宽度记忆复用工作流侧栏的持久化口径。
- 侧栏结构（沿用 v6 §5.1 操作库树，不新建风格）：
  - 搜索框（`ebg` 底 + `bd` 1px，placeholder「搜索命令 / 参数…」）
  - 分组行：`module_catalog.group_label()` 图标 + 组名（`fgt` + `FONT_SMALL_BOLD`）
  - 命令条目：类别图标（v6 §5.1 映射，建议上移为 `module_catalog` 公共函数，工作流树同步受益）+ 命令名 + 参数签名（`fgm`）
  - 悬停：全名 + `tooltip_text`（截断可读）
  - 空态：搜索无结果用 v6 空态（图标 + 主句 + 副句），复用 `workflow_view` 的搜索空态实现
- 插入交互：
  - 双击 → 在选中行之后插入 `ScriptData(cmd, [""]*9)`，走 `_push_undo()` + `state._editor_rows.insert()` + `_editor_sync_to_tree()`（与 `ACRPA.py:2431` 同法），插入后定位到新行
  - 拖拽 → 同上，落点按 `tree.identify_row(y)` 计算插入位置
  - 右键 → 「插入 / 插入并配置参数（打开 `ui/param_form.py`）」
- 数据与性能：目录 `load_catalog()` 结果模块级缓存（88 条，一次性填充树）；搜索 KeyRelease **150–200ms 防抖**，只做 `tree.detach/reattach`，**不触发 `_editor_sync_to_tree`**（避免整表重建卡顿）。
- 验收：插入一条命令 ≤ 2 次点击；搜索 88 条响应 < 100ms；展开/收起无可见卡顿；同屏饱和实色块数不回退（v6 §6 基线 ≤2）。

### P0-B 步骤搜索（最小、独立）

**借什么**：AutoTiny 顶部「步骤搜索」。

**怎么落**（二选一，建议 ①）：
1. **工具条搜索框**：`ACRPA.py:4919 _init_toolbar_buttons` 的工具组之后插入 160px 搜索框（`ebg`/`bd`，右侧 `⌕` 图标）；输入即在编辑器树上过滤（`detach` 不匹配行），命中行打 tag（`search_hit_bg/border` 已有令牌），`Enter` 跳到下一个命中并 `see()`，`Esc` 清空恢复。
2. 独立「查找」面板：成本更高，不推荐首期做。

**注意**：过滤期间禁用「批量删除/上移下移」类结构性操作或先自动清空过滤（避免 `#0` 行号与真实行号错位误操作）；过滤器状态在 `_editor_sync_to_tree()` 后自动重放。
**验收**：输入「找图」仅剩匹配行且行号不变形；`Esc` 秒恢复；不产生全量重建。

### P1-C 视图开关条（贴近结果）

**借什么**：底部 6 个勾选开关。

**ACRPA 适配**（只借"就近可切"这一层，不照抄 6 项）：
- 位置：图例行 `ui/editor_view.py:244 legend_frame` 右侧追加 2–4 个 chip：`跟随运行行`（现有 hlbg 行为开关化）、`慢速运行`（新增，逐行延迟，仅调试）、`变量箱`（显隐变量面板）。
- 样式：v6 ghost 开关 chip（激活=accent 左缘点 + `fgb`，未激活=`fgm`），不用 Checkbutton 原生方块。
- 日志开关不重复做：`ui/log_dock.py` 已有级别过滤/搜索/清空/导出。
- 验收：三个开关均即时生效且状态持久化到 config；不引入轮询定时器（跟随运行行沿用现有 periodic）。

### P1-D 运行模式就地切换（有回归成本）

**借什么**：`基础 / 硬件 / 后台` 三选常驻。

**ACRPA 适配**：执行栏（`ui/exec_bar.py`）增加紧凑下拉「前台 / 驱动 / 后台」，与 `state.INPUT_MODE`、`state.USE_DD_DRIVER` 双向同步（设置卡 `ui/settings/cards/exec.py:169-170` 的保存口径必须共用同一映射，避免两处各自维护）。
**风险**：DD 需管理员权限、SendMessage 兼容性差；切换后需 `engine` 感知。建议：首版只做「只读展示 + 跳转设置」，确认无回归后再开放就地切换。
**验收**：切换后 `state.INPUT_MODE` 与设置卡显示一致；下次运行生效；失败回滚不影响运行中任务。

### P2（记录，不排期）

- 脚本「属性卡」（应用名/描述/图标）→ ACRPA 已有 `SCRIPT_NAME` 与另存语义，收益低。
- 快捷键总览面板 → 现有设置页热键项 + `hotkey_win`，可加只读一览。
- `问AI` 常驻按钮 → ACRPA 已有 `AI生成 / AI调试`（v6 已紫化对齐），无需新增。

## 4. 明确不借鉴

| AutoTiny 做法 | 原因 |
| --- | --- |
| 双行纯文字工具条（9+8 项） | 与 v6「同屏实色块 ≤2、组间竖线、危险组最右」冲突 |
| 项目 › 子程序 › 网络子程序 树 | ACRPA 以脚本切换器 + 工作流子流程 + 设备互联表达，语义更清晰 |
| 手机连接 / 局域互联入口 | 已有独立设备互联 Tab（配对/权限/TLS/远程），功能更强 |
| 导出 EXE / 多开管理 | 与单实例、脚本包（`script_package.py`）设计冲突，且有分发风险 |
| 购买永久版 / 教程 / 反馈 混排标题栏 | 商业入口不应占据主窗视觉权重 |
| 模块条目平铺两大级（20+ 条同类） | ACRPA 已有「分组 + 搜索 + 类别图标 + tooltip」，信息密度更合理 |

## 7. 与既有方案的边界

- 令牌、按钮族、空态结构仍以 v5/v6 为唯一真源，本方案**不新增颜色与控件族**。
- 应用库侧栏与 v6 §5.1「操作库树」同构：图标/最右搜索空态/tooltip 全名三处规则直接复用，避免两套手感。
- 本文档为方案，**不含代码改动**；实施时再按 P0 → P1 出变更清单与截图验收。
