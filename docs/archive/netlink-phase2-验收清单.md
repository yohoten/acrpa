## 0. 能力边界（务必先读，Phase 2 = 可读 + 可控）

- ✅ **能看**：运行/暂停状态、当前脚本、进度（`行/总行 · 循环`）、实时日志、定时任务摘要。
- ✅ **能控**（需被控端授权 + 可选的首次确认）：**远程运行 / 暂停 / 恢复 / 停止**。
- ✅ **有安全**：配对码（PIN）认证，token 存 Windows 凭据库；防重放（nonce）；权限三级
  `仅观察 / 允许操控 / 允许接收脚本`；**审计日志**（`logs/netlink_audit_YYYYMMDD.log`）。
- ⛔ **仍不能**：脚本推送（`push脚本` 按钮灰色，Phase 3）、TLS 加密、截图。
- ⛔ **无 TLS**：链路仍是明文 TCP，请仅在**可信内网**使用。
- 说明（本轮修复）：控制端连上后**自动订阅**对端状态推送，**无需任何手工订阅**即可在看到
  对端的「状态 / 进度 / 日志」列（对应缺陷 A 修复）。

## 1. 前置准备

1. 两台 Windows 机器**接入同一网段**（同交换机 / 同 VLAN，可互 ping）。
2. 两台安装**同版本** ACRPA（比对各机根目录 `VERSION` 文件内容一致）。
3. 用 `ipconfig` 记录两机 IPv4 地址（下称 **A 机 IP**、**B 机 IP**）。
4. 在 A 机 `ping <B 机 IP>` 确认互通。
5. 端口规划（默认即可）：互联 **TCP** `19710`；发现 **UDP** `19711`。

## 2. 需要修改的设置项（两台都要）

打开 ACRPA →「设置」→ 左侧「🌐 网络互联」卡（或「设备互联」窗口内直接维护）。

| 设置项 | 取值建议 | 说明 |
| --- | --- | --- |
| `netlink_enabled` | **勾选** | 两台都要勾选 |
| `netlink_device_name` | 填可辨识名字（如 `财务机-A`） | 对端列表辨认用 |
| `netlink_port` | `19710`（默认） | 本机 TCP 监听端口 |
| `netlink_discovery_port` | `19711`（默认） | UDP 广播端口 |
| `netlink_autodiscover` | 自动发现路径勾选；降级路径取消 | 见 Phase 1 清单场景 A/B |
| `netlink_require_auth` | **勾选（默认）** | 关闭后无需配对即可被连；**生产务必保持勾选** |
| `netlink_pin_ttl` | `600`（默认，秒） | 配对码有效期 |
| `netlink_confirm_control` | **勾选（默认）** | 首次远程操控时被控端弹窗确认 |
| `netlink_script_dir` | 留空（默认=`程序目录/scripts`） | 允许远程运行的脚本目录（本轮不推送脚本，仅作约束） |
| `netlink_audit_days` | `0`（跟随日志保留天数） | 审计日志保留天数 |

> 改完设置点「应用」（或窗口内「应用」），节点会**自动重启**使配置生效。

## 3. Windows 防火墙放行

首次勾选「启用设备互联」启动后，Windows 会弹防火墙授权框——**勾选「专用网络」并允许**。
手动放行（管理员 CMD，两台都执行）：
```
netsh advfirewall firewall add rule name="ACRPA NetLink TCP" dir=in action=allow protocol=TCP localport=19710
netsh advfirewall firewall add rule name="ACRPA NetLink UDP" dir=in action=allow protocol=UDP localport=19711
```
撤销：`netsh advfirewall firewall delete rule name="ACRPA NetLink TCP"`（UDP 同理）。

## 4. Phase 2 主验收流程（两台真机）

约定：**A = 被控端**（要被远程操控的那台），**B = 控制端**（发起远程操控的那台）。
两台都要勾选「启用设备互联」，并保证 B 能看到 A（自动发现或 B 侧手动添加 `A机IP:19710`）。

### 步骤 1：两机互相可见
- **操作**：两台打开「设备互联」窗口（主界面「🌐 互联」）。
- **预期**：≤10s（自动发现）或 ≤6s（手动添加）内，设备列表出现对方；A 若正在跑脚本，
  B 侧该行「状态」列显示 **「● 运行」**、进度列显示 `行/总行 · 循环`，选中 A 后下方日志面板滚动其日志。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | 列表为空 | 防火墙拦 UDP/TCP；或 `netlink_enabled` 未勾选 | 见第 3 节；勾选启用 |
  | 仅一侧可见 | 只配了单侧静态对端 | 在缺失一侧也添加对方 `IP:TCP端口` |
  | B 状态列恒为「○ 空闲」且日志为空 | 连接未认证 / 被对端拒绝 | 见步骤 2；检查 B 侧是否已配对 |

### 步骤 2：被控端 A 打开「配对码」，控制端 B 完成配对
- **操作（A 机）**：在「设备互联」窗口点顶部 **「配对码」** 按钮 → 弹出配对码对话框 →
  点 **「生成配对码」** 得到 **6 位数字 PIN**（顶部状态条也会显示 `配对码 XXXXXX (剩余 mm:ss)`）。
- **操作（B 机）**：在设备列表**选中 A 那一行** → 点下方 **「🔗 配对」** → 输入 A 上的 6 位 PIN → 确认。
- **预期**：
  - B 侧底部提示配对成功；A 侧「已配对设备（本机授予的远程权限）」区**立即出现** B 一行，权限默认 **「仅观察」**。
  - B 侧该行「权限」列显示 **「仅观察」**；B 侧 **[▶ 远程运行] / [⏸ 暂停] / [⏹ 停止]** 三个按钮**仍为灰色**（观察权限不足）。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | B 提示配对失败 / 无反应 | PIN 输错，或 A 的配对窗口已过期（默认 600s） | 在 A 机上**重新生成**配对码，立即在 B 上输入 |
  | A 一直没出现 B | B 未先「选中 A 那一行」再点配对；或 A 侧未开配对窗口 | 先选行再配对；A 侧务必先「生成配对码」 |
  | 反复失败后 B 连接被断开 | 连续错误 PIN 达上限（5 次）触发保护 | 等待 B 侧连接自动重连（约 3s）后重试 |

### 步骤 3：被控端 A 授予「允许操控」
- **操作（A 机）**：「已配对设备」区选中 B 那一行 → 权限下拉选 **「允许操控」** → 点 **「应用」**。
- **预期**：A 侧该行权限即时变为「允许操控」；**B 侧**（无需刷新）该行「权限」列变为 **「允许操控」**，
  且 **[▶ 远程运行] / [⏹ 停止]** 按钮变为**可用**（A 正在运行时可点停止）。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | B 侧权限列不变 | 连接已断开（B 未在线） | 确认 B 仍在线（状态非「离线」）后重试；重连后会自动补发权限通知 |
  | 按钮仍灰 | 未选中 A 行；或 A 未在运行（停止/暂停按钮依赖运行态） | 选中 A 行；先让 A 跑起来 |

### 步骤 4：远程运行（首次会弹「确认」）
- **操作（B 机）**：选中 A 行 → 点 **[▶ 远程运行]** → 本地二次确认 → A 机弹出**首次操控确认弹窗**。
- **操作（A 机）**：在弹出的「远程操控请求」对话框中选择 **「允许」**（或 **「允许并记住此设备」**，
  之后该设备不再弹窗）。
- **预期**：
  - A 机确认后开始执行其**已加载**的脚本；A 侧状态列变「● 运行」；B 侧同步显示「● 运行」与进度。
  - B 侧窗口下方 **「远程指令」** 列表出现一行「远程运行」，先显示 **「已受理」**，随后变为 **「成功」**；
    底部状态行摘要含「远程运行 成功」。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | A 端弹窗未出现，30s 后自动拒绝 | A 机主窗口被最小化/被遮挡，弹窗抢焦点失败 | 把 A 机主窗口置于前台后重试 |
  | 「远程指令」显示「失败: no script selected」 | A 机未加载任何脚本 | 先在 A 机打开一个脚本 |
  | 「失败: already running」 | A 机已在运行 | 正常保护；勿重复下发 |
  | 「失败: permission denied」 | A 未授予「允许操控」 | 回到步骤 3 授权 |

### 步骤 5：远程暂停 / 恢复
- **操作（B 机）**：A 运行中时点 **[⏸ 暂停]**（按钮文案会随 A 状态切换为 **[▶ 恢复]**）。
- **预期**：A 机脚本暂停（状态列「⏸ 暂停」）；再点变为 **[▶ 恢复]** 后脚本继续；
  两条指令在「远程指令」列表各成一行并显示「成功」。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | 提示 `not running` | A 当前未运行 | 先远程运行 |
  | 按钮不可点 | 未选中 A 行 / 权限不足 / A 未运行 | 检查选中态与权限 |

### 步骤 6：远程停止
- **操作（B 机）**：点 **[⏹ 停止]** → 本地二次确认。
- **预期**：A 机脚本停止（状态列变「○ 空闲」）；「远程指令」显示「停止 成功」。
- **说明**：无需被控端再次确认「停止」（首次确认按设备粒度记忆）。

### 步骤 7：查看审计日志（A 机视角最完整）
- **操作**：在任一端「设备互联」窗口点 **「📜 审计日志」**。
- **预期**：弹出只读窗口，显示 `logs/netlink_audit_YYYYMMDD.log` 内容，每行形如：
  `[时间] actor=<设备名|指纹前8位> remote=<ip:port> cmd=<CMD_RUN> args={...} result=<ok|err|rejected> detail=...`。
  **每一条远程指令**（含被拒绝的）都有记录。
- **常见失败**：
  | 现象 | 原因 | 处置 |
  | --- | --- | --- |
  | 列表为空 | 尚无任何远程指令；或窗口指向的不是被控端 | 先执行一次远程指令 |
  | B 侧看不到内容 | 审计只由**执行侧（被控端）**写入 | 在 A 机查看即可 |

### 步骤 8：权限回收（安全收尾，务必执行）
- **操作（A 机）**：「已配对设备」区选中 B → 权限下拉改回 **「仅观察」** →「应用」。
- **预期**：B 侧权限列变「仅观察」，四个操控按钮**重新变为灰色**；此后 B 发任何 `CMD_*` 均被拒绝
  （B 侧「远程指令」显示「失败: permission denied: need control」，A 机**不受影响**）。
- **可选**：点 **「移除」** 彻底删除该设备（同时清除其 token）。

## 5. 安全模型小结（验收结论必写）

- **PIN 绝不明文上网**：PIN + 随机 salt 经 `PBKDF2-HMAC-SHA256`（10 万轮）派生 token，网络只传挑战/证明。
- **敏感 token 只进 Windows 凭据库**（`ACRPA/netlink/peer/<指纹>`），**绝不写入 `config.json`**。
- **防重放**：每次认证使用一次性 `nonce`，消费后失效；证明含时间戳（±60s）。
- **权限三级**：`仅观察 < 允许操控 < 允许接收脚本`；越权指令一律回 `CMD_ERR`。
- **首次操控确认**：被控端可对每个设备「记住」，也可每次弹窗；30s 无人应答自动拒绝。

## 6. 典型故障总览（贯穿全流程）

| # | 失败现象 | 根因 | 快速定位 |
| --- | --- | --- | --- |
| 1 | 节点显示「○ 已停止」或反复无法启动 | TCP 端口被占用 | `netstat -ano \| findstr 19710` 找占用 PID；改端口或结束进程 |
| 2 | 能 ping 但列表为空 | 防火墙拦 UDP（广播）/ 或关掉了自动发现 | 放行 UDP；改用手动添加 `IP:19710` |
| 3 | B 侧状态/进度/日志恒为空 | 连接未认证（未配对） | 完成步骤 2 配对 |
| 4 | 配对老是失败 | PIN 过期 / 输错 / 未先选行 | 重新生成 PIN、先选中 A 行再配对 |
| 5 | 远程指令「permission denied」 | A 未授予「允许操控」 | 执行步骤 3 |
| 6 | 首次远程运行 30s 后自动拒绝 | A 机确认弹窗被遮挡未应答 | 置前 A 机主窗口后重试，或勾选「允许并记住此设备」 |

## 9. 已知边界与风险（用于决定是否进入 Phase 3）

- 传输**未加密**（明文 TCP + HMAC 认证）——不可信网络下有被窃听/篡改传输内容的可能；TLS 属后续阶段。
- **脚本推送未开放**（`[推脚本]` 灰色）——远程只能运行被控端**已加载**的脚本。
- **无截图**能力。
- 仅验证过 **两人/两台** 规模；更多设备/多控制端并发操控同一被控端的行为（广播回执、串行队列）
  已在自动化中覆盖基本路径，但**大规模拓扑**未做压测。
- 工作流分叉依赖被控端存在真实 `workflow` 引擎；无 GUI/缺依赖环境下该路径仅以假引擎覆盖
  （真实模块路径见 `tools/_test_netlink_phase2_e2e.py` 断言 5，可自动跳过并记 WARN）。
