# ACRPA UI 视觉规范与设计图（v6）

> 版本：2026-11-05
> 定位：本文是 **视觉规范画册**——把 v2–v5 里已经落地的颜色/间距/字体 token，固化成可看的「设计图」，并给出**下一步美化的具体落点**。
> 与既有文档关系：v2/v3 讲布局与承载，v4 讲视觉层级/分类色/一致性收口，v5 讲性能与线程。本文只做两件事：① 把规范画出来 ② 指出还差的那几步。

---

## 0. 结论速览

ACRPA 的 UI 基础已经**超出大多数个人项目的水平**——语义色双套、表面层级 5 级、命令分类色 10 组、命名字体、圆角自绘控件、动效 token、a11y 断言，全都在代码里落地了（`src/ui/theme.py`、`src/ui/widgets/rounded_button.py`、`src/core/`）。

**所以「美化」的下一步不是再造一套规范，而是把已定义的 token 真正铺到界面上**。当前最大的视觉欠账是：

1. 分类色、日志语义色**已经铺设到位**（实测 `editor_view.py:258` 命令按钮用 `cat_color`，`log_dock.py:306-371` 日志 tag 全用语义色）——视觉体系其实比看起来更完整；
2. 真正的欠账是 **glyph 常量表**（emoji 跨 Windows 版本渲染不稳定）与 **焦点可见性**；
3. 可选的辨识度升级是「分类色块按钮」——这是口味，不是欠账。

下面 5 张设计图是这套规范的全貌，其中图 5 展示的是「升级后」的观感（部分对应 §3 P1-1，非当前现状）。

### 1.1 色彩系统（图 1）

- **强调色收敛为 Windows 蓝 `#0078D4`**（亮）/ `#4CC2FF`（暗），放弃旧网页蓝。这是 v4 最重要的一个决定——让工具在 Windows 里「像原生应用」。
- **语义色亮暗是两套独立设计**，不是互相调亮度：暗色语义色（`#4CC2FF`/`#6CCB5F`/`#FF99A4`）是「发光的深底配色」，在深色面板上仍清晰。这是深色模式观感好的关键。
- **AI 功能统一用品牌紫** `ai`（`#7C3AED` 亮 / `#8B5CF6` 暗），与 ac/sc/dg/wn 同级——凡是 AI 相关（智能重试、AI 找元素、AI 生成）都用紫，一眼可辨。

### 1.2 命令分类色（图 2）

- 10 组分类，每组亮暗双套，全部 ≥ WCAG 4.5:1（v4 §4.2 已验证）。
- **用途是「图标/标签底色」，不是「文字色」**——文字永远用 `fgb`/`fgm`，分类色只做色块/色点，这是 v4 从「可读性」里学到的教训（分类色当文字色时明暗两套都不达 AA）。

### 1.3 间距·圆角·字阶（图 3）

- 间距 6 档：4/8/12/16/24/32，全部走 `sp()`，禁止裸像素。
- 圆角 5 档：r2 按钮 → r4 标签 → r6 输入框 → r8 卡片 → r12 弹窗。
- **字号下限 9pt**（密集表格可读下限），`FONT_SMALL`/`FONT_TINY` 已从 8/7pt 提到 9pt。图标字形（`FONT_ICON*`）不受此限。

### 1.4 组件状态（图 4）

- 按钮四层级：主（ac 底白字）/ 次（白底 bd 描边）/ 危险（errbg 底 err 字）/ 禁用（灰底灰字）。
- 开关：ac 底白滑块（开）/ bd 底白滑块（关），圆角胶囊。
- 状态徽标：小圆点 + 文字，四态（已完成/运行中/失败/待执行）分别用 sc/ac/dg/fgd。
- 输入框焦点：ac 描边加粗；卡片：白底 bd 描边 r8，右上角可放语义徽标。

### 1.5 编辑页效果图（图 5）

这是「所有 token 铺满后的理想观感」：彩色命令工具栏 + 分类色行首标识 + 染色悬停行 + 语义色日志。

## 3. 下一步美化建议（按性价比排序）

> 实查修正：分类色与日志语义色**已经铺设**（见 §2 表格）。因此真正的增量在「一致性收口」与「辨识度升级」，而不是「把颜色铺满」。

### P0 — 收尾两个真欠账（1 天）

**P0-1 glyph 常量表（去 emoji）**

`⏱` `✓` `✔` `●` 等字符在不同 Windows 版本 / 字体回退下渲染不一致（有的显示为方框）。把它们统一成 `ui/theme.py` 里的常量，全库替换。这是 v4 §6.2 的欠账，也是唯一有「跨版本正确性」风险的点。

**P0-2 焦点可见性确认**

`focus` token（`#0078D4`）已定义，核对键盘 Tab 导航时输入框 / 按钮是否有可见焦点环。桌面工具必须纯键盘可操作。

### P1 — 辨识度升级（可选，按口味）

**P1-1 命令按钮「分类色块」升级**

当前命令按钮是「分类色文字 + 白底」（`editor_view.py:258`，已合规达 AA）。若要更强的扫读辨识度，可升级为效果图里的「分类色块 + 对比色文字」：

- 深色分类色（`#1D4ED8` 蓝 / `#15803D` 绿 / `#6D28D9` 紫 / `#B91C1C` 红 / `#475569` 灰蓝）→ 白字；
- 浅色分类色（暗色主题的 `#93C5FD` 等）→ 深字。

注意：这是「口味」不是「欠账」，浅色分类色必须配深字，否则破坏对比度。做完要重跑 `tests/_test_ui_contrast.py`。

**P1-2 空状态引导**

首次打开无脚本时，用「居中插画 + 一句引导 + 一个主按钮」替代纯文字 hint。空状态是高级感的廉价来源。

**P1-3 动效语义化**

定义动效时长语义（hover 光晕 120ms / 开关滑块 180ms / toast 滑入 240ms / 执行行扫光 800ms），全部尊重 `reduce_motion`。token 已有（`core/`），缺的是「统一使用」的约定。

## 5. 明确不做

1. **不做渐变、阴影、光晕、玻璃拟态**。桌面工具要「像原生应用」，扁平 + 细描边 + 染色悬停已经足够高级，任何花哨效果都会和 Windows 原生观感打架。
2. **不做深色模式的第二套布局**。只换色，不换布局——布局差异是 bug 之源。
3. **不为了「美」增加字号或间距**。ACRPA 是密集表格型工具，v4 已明确「不建议加大密度」，可读性优先于呼吸感。
4. **不引入任何 UI 库 / 前端框架**。现有 Tk + 自绘 `rounded_button` 的路线是对的，保持零依赖。
