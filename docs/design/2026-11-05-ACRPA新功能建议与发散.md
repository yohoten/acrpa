# ACRPA 新功能建议与发散思考

> 日期：2026-11-05 ｜ 基线：v0.1.30-beta（94 命令 / 11 分组）
> 依据：README 定位、`docs/design/` 既有方案、`commands` 注册表、`ai_client`/`ai_enhance` 现状、近 5 日运行日志

---

## 0. 结论先行

ACRPA 的护城河不是"命令多"，而是三个别人不愿意做的组合：**Excel 即脚本（零学习成本 + 天然可审计）· 单文件 14MB 便携 · 纯内网多机**。新功能应当**加深这三条轴**，而不是去追通用 Agent 的热点。

一个关键判断：**当前最大的功能缺口不在"能做什么"，而在"批量做"和"证明做对了"**。README 把「批量填表、对账、录单」列为头号适用场景，但命令表里**没有任何表格读取/数据驱动命令**——用户只能自己拼 `循环开始` + 逐行写死。这是投入产出比最高的一刀。

三条设计铁律（后续所有建议都受其约束）：

1. **Excel 是一等公民**：新能力优先以"命令/表格"形态落地，而不是只在 GUI 里可用。
2. **零依赖便携**：新增依赖必须走 `capabilities.py` 的可选扩展四态（READY / MISSING / BROKEN / DISABLED），绝不进 `requirements.txt` 必需项。
3. **内网优先，不出公网**：任何"云"能力都要能降级为本地/局域网实现。

---

## 1. 现状能力矩阵（找缺口用）

| 轴 | 已有 | 缺口 |
|---|---|---|
| 定位元素 | 图像 / 窗口相对坐标 / OCR / AI 视觉 | 无元素库（图/文字定位结果不可跨脚本复用） |
| 流程 | 条件 / 循环 / 跳出 + 工作流图 + 静态检查 | **无数据驱动（行=数据）**、无断言、无子流程参数化 |
| 数据 | 变量 / 字符串 / 数学 / 剪贴板 / HTTP / JSON | **无表格读写**（仅 `.xls` 经 xlrd/xlwt）、无 CSV |
| 执行 | 断点/单步/变量监视、失败留存现场 | 无完整回放、无 dry-run 影子执行 |
| 多机 | NetLink 发现/配对/远程运行/截图/网页面板 | 无任务分片、无审批门禁 |
| 生态 | 市场（脚本/扩展）、Python 沙箱三级权限 | 缺"开箱即用"的可运行示例与素材包 |
| AI | 生成脚本、AI 找元素、智能重试、优化建议、调试解释 | 无生成→校验→试跑→修复的闭环，无成本控制 |

## 2. 第一层：补短板（P0，1–4 周，直接放大现有场景）

### 2.1 数据驱动执行（最高优先级）

**场景**：1000 行客户数据，逐个录入 ERP（README 的头号场景）。

**现状**：用户只能 `循环开始 1000` + 自己算行号取数，无法维护、无法断点续跑。

**建议**：新增两条命令，最小改动撬动最大场景。

```
读取表格   data.xlsx, Sheet1, 1, 数据        → 读入 {标题:值} 的行列表
循环开始   遍历 ${数据}                       → 每次迭代注入 ${行.姓名} ${行.金额}
─────────────────────────────────────────
可选：循环开始 遍历 ${数据} 从 350            → 断点续跑（跳过前 350 行）
```

**落点**：`src/commands.py` 注册 + `engine.py` 的循环帧增加 `dataset` 字段（现有 `ctx` 已是 dict 栈，扩展成本低）。`script_validate.py` 增加"遍历变量未定义"检查。

**价值**：把"脚本"升级为"任务"，批量场景从"能跑"变"可维护"。**成本 M，风险低**。

### 2.2 `断言` 命令 + 脚本自测

**场景**：脚本改了一行，怎么知道没改坏？现在只能人肉跑一遍看日志。

**建议**：
```
断言  ${结果} == "成功", 录入失败      → 不成立则标记该行 failed 并写报告
等待稳定  3                              → 界面静止 N 秒再继续（比 sleep 智能）
```
配套：`--script x.acrpas --assert-only`（只跑断言不产副作用）→ 进 CI。无头 CLI 与 JSON 报告已具备，这是最低成本的"RPA 工程化"卖点。

**成本 S，风险低**。

### 2.3 `.xlsx` 读写 + 结果回写

**现状**：`requirements.txt` 只有 `xlrd/xlwt`，即只能处理 **.xls**；而企业里 99% 的表是 **.xlsx**。用户拿到 `.xlsx` 会直接卡在第一步。

**建议**：`openpyxl` 作为**可选能力**（`capabilities.py` 注册 `data.xlsx`），新增 `读取单元格 / 写入单元格 / 追加行`。最杀手级的用法是**结果回写**：脚本跑完，把成功/失败/耗时写回源表 F/G/H 列 —— 对账场景一眼看结果。

**成本 M（openpyxl 打包体积 +3MB，需评估单文件大小），风险中（体积是卖点）**。

### 2.4 脚本体检报告（把"使用说明"变成自动检查）

`script_validate.py` 已能查未知命令/参数类型。补上**反模式规则**，直接命中现有文档里的"坑"：

| 规则 | 今天只能靠文档提醒 |
|---|---|
| 图片路径含中文 / 纯数字名 | 使用说明第 4 条 |
| 连续 `坐标` 点击（本可用窗口坐标） | README：窗口命令快 10–100 倍 |
| `等待` 固定 5s 的滥用 | 无 |
| 循环内 `找图` 全屏扫描 | 无 |
| 缺少失败分支的写操作（删除/转账类） | 无 |

输出为一份"体检报告"面板 + 一键修复建议。**成本 S，风险低，体感极强**。

## 3. 第二层：强化护城河（P1，1–3 月）

### 3.1 失败自愈闭环（已有零件，缺装配）

现状零件：`ai_smart_retry`（命令失败后 AI 兜底）、`ai_find_element`（自然语言找元素）、失败现场截图+JSON。

缺的是**闭环**：失败 → 归因 → 修复建议 → 一键应用 → 回写脚本。

```
第 12 行 找图 submit.png 失败（置信度 0.71 < 0.96）
  建议：① 降到 0.80 重试  ② 改用 点击文字 "提交"  ③ 改用 AI找图 "蓝色提交按钮"
  [应用并重跑 12 行]
```
这是"越用越省心"的体验分水岭，也是与按键精灵类工具的根本区别。**成本 M，风险低（无新依赖）**。

### 3.2 执行回放（RPA 的"行车记录仪"）

现已留存失败截图与变量快照，缺时间线。建议每次执行生成 `run.jsonl`：每行 = 命令 + 参数（脱敏）+ 耗时 + 截图缩略 + 变量 diff。GUI 里拖动时间轴回放，导出 PDF 作为**交接/审计凭证**。

**为什么重要**：财务、票据、报表归档场景买的就是"可证明"。这也是国内 RPA 普遍薄弱的一环。**成本 M–L，风险低**。

### 3.3 素材库（元素库）

图、OCR 文案、AI 描述统一进一个库：跨脚本复用、支持"同一元素多套模板（不同分辨率/主题）"。顺带解决"图片路径不能含中文"这类历史包袱——库内用 ID 引用，落盘名由程序生成。

**成本 M，风险中（需迁移旧脚本引用，做兼容层）**。

### 3.4 模板 2.0：可运行示例 > 文档

市场已有基础设施。建议每个命令配一个**可在 3 秒内跑起来的 demo**（如 `HTTP 请求` → 请求公开 API 并弹结果），加上 5 个"行业整包"：电商后台录单、财务对账、HR 入职、教务成绩录入、运维巡检。**转化率提升远高于新增命令**。

**成本 M（内容为主），风险低**。

## 4. 第三层：差异化（P2，3–6 月）

### 4.1 NetLink 从"看屏幕"升级为"算力池"

现有：远程运行单个脚本。缺：**任务分片调度**。

```
$\ 10000 行数据 → 5 台机器各领 2000 行 → 汇总结果
```
实现要点：主节点做分片（复用 `读取表格` 的数据驱动）、从节点幂等领取（`WM_COPYDATA` 已有 IPC 基础）、失败片重分配。这个能力一旦成立，ACRPA 的定位从"个人自动化"变成"**内网批处理引擎**"，客单价与壁垒同时抬升。**成本 L，风险中（并发安全、结果汇总）**。

### 4.2 危险动作门禁（人工审批）

NetLink 已有手机只读面板。加"审批"：脚本执行到标记为危险的行（删除/转账/提交订单）时挂起，推送到手机面板，人工点"允许"才继续。技术上是现有面板 + 一个等待原语（`pause_event` 已有）。

**价值**：让 RPA 敢碰真正有价值的流程（钱、单、票据）。**成本 M，风险低**。

### 4.3 混合执行策略：能走 API 就别走 UI

README 已明说"有 API 的系统直接调 API 更快更稳"。可以把它变成产品能力：命令级"双通道"——同一语义（如"提交订单"）优先走 HTTP 请求，失败/无接口时回退 UI 操作。给每个业务系统维护一份"通道映射"。

**成本 M–L，风险中（需要业务知识沉淀）**，但这是 RPA 稳定性从 80% 到 98% 的关键。

### 4.4 脚本时间线（Git 化的版本管理）

`script_versions.db` 已有版本快照。加：可视化 diff（行级）、一键回滚、分支（"试验版"/"生产版"）、变更备注。对多机分发场景是刚需——否则"哪台机器跑的哪个版本"永远说不清。

**成本 M，风险低**。

## 5. 第四层：发散（6 月+，重新定义边界）

> 以下不是"要不要做"，而是"想清楚再决定"。每条都标注了它与现有定位的冲突点。

| # | 设想 | 一句话 | 冲突/风险 |
|---|---|---|---|
| D1 | **数字同事** | 脚本不再是"跑一次"，而是有班次、有 SLA、有日报的常驻员工：早报推送"昨日执行 42 次 / 失败 1 次 / 节省 3.2 小时" | 需要常驻进程与通知渠道，与"便携单文件"哲学有张力 |
| D2 | **RPA 行车记录仪** | 全程可回放可导出，作为审计证据链（见 3.2 的延伸：加签章/哈希存证） | 合规价值高，但存储与脱敏要设计 |
| D3 | **任务表单化** | 把脚本变成一张给同事填的表单（参数 + 运行按钮），非技术人员不接触 Excel 行 | 会引入 Web/内网服务，需守住"不出公网" |
| D4 | **Excel 侧边栏** | 在 Excel 里直接选行执行（pywin32 已有基础），"表格里点一下就自动化" | COM 加载项维护成本高，且与 WPS 兼容性要验 |
| D5 | **影子执行（dry-run）** | 先在虚拟桌面/影子会话试跑，确认无破坏再真跑 | 依赖虚拟化，重；可先做"只读命令子集"的轻量版 |
| D6 | **环境漂移检测** | 同一脚本在"当前环境 vs 上次成功环境"对比（DPI/窗口/字体/版本），定位"昨天还能跑今天不行" | 需要环境指纹采集，价值极高但工程量大 |
| D7 | **语音下达** | "把昨天的日报跑一下" | 噱头 > 实用，暂不建议 |
| D8 | **跨组织脚本交换** | 市场升级为"带 SLA 的流程资产交易" | 审核与责任边界复杂，早期不做 |

**最看好 D2 与 D6**：两者都不追热点，但都直击"企业为什么敢把关键流程交给它"。

## 7. 明确**不**做（反发散，同样是设计决策）

1. **不做通用 AI Agent**：README 已把"需要语义理解的非结构化任务"划为不适合。追这个热点会同时丢掉"确定性、可审计、离线可用"三个卖点。
2. **不做云端 SaaS 主形态**：单文件便携 + 纯内网是核心差异；云只做"可选的市场/更新"，且必须可离线降级。
3. **不做复杂可视化流程设计器**：现有工作流图已够；再往上就是低代码平台，与"Excel 简单性"背道而驰。
4. **不做反检测/游戏对抗**：法律与道德红线，且会污染产品定位。
5. **不盲目加命令数**：94 → 120 条带来的边际价值远小于"把现有 94 条串起来能批量跑"。

---

## 8. 一句话路线

> **v0.2 让脚本能"批量跑"（数据驱动 + xlsx + 断言 + 体检）→ v0.3 让结果"可信"（自愈 + 回放 + 素材库）→ v0.4 让规模"可扩"（分片 + 审批）→ v1.0 让价值"可证明"（审计存证 + 环境漂移）。**

每一层都不引入必需依赖、不破坏便携性、不离开内网——这是 ACRPA 能长期活下来的姿势。
