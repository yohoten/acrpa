## 2. UI 细节观察

**已做对的（本轮改动确认）**：
- `theme.py`：Checkbutton/Radiobutton 暗色主题补齐（此前暗色下整条白底），状态色统一走 `core.color.state_color` 派生，消除逐处 `_darken` 字面量。
- `flow_canvas.py`：脏区渲染（`render(dirty=...)` → `_render_dirty`）落地，节点级重绘替代全图重绘；文本按节点宽度预算截断（`_ellipsize`）替代固定字符数。
- 设置窗口：600ms 防抖自动保存 + 「✔ 已保存 / ⚠ 保存失败(可重试)」角标 + 底部「需重启生效 N 项」汇总 + 搜索命中下钻聚焦输入框 —— 反馈闭环完整。

**建议关注的细节（低成本高感知）**：
1. **可折叠卡片的点击热区太小**：`make_collapsible_card` 只在箭头 Label 上绑 `<Button-1>`，标题行其余区域点击无响应。建议整行 `title_row` 绑定 + `cursor="hand2"`。
2. **`refresh_theme` 全树递归 walk**：每个 widget 做 `_role_of` 反查（O(widgets × 色表条数)）。当前规模无感，但设置窗口控件数已过千，若将来加动画会卡顿；可在 widget 上存 `_acrpa_role` 属性替代反查。
3. **保存失败角标文案**："⚠ 保存失败（点击重试）" 已可重试，但失败原因只在 `messagebox`；建议 hover 时 `attach_tooltip` 显示原始异常，减少一次弹窗打断。
4. **OCR 状态行**：状态探测已异步化，但多次进入设置页会重复探测；建议按后端名缓存结果 + 显式"刷新"按钮（后者已有）。

## 4. 设计建议

1. **把"字体契约"固化进测试**（本轮已做）：`tests/_test_settings_split.py` 新增 E1 段——`init_ctx` 必须兼容命名字体字符串、解包顺序与调用方一致、粗体可直接建 Tk Label。同类"DI 边界契约"（colors/fonts/回调签名）建议都用实机断言锁死，这类 bug 的特点是**静态检查发现不了、运行期静默、日志不落**。
2. **`claim_window` 作为新增独立窗口的强制步骤**：ThemeBus 的自管换肤边界约定是对的，建议在贡献文档/代码模板里明确"新 Toplevel 必须声明 owner"，`_test_theme_bus` 已按文件清单兜底。
3. **探针/埋点类 monkey-patch 必须有生命周期**：`_wrap_once` 的教训——"once" 应该指语义（只记首启），而非"只包一次壳但每次都打点"。今后新增 boot 探针统一走修复后的 `_wrap_once`。
4. **设置窗口设计方案文档已过期部分应更新**：`docs/design/设置窗口优化设计方案.md` 中行号引用（如 `_do_save` 在 244 行）指向的是旧单文件；建议在 P0 表格后加"现行实现见 src/ui/settings/ 目录"的导航说明，避免后来者按行号找到错误位置。
5. **UI 性能基线**：启动各阶段 cost 正常（ui_build ~550ms / ui_ready ~220ms）；建议把 `ui_first_frame ≤ 400ms`、`theme 首启 ≤ 1s` 写成 `_test_l5` 的软断言，防止回归。
