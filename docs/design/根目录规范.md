# 根目录规范

> 定位：**可执行的约定**，不是建议清单。建议与动因见 [`根目录结构优化建议.md`](根目录结构优化建议.md)；本文只规定"必须/应当/可以"。
> 约束层级：**L0 硬性**（违反即缺陷，检查器报 FAIL）/ **L1 应当**（评审时需给出理由）/ **L2 可选**（风格偏好）。
> 机器检查：`python tools/check_root_layout.py`（`--strict` 把 WARN 也视为失败）。

---

## 0. 适用范围

适用于仓库根目录**一级条目**（文件与目录），以及由根目录派生的四类落点：随包资源、用户可写数据、构建产物、运行时状态。`src/` 内部布局由 [`项目结构优化建议.md`](项目结构优化建议.md) 约定，不在本文范围。

---

## 1. 五类内容与归属（L0）

根目录一级条目**只允许属于以下五类之一**，每类有唯一正确落点：

| 类别 | 特征 | 落点 | 典型条目 |
|---|---|---|---|
| **入口** | 被外部（人/CI/PyInstaller/更新器）直接调用 | 根 | `run.py`、`build.py`、`VERSION`、`requirements.txt` |
| **发布资产** | 需要以固定 URL 直接访问 | 根 | `index.html`、`index.en.html`、`img/`、`LICENSE` |
| **文档** | 供人阅读 | 根仅 `README.md`；其余入 `docs/` | `README.md`、`docs/` |
| **代码 / 资源** | 被程序 import 或随包分发 | `src/`、`res/`、`lib/`、`samples/` | — |
| **工程支撑** | 只服务开发过程，不进产物 | `tools/`、`tests/`、`.github/` | — |
| **运行时状态** | 每次运行会变，属本机数据 | `DATA_ROOT`（**不是根目录**） | `config.json`、`logs/`、`*.db` |

**禁止**在根目录新增第六类内容。若某个新条目无法归入上表，说明它属于某个已有目录的子项，应放进去。

## 2. 根目录白名单（L0）

### 2.1 允许常驻的条目

下表是**当前全部合法条目**，新增必须先登记（见 §8）。"纳管"列指是否进 git。

| 条目 | 职责 | 纳管 | 生命周期 |
|---|---|---|---|
| `run.py` | 进程入口：GUI/CLI/回滚/IPC 判决 | ✅ | 永久 |
| `build.py` | PyInstaller 打包 | ✅ | 永久 |
| `VERSION` | 版本 + 直链 + sha256（唯一事实来源） | ✅ | 永久 |
| `requirements.txt` | 源码运行依赖 | ✅ | 永久 |
| `README.md` | 唯一文档入口 | ✅ | 永久 |
| `config.example.json` | 配置样板（脱敏，键名齐全） | ✅ | 永久（待建） |
| `LICENSE` | MIT | ✅ | 永久 |
| `.gitignore` | 忽略规则（三段式，见 §5） | ✅ | 永久 |
| `.gitattributes` | 行尾/二进制属性 | ✅ | 永久（**待建，当前未纳管**） |
| `index.html` / `index.en.html` | 落地页（GitHub Pages 根） | ✅ | 永久 |
| `img/` | 落地页图片，仅此用途 | ✅ | 永久 |
| `src/` | 应用代码 | ✅ | 永久 |
| `res/` | 随包只读资源（整目录被打包，`build.py:357`） | ✅ | 永久 |
| `lib/` | 第三方原生依赖（`dd_driver` 必打包、`paddle_ocr` 按需） | ✅ | 永久 |
| `samples/` | 用户可写示例库（片段库，可被程序写入） | ✅ | 永久（由 `template/` 迁入，待做） |
| `hooks_override/` | PyInstaller hook 覆盖（`build.py:336`） | ✅ | 永久 |
| `extensions_src/` | 扩展源码（`tools/build_cv_match_extension.py` 的输入） | ✅ | 永久 |
| `docs/` | 文档（四分类，见 §6） | ✅ | 永久 |
| `tools/` | 开发工具（五分类，见 §7） | ✅ | 永久 |
| `tests/` | 回归测试 | ✅ | 永久 |
| `.github/` | CI | ✅ | 永久 |

### 2.2 允许出现但**必须被忽略**的条目

这些是运行/构建的自然结果，允许存在于工作区，但**不得纳管**：

| 条目 | 产生者 | 忽略依据 |
|---|---|---|
| `config.json` | `state.py:354`（`DATA_ROOT`） | 用户本机配置 |
| `recent.json` / `recent_workflow.json` | `ui/exec_bar.py`、`ui/workflow_view.py` | 本机最近使用 |
| `script_versions.db` | `version_manager.py` | 本机版本历史 |
| `.ipc_key` | `single_instance.py` | 本机单实例密钥 |
| `logs/` `backups/` `screenshots/` | `state.py:369/375/543` | 运行日志与备份 |
| `__pycache__/` | Python | 字节码 |
| `dist/` `build/` | `build.py` | 构建产物 |
| `*.spec` | `build.py:319` | 构建中间物 |
| `.venv/` | 开发者 | 虚拟环境 |
| `.vscode/` `.codebuddy/` | IDE / 工具 | 本机缓存 |

**L0**：`git ls-files -i -c --exclude-standard` 必须为空 —— 即不存在"既被跟踪、又匹配忽略规则"的文件。当前有 12 个 `template/*` 违反此条。

### 2.3 禁止出现在根目录的条目（L0）

- 带**空格**的文件名（`ACRPA v0.1.30-beta.spec` 为反例）
- 带**版本号**的文件名（版本是 `VERSION` 文件与 `name=` 字段的事，不是文件名的事）
- 临时/备份后缀：`*.bak`、`*.tmp`、`*.orig`、`*~`、`*_old`、`*(1)`
- 散落脚本：`*.py` / `*.xls` / `*.xlsx` / `*.log`（根下只允许白名单内的 `.py`）
- 一次性排查产物、截图、测试结果

## 3. 文件命名规范

| 对象 | 规则 | 层级 |
|---|---|---|
| 目录名 | 全小写、ASCII、无空格、单词间用 `-`（`hooks_override` 为历史例外，不再新增同类） | L1 |
| 根目录文件 | 入口与文档用大写或惯用名（`README.md`、`VERSION`、`LICENSE`），脚本小写 + 下划线 | L1 |
| 代码/工具文件名 | ASCII + 下划线；测试以 `_test_` 前缀；生成器以 `gen_`；检查器以 `check_` | L1 |
| 面向用户的文档 | **允许中文名**（`docs/guide/快速上手.md`），因为读者是人不是工具 | L1 |
| 资源文件名 | ASCII；`res/template/` 与 `samples/` 允许中文（用户可见） | L2 |
| 版本信息 | **只**写在 `VERSION` 文件与打包 `name=` 字段，文件名中禁止出现 | L0 |

## 4. 运行时状态规范（L0）

**唯一规则：运行时写盘路径必须经 `state.data_path()`，不得直接拼 `APP_ROOT`。**

现状（`state.py:346-354`）：`DATA_ROOT = userdata/ if PORTABLE else APP_DIR`。已有 5 处正确，3 处错误：

| 位置 | 现状 | 必须改为 |
|---|---|---|
| `ui/exec_bar.py:519,561` | `_CTX["app_root"]/recent.json`（注入值 = `APP_ROOT`） | `state.data_path("recent.json")` |
| `ui/workflow_view.py:1399` | `_CTX["app_root"]/recent_workflow.json` | `state.data_path("recent_workflow.json")` |
| `single_instance.py:107` | 异常兜底 `os.getcwd()/.ipc_key` | `state.APP_DIR/.ipc_key` |

**为什么是硬性**：便携模式的定义是"整包搬走可用"，任何绕过 `DATA_ROOT` 的写入都会让该定义失效；`os.getcwd()` 兜底会让单实例互斥在"从快捷方式/任务计划启动"时失效，表现为可开两个主窗口。

**新增运行时文件的准入**：先加到 `state.data_path()` 的白名单，再在 `.gitignore` 的"运行时状态"段登记，两处同一次提交。

## 5. 版本控制规范

### 5.1 `.gitignore` 三段式（L1）

必须按语义分段，段间用注释分隔，**顺序**：① 运行时状态 → ② 构建产物 → ③ IDE/工具缓存。当前文件已接近此结构但存在三个问题：

| 问题 | 证据 | 处理 |
|---|---|---|
| 规则重复 | `build/`、`backups/`、`dist/` 各出现两次 | 去重 |
| 指向已失效的名字 | `!ACRPA.spec` 与 `!res/template/` 例外：前者匹配不到实际文件名，后者依赖"整目录忽略 + 子目录例外"技巧 | 前者删除（spec 不再纳管）；后者改为显式白名单 |
| 用 `!` 例外补救整目录忽略 | 已有 4 处 `!`，其中 `!res/template/` 与 `template/` 相互抵消 | **L0**：不得再用"整目录忽略 + 子目录例外"，改为"忽略具体模式" |

### 5.2 `.gitattributes` 必须纳管（L0）

当前 `.gitattributes` **未提交**，且内容 30/31 行是注释、唯一规则是 `filter=lfs`（从未生效）。规范要求：

```gitattributes
* text=auto eol=lf
*.bat  text eol=crlf
*.cmd  text eol=crlf
*.ps1  text eol=crlf
*.png  binary
*.ico  binary
*.dll  binary
*.xls  binary
*.xlsx binary
*.db   binary
```

LFS 决策依据实测而非传闻：`lib/paddle_ocr/` 全部内容 920 KB，结论是**不上 LFS**。任何"上 LFS"提案须附 `du -sh` 实测。

### 5.3 改名必须全量替换引用（L0）

**根目录文件改名是跨文件操作，不是文件系统操作。** 违反代价见 §9 复盘。

最低要求：`git grep -n "<旧名>"` 无残留，且 `python tools/check_root_layout.py` 的引用完整性检查通过。

## 6. 文档规范

| 规则 | 层级 | 说明 |
|---|---|---|
| `README.md` 是**唯一入口** | L0 | 命令表、FAQ、结构树只存在于 README，不设第二份 |
| `docs/` 根只放索引 | L1 | 根下 md ≤ 1 个（当前 14 个，需归位） |
| `docs/` 四分类 | L1 | `guide/`（用户手册）`design/`（设计方案）`analysis/`（对标分析）`archive/`（已归档）`releases/`（发布说明） |
| 命令表单一来源 | L0 | 事实来源 `res/help/command_schema.json`（实测 94 条）；README 命令表由其生成，禁止手写第二份 |
| 文档改名/移动 | L0 | 同 §5.3 |

**待归位清单**：`docs/` 根下 14 个 md —— `netlink-*`（8 个）→ `design/netlink/`；`*使用说明.md`（浏览器、python扩展、marketplace-v2、paddle-ocr-dll）→ `guide/`；`执行控制tab设计方案.md`、`浏览器后端增强设计.md` → `design/`。`使用说明.md` → `guide/`，其命令清单章节删除，改为指向 README 锚点。

## 7. 工具与测试规范

### 7.1 `tools/` 五分类（L1）

```text
tools/
├── ci/        # CI 直接调用：run_tests.py、static_checks.py、check_toc.py
├── build/     # 构建链路：clean_before_build.py、safe_build.py、rebuild_all.py
├── gen/       # 生成器：export_command_schema.py、gen_script_template_xlsx.py
├── release/   # 发版：bump_version.py、make_release.py、publish_release.py、verify_release.py
├── probe/     # 一次性排查脚本（允许腐烂，不参与 compileall）
└── _out/      # 所有运行产物（测试结果、截图），整目录忽略
```

- **L0**：`_smoke_result_*`、`_ui_screenshots`、`_out` 一类运行产物**一律不纳管**。当前 `_smoke_result_phase1/regression/regression2` 共 111 个文件被跟踪，而 `phase2` 被忽略 —— 同类三种待遇，必须统一。
- **L1**：`compileall` 只编 `src` 与 `tools/{ci,build,gen,release}`，不编 `probe/`。否则一个腐烂的 `_debug_*.py` 会让 CI 变红，与项目质量无关。

### 7.2 `tests/` 规范（L1）

- 文件命名 `_test_<主题>.py`，可被 `tools/ci/run_tests.py` 发现；
- 一个测试文件只验证一个契约，文件名即契约名；
- 断言的是**结构不变量**而非具体文案（例：`_test_index_nav.py` 断言"分组覆盖 == section 序列"而不是"导航第 3 项叫多机互联"）。

## 8. 新增一级条目的准入门槛（L0）

新增根目录一级条目必须同时满足三条，并在此表登记：

1. **不可下沉**：放进 `src/`/`docs/`/`tools/`/`res/` 任一处都无法满足需求（如被外部工具按固定路径调用）；
2. **生命周期明确**：永久 / 构建期 / 运行期，且与表中已有一条不重叠；
3. **有归属类别**：能归入 §1 的五类之一。

登记格式：`| \`名称\` | 职责 | 纳管 | 生命周期 |`，并同步 `tools/check_root_layout.py` 的 `ALLOWED_ROOT`。

## 9. 附录：事故复盘 —— `使用说明.txt` → `.md`

**性质**：根目录文件改名未同步引用，5 处引用至今悬空（commit `462aa4e` 执行了 `A 使用说明.md` + `D 使用说明.txt`）。

| # | 位置 | 引用 | 现有后果 |
|---|---|---|---|
| 1 | `src/dialogs.py:335` | `os.path.join(APP_ROOT, "使用说明.txt")` | 应用内"使用说明"的**本地回退永远失效**（`os.path.exists` 为假，只记一条 warning） |
| 2 | `src/dialogs.py:339` | `DOC_URL = .../blob/master/使用说明.txt` | 在线地址 **404**，且失败后回退到 #1 的失效路径 → 按钮实际打不开任何东西 |
| 3 | `build.py:174` | `EXTRA_DATAS = [..., "使用说明.txt", ...]` | `build.py:372` 的 `os.path.exists` 守卫**静默跳过** → 产物内无说明书 |
| 4 | `tools/make_release.py:44` | `PACKAGE_ITEMS = [..., ("使用说明.txt", "使用说明.txt")]` | `:125` 的 `os.path.exists` **静默跳过** → 发布 zip 缺说明书 |
| 5 | `tools/_gen_help_command_table.py:43` | `DEFAULT_DOC = BASE/使用说明.txt` | 命令表漂移守卫读不到文件（`:235` 提前返回）→ **这道守卫事实上停摆**，正是 README/使用说明 命令数长期漂移的机制性原因 |

**四条教训**（已写入本文 §5.3、§6）：

- 改名 = 跨文件操作，必须 `git grep` 全量核对；
- `os.path.exists` 守卫是"静默失败"的温床 —— 引用缺失文件时应 **fail loud**（至少 log warning，最好让构建失败）；
- 文档类引用有三条独立通道（代码常量、构建清单、发布清单），只改一处等于没改；
- **守卫脚本自身也会腐烂**：漂移守卫指向不存在的文件时，它的"通过"毫无意义 —— 这类脚本必须自查前置条件。

**修复顺序**（建议）：先统一为 `使用说明.md`，改 5 处引用 + `EXTRA_DATAS` + `PACKAGE_ITEMS`；再跑 `python tools/_gen_help_command_table.py --check` 让它真正开始工作，此时大概率会暴露命令表漂移，按 §6 收敛到 schema 单一来源。

## 10. 检查器

```bash
python tools/check_root_layout.py            # 常规：失败返回 1
python tools/check_root_layout.py --json     # 机器可读
python tools/check_root_layout.py --strict   # 把 WARN 也视为失败（建议 CI 用）
```

检查项与规范的对应关系：

| 检查 | 对应条款 | 级别 |
|---|---|---|
| `root.whitelist` | §2.1 | FAIL（新增未登记条目） |
| `root.naming` | §2.3、§3 | FAIL |
| `vcs.ignore_conflict` | §2.2 | WARN（棘轮：基线 12，只减不增） |
| `vcs.attr_tracked` | §5.2 | FAIL |
| `refs.root_files` | §5.3 | FAIL（当前命中 `使用说明.txt`） |
| `docs.root_md` | §6 | WARN（棘轮：基线 14） |
| `tools.probe_count` | §7.1 | WARN（棘轮：基线 55） |
| `build.spec_left` | §2.3 | FAIL |

**棘轮机制**：WARN 类检查带基线，当前数量记为上限；减少后基线不会自动回退（需手动下调），以此保证"只减不增"。

CI 接线（一行，建议与 `ci.yml:41` 的 `compileall` 同 job）：

```yaml
- name: Root layout check
  run: python tools/check_root_layout.py --strict
```
