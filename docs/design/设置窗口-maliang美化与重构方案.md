# ACRPA 设置窗口 maliang 美化与重构方案

> 文档状态：**九页方案已实施（2026-11-04）**；本文前半部分保留设计评审记录，实际落地差异见第 17 节。  
> 创建日期：2026-11-04  
> 目标项目：`D:\CodingEmber\ACRPA`  
> 参考项目：`F:\（8）Desktop\maliang`（本地源码版本 3.2.0）  
> 适用代码：`src/ui/settings/window.py`、`src/ui/settings/cards/*.py`、`src/ui/theme.py`

## 0. 方案结论

建议采用 **“保留配置与业务逻辑，重做设置窗口外壳，按 Python 版本分轨接入 maliang”** 的路线：

1. 保留现有 `state`、配置键、ThemeBus、凭据库、调度器、设备互联和各卡片 `apply()` 业务契约。
2. 将“12 张卡片全部堆叠 + 左导航滚动定位”改为“9 个业务页面切换 + 12 张业务卡片复用”；页面一次构建并缓存，避免重复绑定变量和后台任务。
3. 先完成信息架构、按钮层级、字段文案、保存反馈和两项逻辑修复，再处理视觉组件替换。
4. **保留 Python 3.9 时，只复刻 maliang 的组件设计与交互，不直接引入当前版本；升级到 Python 3.11+ 后，再分页面接入 maliang。**
5. 不复制整个 maliang 源码进 ACRPA，不维护私有降级版，不让 maliang 与 ACRPA 各自独立管理主题。

本方案的重点不是“换一套皮肤”，而是同时提升：

- 设置项的可发现性；
- 页面扫描效率；
- 按钮语义的一致性；
- 保存、失败、待生效状态的可见性；
- 复杂设置页的加载性能与可维护性。

## 1. 现状审查与事实依据

### 1.1 当前实现中应保留的能力

| 能力 | 当前位置 | 处理原则 |
|---|---|---|
| 分组左侧导航 | `window.py:462-484` | 保留分组思想，改为真正页面切换 |
| 600ms 防抖自动保存 | `window.py:297-319` | 保留，补齐关闭前冲刷与统一状态 |
| 卡片级 `build/apply` | `cards/*.py` | 保留业务写回逻辑，逐步分离视图 |
| 保存成功/失败反馈 | `window.py:322-363` | 从每卡角标升级为全局状态 + 当前页就地反馈 |
| 主题色板与 ThemeBus | `ui/theme.py` | 保持唯一主题事实源 |
| 数字校验与设置行布局 | `window.py:384-418`、`cards/_layout.py` | 保留思路，改为元数据驱动与即时校验 |
| Windows 凭据库保存密钥 | `cards/ai.py` | 完全保留，禁止因 UI 迁移改变安全边界 |
| OCR 后台探测 | `cards/advanced.py` | 保留异步方式，改为进入 OCR 页面时再触发 |

### 1.2 当前主要问题

#### P0：快速关闭可能丢失尚未保存的修改

`window.py:276-290` 的 `_close()` 只保存窗口几何和当前 `state`，没有先执行 `_debounce_after` 中等待处理的卡片 `apply()`。

因此，用户修改控件后在 600ms 内关闭窗口，等待中的回调可能随窗口销毁而失效，最新值尚未写回 `state`。

**要求：**关闭窗口、Esc、页面进程退出前必须执行统一的 `flush_pending_saves()`；保存失败时不得静默关闭。

#### P0：两个“恢复默认”入口实际都重置全部配置

`cards/quick.py:65-83` 中，无论 `all_settings` 为 True 还是 False，都会遍历 `state._config_schema` 并重置全部默认值。

**要求：**

- “恢复此页面默认设置”只重置当前页面声明的字段；
- “恢复全部默认设置”单独放入危险操作区；
- 两者使用不同确认文案和影响范围说明；
- 恢复后刷新页面控件、运行时状态和保存状态，不通过简单关闭重开掩盖状态不同步。

#### P1：导航是长页面锚点，不是真正的页面导航

- `window.py:495-522` 通过计算卡片位置进行滚动；
- `window.py:730-739` 打开窗口时构建全部 12 张卡片；
- 折叠卡片会改变内容高度，增加锚点定位维护成本；
- 高级页的 OCR 探测等逻辑会随窗口创建，即使用户没有进入该页面。

**影响：**页面过长、扫描效率低、首屏构建成本高。

#### P1：搜索只匹配导航名称

`window.py:590-613` 仅匹配卡片 key 与显示名，不能定位“识图超时”“快捷键”“Paddle”“API 地址”等具体字段。

#### P1：按钮样式与层级不统一

当前同时存在：

- `_btn()` 创建的扁平按钮；
- 原生 `tkinter.Button(relief="raised")`；
- 强调色实心的“浏览”“刷新状态”“DLL 自检”“导出日志”；
- Label 模拟的链接、图标按钮和录制按钮。

这会导致普通动作、主操作、危险操作和链接缺乏明确区分。

#### P2：默认宽度与表单密度不适配复杂设置

当前默认 `680×680`、最小 `580×500`（`window.py:557-565`）。高级设置中路径、状态文字和多个动作并排时容易拥挤。

#### P2：帮助文字与技术术语使用不统一

例如 `BaseURL`、`Profile`、`持久化`、`最大执行`、`类型`、`应用并重载` 等文案要求用户预先理解内部实现，不够面向任务。

## 2. 重构目标与边界

### 2.1 目标

| 目标 | 验收口径 |
|---|---|
| 快速定位 | 能按字段名、帮助文字、配置 key、别名搜索并跳到具体字段 |
| 单页聚焦 | 导航切换后只展示当前页面，不再滚动遍历全部卡片 |
| 操作明确 | 主按钮、次按钮、文字按钮、危险按钮具有统一规则 |
| 状态可信 | 区分编辑中、保存中、已保存、保存失败、需重启 |
| 配置安全 | 快速关闭不丢修改；本页重置不影响其他页面 |
| 视觉一致 | 亮暗主题、缩放、焦点、禁用和悬停均使用统一令牌 |
| 渐进迁移 | 每页独立迁移、独立回归，可随时回退到旧页面 |
| 打包可用 | PyInstaller 产物中页面、样式和组件不缺失 |

### 2.2 非目标

- 不修改 `config.json` 的既有键名和数据含义；
- 不重写 OCR、调度器、NetLink、脚本市场等业务模块；
- 不追求所有页面一次性换成 maliang；
- 不使用高成本玻璃、模糊、阴影或大幅动画掩盖信息层级；
- 不为了组件统一而牺牲快捷键录制、账户管理等复杂交互。

## 3. 设计方向

### 3.1 设计关键词

**清晰、克制、原生、可扫描、状态可信。**

采用“Windows 11 设置页的信息架构 + maliang 的 Canvas 自绘控件”：

- 通过留白、字号和分节建立层级，而不是增加装饰；
- 卡片使用细描边和弱表面差异，不使用厚重阴影；
- 强调色只用于当前导航、焦点、主按钮和关键状态；
- 图标保持单色，避免彩色 Emoji 破坏跨系统一致性；
- 所有关键帮助和错误信息直接显示，不只藏在 Tooltip 中。

### 3.2 页面框架

```text
┌──────────────────────┬───────────────────────────────────────────────┐
│ 设置                 │ 页面标题                         自动保存状态 │
│ ┌──────────────────┐ │ 页面用途说明                                   │
│ │ 搜索设置…       │ ├───────────────────────────────────────────────┤
│ └──────────────────┘ │ ┌ 分节标题 ─────────────────────────────────┐ │
│ 常用                 │ │ 字段标签       控件                       │ │
│  常规                │ │                帮助文字 / 校验信息          │ │
│  执行                │ │ 字段标签       控件       [次按钮]          │ │
│  录制与日志          │ └───────────────────────────────────────────┘ │
│  定时任务            │ ┌ 分节标题 ─────────────────────────────────┐ │
│ 智能与高级           │ │ 开关标题                           开关    │ │
│  AI 与 OCR           │ │ 开关作用说明                                  │ │
│  浏览器与驱动        │ │ 状态文本             [主按钮] [次按钮]      │ │
│ 连接                 │ └───────────────────────────────────────────┘ │
│  设备互联            │                                               │
│  扩展与市场          │                                               │

│ 关于                 │                                               │
├──────────────────────┴───────────────────────────────────────────────┤
│ ● 所有更改已保存                       2 项需重启 · 关闭前自动保存    │
```

### 3.3 推荐尺寸与响应式规则

| 项目 | 推荐值 |
|---|---|
| 默认窗口 | `960×680` |
| 最小窗口 | `820×560` |
| 左侧导航 | `200px` |
| 内容区外边距 | `24px` |
| 表单最大宽度 | 约 `720px`，宽屏不无限拉伸 |
| 标签列 | `144–160px` |
| 输入框/按钮高度 | `32px` |
| 导航项高度 | `36px` |
| 设置行最小高度 | `52px`，带帮助文字时自动增长 |
| 卡片内边距 | `16–20px` |
| 分节间距 | `16–24px` |

响应式要求：

- 窗口变窄时优先让标签移到控件上方，不压缩按钮文字和帮助文字；
- 路径输入框收缩，浏览按钮保持可见；
- 状态文本允许换行，动作按钮可移到下一行；
- 禁止通过水平裁切解决布局不足；
- 所有尺寸继续消费 DPI/UI Scale 令牌，不能写死缩放后的像素。

## 4. 信息架构：12 张卡片重组为 9 个页面

| 导航分组 | 页面 | 现有内容归属 | 设计说明 |
|---|---|---|---|
| 常用 | 常规 | `system.py` | 启动、托盘、界面、Mini Bar、快捷键 |
| 常用 | 执行 | `exec.py` + `advanced.py` 的执行与绑定部分 | 重试、输入方式、故障保护、最长运行、出错处理 |
| 常用 | 录制与日志 | `record.py` + `log.py` | 两个独立分节；导出日志作为次按钮 |
| 常用 | 定时任务 | `sched.py` + 调度轮询 | 基础计划与高级轮询分开；显示下次执行 |
| 智能与高级 | AI 与 OCR | `ai.py` + OCR/PaddleOCR.dll | AI 服务和 OCR 为两个分节；低使用率协议参数折叠 |
| 智能与高级 | 浏览器与驱动 | 浏览器设置 + DD 驱动 | 浏览器用户目录、后台运行、驱动路径与说明 |
| 连接 | 设备互联 | `netlink.py` | 基础开关、配对安全、Web 控制、TLS 分层展示 |
| 连接 | 扩展与市场 | `python.py` + `market.py` + `extensions.py` | 扩展运行权限、市场账户、可选依赖管理 |
| 底部入口 | 关于 | `quick.py` | 版本、更新、开源信息、分级恢复默认 |

### 4.1 “高级设置”的处理原则

不再保留一个混杂所有底层配置的“大高级页”：

- OCR、DLL、模型、调用原型 → AI 与 OCR；
- 浏览器通道、Profile → 浏览器与驱动；
- DD DLL → 浏览器与驱动中的“输入驱动”分节，或执行页的高级分节；
- 调度轮询 → 定时任务的高级选项；
- 最大执行、绑定窗口、出错处理 → 执行。

高级不等于难找。高级参数应收在**所属业务页面**中，而不是集中堆放。

### 4.2 搜索设计

搜索范围：

- 页面名、分节名、字段标签；
- 帮助文字；
- 配置 key，如 `ocr_threads`；
- 别名与同义词，如“截图/文字识别/OCR”、“密钥/API Key”；
- 可选：拼音首字母索引。

搜索结果项包含：

```text
图像识别超时
执行 · 重试与超时
图片识别等待时间，超时后跳过当前识别
```

交互要求：

- `Ctrl+F` 聚焦搜索；
- 上下键移动结果，Enter 跳转并聚焦字段；
- 跳转后显示所属页面和分节，并短暂高亮字段行；
- 无结果时显示可修改关键词的建议，不弹错误框；
- Esc 优先清除搜索/关闭结果，再次触发才关闭窗口。

## 5. 视觉规范

### 5.1 颜色

继续以 `src/ui/theme.py` 为唯一色板来源，不另建一套独立品牌色。

| 角色 | 亮色取值 | 暗色取值 | 用途 |
|---|---|---|---|
| 窗口背景 `bg` | `#F3F3F3` | `#202020` | 页面与导航背景 |
| 卡片表面 `bgc` | `#FFFFFF` | `#2B2B2B` | 设置分节与输入表面 |
| 次级表面 `surface_alt` | `#F7F7F7` | `#262626` | 次按钮、弱分区 |
| 主文字 `fgt` | `#1F1F1F` | `#FFFFFF` | 标题、重要状态 |
| 正文 `fgb` | `#333333` | `#E0E0E0` | 字段与控件 |
| 辅助文字 `fgm` | `#5F5F5F` | `#A0A0A0` | 帮助、单位、次级说明 |
| 强调色 `ac` | `#0078D4` | `#4CC2FF` | 当前导航、焦点、主按钮 |
| 边框 `bd` | `#D6D6D6` | `#3F3F3F` | 1px 卡片与控件描边 |
| 成功 `sc` | `#107C10` | `#6CCB5F` | 保存成功、连接成功 |
| 警告 `wn` | `#C2410C` | `#FCE100` | 需重启、配置风险 |
| 危险 `dg` | `#C42B1C` | `#FF99A4` | 删除、清空、失败 |

规则：

- 暗色主题的浅色强调底上使用深色文字，由现有 `text_on()` 计算；
- 不用颜色作为唯一状态表达，必须同时提供文字或图标；
- 普通正文与背景对比度至少 4.5:1；
- Mica/Acrylic 仅作为可选窗口背景效果，不能降低表单对比度，默认仍使用实色。

### 5.2 字体与图标

| 角色 | 推荐规格 |
|---|---|
| 页面标题 | Microsoft YaHei UI，16pt，bold |
| 分节标题 | Microsoft YaHei UI，11pt，bold |
| 正文与字段 | Microsoft YaHei UI，10pt，normal |
| 按钮 | Microsoft YaHei UI，10pt，bold 或 semibold 等效 |
| 帮助与状态 | Microsoft YaHei UI，9pt，normal |
| 图标 | Segoe Fluent Icons；回退 Segoe UI Symbol |

图标建议：

- 不使用彩色 Emoji；
- 图标只辅助识别，不替代字段文字；
- 图标按钮必须提供 Tooltip、可聚焦状态和可访问名称；
- 密钥显示、复制等图标保持固定尺寸，避免点击区域仅覆盖字形。

### 5.3 圆角、描边与动效

- 卡片圆角：`8px`；输入和按钮圆角：`6px`；
- 描边：默认 1px `bd`，悬停使用 `border_strong`，焦点使用 2px `focus`；
- 页面切换：`120–160ms` 淡入或轻位移；
- 悬停和按钮状态：`80–120ms`；
- `REDUCE_MOTION=True` 时全部退化为立即切换；
- 不使用渐变、发光、重投影和连续装饰动画。

## 6. 按钮与操作规范

### 6.1 按钮层级

| 类型 | 视觉 | 使用规则 | 示例 |
|---|---|---|---|
| 主按钮 | 强调色实心 | 每个页面最多一个；允许整页没有主按钮 | 测试连接、重新加载 OCR 后端 |
| 次按钮 | 中性底 + 1px 描边 | 普通命令和辅助动作 | 浏览…、刷新状态、导出日志… |
| 文字按钮 | 无底色，强调色文字 | 帮助、跳转、低频入口 | 输入方式说明、管理提供商… |
| 危险按钮 | 默认危险色描边 | 删除、清空、重置 | 清空指纹、恢复全部默认 |
| 图标按钮 | 透明/弱表面 | 含义直观的单动作 | 显示密钥、复制路径 |

危险操作的红色实心按钮只出现在二次确认对话框中，作为最终确认动作，不在普通页面大面积使用。

### 6.2 异步按钮状态

以“测试连接”为例：

```text
默认：     [测试连接]
执行中：   [正在测试…]（禁用，附 Spinner）
成功：     ● 连接成功，模型可用（就地显示）
失败：     ● 连接失败：原因 [重试]
```

要求：

- 防止重复提交；
- 结果就近显示；
- 异常文案包含可执行的下一步；
- 不使用模态框展示常规进度；
- 后台线程只计算，UI 更新必须回主线程。

### 6.3 省略号与命名

- 会打开文件/目录选择器：`浏览…`；
- 会打开保存对话框：`导出日志…`；
- 会打开管理窗口：`管理提供商…`；
- 立即执行且不需要补充信息：`刷新状态`、`测试连接`，不加省略号；
- 自动保存体系下不再使用含义不清的“应用并重载”，改为“重新加载 OCR 后端”。

## 7. 控件与字段行为

### 7.1 控件选择

| 字段类型 | 推荐控件 | 说明 |
|---|---|---|
| 即时启停功能 | Switch | 如智能重试、日志保存 |
| 多选或并列独立能力 | CheckBox | 不使用 Switch 代替所有复选语义 |
| 单选模式 | SegmentedButton 或 RadioBox | 输入方式、重复周期 |
| 短整数/小数 | SpinBox | 次数、线程数、超时 |
| 连续范围 | Slider + 数值框 | 透明度等需要精确值的字段 |
| 固定选项 | ComboBox | OCR 后端、浏览器、日志级别 |
| 单行文本 | InputBox | 模型名、窗口标题 |
| 密钥 | InputBox(show="*") + 显示按钮 | 凭据库写回逻辑不变 |
| 路径 | InputBox + 浏览… | 显示存在性和类型校验 |
| 只读状态 | 状态文字 + 次按钮 | 不参与自动保存 |

### 7.2 联动规则

- 父开关关闭时，子字段禁用但保留原值；
- 禁用区同时显示原因，例如“启用 PaddleOCR.dll 后可配置”；
- 禁用不能只用降低透明度表达，还需改变控件状态并阻止编辑；
- 切换选项时，只更新相关字段，不重置用户其他输入；
- 程序化回填不得再次触发自动保存，避免保存循环。

### 7.3 校验规则

当前“非法输入后恢复默认值”的方式会覆盖用户原本合法值，建议调整为：

1. 输入过程中进行轻量格式校验；
2. 失焦或防抖保存前完成范围校验；
3. 非法值不落盘，字段行下方显示原因和有效范围；
4. 保留用户输入，提供“恢复为上次有效值”动作；
5. 关闭窗口时如仍有非法值，明确提示，不静默丢弃。

路径字段还应校验：是否存在、是文件还是目录、是否满足特定后端的路径要求。

## 8. 保存与状态反馈

### 8.1 状态模型

| 状态 | 显示位置与内容 |
|---|---|
| 已修改待保存 | 当前页标题旁“有未保存更改”，底部“正在等待保存…” |
| 保存中 | 底部“正在保存…”，防止重复写入 |
| 已保存 | 底部“● 所有更改已保存” |
| 保存失败 | 底部错误摘要 +“查看详情/重试”，相关字段行标错 |
| 已保存待重启 | 字段行“需重启生效”，底部汇总数量 |
| 校验失败 | 字段行显示错误，未进入保存流程 |

“已保存”和“已生效”必须分开表达，特别是 OCR、界面缩放、驱动和调度相关字段。

### 8.2 关闭与页面切换

- 页面切换不应销毁未保存数据；页面控制器持有编辑状态；
- 关闭窗口和 Esc 前执行 `flush_pending_saves()`；
- 保存失败时提供“重试”“保留窗口”“放弃未保存修改并关闭”的明确选择；
- 不允许仅写 `WIN_GEOMETRY` 后就销毁窗口；
- 自动保存下不额外增加常驻“保存”按钮，失败状态可提供“立即重试”。

帮助文字回答“有什么影响、何时生效、有什么代价”，不重复标题。

推荐示例：

- API 密钥：`密钥仅保存在 Windows 凭据库，不写入 config.json。`
- 图像识别超时：`等待图像识别完成的最长时间；超时后跳过当前识别。`
- 后台运行浏览器：`执行期间不显示浏览器窗口；调试页面问题时建议关闭。`

## 10. maliang 复用与接入设计

### 10.1 组件映射

| ACRPA 需求 | maliang 组件/能力 | 使用建议 |
|---|---|---|
| 功能开关 | `widgets.Switch` | 替代现有自绘开关，保持命令回调 |
| 文本/密钥输入 | `widgets.InputBox` | 密钥使用 `show="*"` |
| 数值输入 | `widgets.SpinBox` | 范围仍需 SettingsStore 校验 |
| 下拉选择 | `widgets.ComboBox` | 提供商、OCR、浏览器 |
| 单选模式 | `widgets.SegmentedButton` / `RadioBox` | 输入方式、重复周期 |
| 连续值 | `widgets.Slider` | 与数值框组合，不只显示滑块 |
| 普通按钮 | `widgets.Button` | 通过自定义 Style 区分主次 |
| 链接 | `UnderlineButton` / `HighlightButton` | 帮助与跳转 |
| 图标动作 | `widgets.IconButton` | 显示密钥、复制等 |
| 加载状态 | `widgets.Spinner` | 测试连接、依赖检测 |
| 补充提示 | `widgets.Tooltip` | 只承载补充说明 |
| 页面与卡片 | `Canvas` + `virtual.Widget` + 圆角 Shape | 需要 ACRPA 自行封装 |
| 文件与消息对话框 | `TkMessage` / 现有 tkinter 对话框 | 第一阶段保持原生，降低回归 |

### 10.2 必须自行封装的设置组件

maliang 提供绘制和基础控件，不是完整设置页框架。ACRPA 仍需实现：

- `SettingsWindowShell`：窗口、导航、页面容器、底部状态栏；
- `SettingsNavItem`：选中、悬停、焦点、搜索结果数量；
- `SettingsSection`：标题、说明、内容容器；
- `SettingsRow`：标签、控件、单位、帮助、错误、重启标记；
- `SettingsButton`：primary/secondary/tertiary/danger 四类；
- `SettingsSearch`：索引、结果、键盘导航与字段定位；
- `MaliangThemeAdapter`：ACRPA 色板到 maliang Style 的映射。

### 10.3 主题集成原则

ACRPA 的 ThemeBus 是唯一主题事实源：

```text
ACRPA ThemeBus.publish
        │
        ▼
MaliangThemeAdapter
        │
        ├─ 映射 light/dark 与 C[*] 到 maliang Style
        ├─ 刷新当前页面和已缓存页面
        └─ 同步 Canvas 背景、焦点、禁用与语义色
```

现有 `window.refresh_theme()` 的递归 `winfo_children()` 只能看到 Canvas 容器，无法完整遍历其内部虚拟控件，因此不能直接把 maliang 控件当作普通 tkinter 子控件换肤。

禁止：

- ACRPA 与 maliang 分别监听系统主题并各自换色；
- 在递归 walk 中只改 Canvas 背景，却不更新内部 Shape/Text；
- 在卡片内直接写死新的颜色字面量。

## 11. 兼容性门槛与技术分轨

### 11.1 已核实的约束

| 项目 | ACRPA | maliang 3.2.0 | 结论 |
|---|---|---|---|
| Python | README 标注 3.8+，开发与 CI 使用 3.9 | `pyproject.toml` 要求 `>=3.11` | 当前基线不能直接接入 |
| 必选依赖 | 项目现有依赖 | `typing-extensions` | 核心包依赖较少 |
| Pillow | `requirements.txt` 为 `>=9,<10` | 可选依赖 `opt` 要求 `>=10` | 不能直接安装 `maliang[opt]` |
| UI 承载 | tkinter/ttk + 自绘 Canvas | tkinter Canvas 虚拟控件 | 设计理念兼容，但控件树和主题刷新不同 |
| 打包 | PyInstaller 静态导入约束 | 包资源与模块需纳入 Analysis | 必须验证打包产物 |

### 11.2 路线 A：保留 Python 3.9（默认稳妥路线）

- 不直接引入 maliang 3.2.0；
- 参考其 Switch、Button、InputBox、Slider 的视觉与状态设计；
- 扩展现有 `RoundedSwitch` 和 `ui.widgets`，形成设置页专用组件；
- 先完成本方案的信息架构、保存模型和视觉规范；
- 未来升级 Python 后，可将组件适配层替换为真正的 maliang 实现。

优点：不破坏当前支持范围和 CI，回归面最小。  
代价：需要维护本地控件，不能直接使用 maliang 后续修复。

### 11.3 路线 B：升级到 Python 3.11+

前置条件：

1. 项目正式宣布最低 Python 版本调整为 3.11；
2. CI、开发文档、打包环境和用户安装说明同步升级；
3. 全量测试通过；
4. 明确 Pillow 升级策略，或只安装 maliang 核心包而不安装 `opt`；
5. 固定 maliang 版本，不从本地绝对路径导入。

迁移顺序：常规 → 执行 → AI 与 OCR → 其他简单页面 → 复杂页面。

优点：直接复用 maliang 控件和动画能力。  
代价：运行时支持范围、依赖和打包均发生变化，属于独立版本决策。

### 11.4 不推荐的做法

- 将 `F:\（8）Desktop\maliang\src` 直接加入生产 `sys.path`；
- 复制整个源码树后删除新版本语法以兼容 Python 3.9；
- 为得到 Mica 而一次性安装全部可选依赖；
- 在两个 Python 进程间仅为了设置页进行 UI 通信。

```text
  controller.py          # 当前页面、搜索、关闭前冲刷、状态汇总
  store.py               # 唯一写入口、dirty、校验、保存、reset_page
  registry.py            # 页面/字段元数据、依赖、范围、单位、别名
  theme_adapter.py       # ThemeBus 到具体组件实现的主题适配
  components/
    section.py
    row.py
    button.py
    navigation.py
    status_bar.py
  pages/
    general.py
    execution.py
    recording_logs.py
    schedule.py
    ai_ocr.py
    browser_driver.py
    netlink.py
    extensions_market.py
    about.py
  legacy_cards/          # 迁移期旧卡片，按页面逐步退役
```

### 12.1 字段元数据

```python
ConfigField(
    key="ocr_threads",
    page="ai_ocr",
    section="ocr",
    label="CPU 线程数",
    kind="int",
    min=1,
    max=32,
    unit="线程",
    help="pip 版与 DLL 后端共用；过高可能增加内存占用。",
    aliases=("OCR 线程", "识别线程"),
    needs_restart=False,
)
```

元数据至少覆盖：页面、分节、标签、类型、范围、单位、帮助、别名、依赖、是否需重启、是否敏感、是否高级。

复杂交互（快捷键录制、账户登录、配对、DLL 自检）保留手写页面，不强求 100% schema 化。

### 12.2 保存边界

```text
控件变更
   │
   ▼
SettingsController 标记 dirty
   │
   ▼
SettingsStore 校验并防抖
   │
   ├─ 校验失败 → 字段行错误，不写盘
   │
   ▼
写回 state / 凭据库
   │
   ▼
执行必要的运行时副作用
   │
   ▼
state.save_config()
   │
   ├─ 成功 → 已保存 / 已保存待重启
   └─ 失败 → 保留 dirty + 可见错误 + 可重试
```

## 17. 实际实施结果（2026-11-04）

### 17.1 已落地的结构

当前版本采用 **“9 页外壳复用 12 卡业务逻辑”**，没有引入第二套 Store 或完整 Registry：

| 页面 | 实际内容 |
|---|---|
| 常规 | `system.py` |
| 执行 | `exec.py` 与 `advanced.py` 的执行时限、绑定窗口、出错处理 |
| 录制与日志 | `record.py`、`log.py` |
| 定时任务 | `sched.py` 与调度轮询 |
| AI 与 OCR | `ai.py` 与 OCR、PaddleOCR.dll 设置 |
| 浏览器与驱动 | 浏览器设置与 DD 驱动路径 |
| 设备互联 | `netlink.py` |
| 扩展与市场 | `python.py`、`market.py`、`extensions.py` |
| 关于 | `quick.py` |

`window.py` 保留 12 个卡片模块的静态 import，确保 PyInstaller 可收集；`advanced.py` 分节只创建一次，合并 handles 后仍走原 `apply()`。`src/settings_window.py` 继续作为兼容薄壳，公共入口未改。

页面宿主一次构建并缓存，通过 `grid/grid_remove` 切换；Tk Variable、trace、apply、600ms 防抖保存及运行时副作用沿用原路径。切页保留编辑值和各页滚动位置，不重复创建卡片或后台任务。OCR 等延迟任务通过统一生命周期管理，在窗口关闭时取消。

### 17.2 搜索、保存与重置

- 左侧搜索支持页面、字段说明和已注册别名，不读取或保存 Entry 内容；结果可切页、滚动并定位目标。
- 支持 `Ctrl+F`、结果键盘导航、`Enter` 和 `Esc`；第一次 `Esc` 关闭搜索结果，再次触发才关闭窗口。
- `flush_pending_saves()` 会同步执行所有待处理 apply/save；标题栏关闭与 `Esc` 均先冲刷。
- 保存失败时保留窗口，可重试、返回或明确放弃未保存修改，不静默丢失配置。
- 关于页“恢复本页默认”只处理 `check_update` 并同步界面变量；全部重置仍位于独立危险操作确认流程。
- 凭据库、配置键、默认值及敏感信息存储边界未改。
