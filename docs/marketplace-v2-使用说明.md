<a id="open"></a>
## 1. 打开市场窗口

在**脚本编辑器工具栏**点击「**市场**」按钮即可打开脚本市场窗口。

窗口自上而下由四部分组成：

1. **顶部**：账号区（登录状态）+ 搜索框 + 分类下拉 + 「标签 ▾」筛选；
2. **操作栏**：「刷新」「上传脚本」；
3. **主体**：脚本卡片列表（四种状态，见下）；
4. **状态栏**：脚本计数与登录信息。

窗口主体为**四态容器**，同一位置按数据源切换：

| 状态 | 触发时机 | 呈现 |
| --- | --- | --- |
| 加载中 | 打开窗口 / 点「刷新」 | 「正在加载脚本库…」+ 进度动画 |
| 空态 | 筛选或搜索后 0 条 | 「没有找到匹配的脚本」+「清除筛选」 |
| 错误态 | 在线拉取失败且未回退 | 错误文案 +「重试」按钮 |
| 正常 | 有数据 | 卡片列表 + 状态栏计数 |

<a id="browse"></a>
## 2. 浏览、搜索与筛选

- **搜索**：在搜索框输入关键字，**输入即筛**。匹配范围包括脚本名称、简介、分类与标签。
- **分类筛选**：分类下拉为四选一 —— **办公 / 财务 / 系统 / 其他**（另有「全部」）。
- **标签筛选**：点「标签 ▾」展开多选菜单，勾选若干标签，多个标签之间为**或（任一命中）**关系。
- **叠加规则**：搜索、分类、标签可同时生效，三者**与（同时满足）**组合。
- **清除筛选**：空态下点「清除筛选」，或在搜索框清空、分类切回「全部」、取消全部标签勾选。

> 标签菜单由当前脚本集合动态生成，最多列出前 20 个标签。

<a id="install"></a>
## 3. 查看详情与安装

### 3.1 卡片与详情

每张卡片显示脚本图标、名称、版本、分类、简介、作者、评分 / 下载量与前几个标签。
点「**详情**」打开详情弹窗，可查看完整简介、标签、依赖提示（`requires`）与文件清单，
底部提供「导入到编辑器」入口。

### 3.2 安装到编辑器

- 在卡片或详情中点「**导入**」→ 后台下载 → 完成自动**载入脚本编辑器**，
  并同步更新当前的脚本目录与文件名。
- **两种分发形态**（对使用者透明）：
  - **包模式（v2）**：市场条目携带 `.acrpapkg` 包 → 下载后做 **sha256 完整性校验** → 解包安装到
    `market_scripts/<id>/`，脚本与图片同目录，图像识别可直接命中；
  - **旧单文件模式（v1）**：条目仅含单个 `.xls` → 下载到安装根目录并平铺，行为与历史版本一致。
- 两种形态同时存在时优先按包模式处理。

### 3.3 离线回退

在线拉取索引失败时，市场窗口可**回退到内置脚本库**继续展示与安装，
此时列表来自本地内置数据，而非远程市场。

<a id="login"></a>
## 4. 账号登录（GitHub / Gitee）

市场**浏览与安装无需登录**；仅在**上传投稿**时需要登录。

### 4.1 登录方式：个人访问令牌（PAT）

市场采用 **Personal Access Token（个人访问令牌）** 方式登录，不涉及跳转式 OAuth 回调：

1. 在市场窗口点击**账号区**，选择「**使用 Gitee 登录**」或「**使用 GitHub 登录**」；
2. 或直接在账号下拉菜单中选择「如何获取 Token？」查看对应平台的令牌页面。

**如何生成 PAT（按官方设置页导航文字说明）**

- **GitHub**：登录 GitHub → 右上角头像 → **Settings** → **Developer settings** →
  **Personal access tokens**（经典令牌或细粒度令牌）→ 新建令牌 → 按提示勾选
  **仓库读写（经典令牌通常勾选 `repo`）** 等所需权限 → 生成并**立即复制**令牌串。
- **Gitee**：登录 Gitee → 右上角头像 → **设置** → **安全设置** → **私人令牌 / 访问令牌** →
  生成新令牌 → 按提示勾选**仓库读写（`projects`）与 PR（`pull_requests`）** 等所需权限 →
  生成并**立即复制**令牌串。

> 令牌仅在生成时显示一次，请及时保存。市场窗口内不加伪造链接，帮助入口直接指向上述官方设置页。

### 4.2 登录与注销

- **登录**：粘贴令牌 → 客户端会在后台调用平台 API **校验令牌有效性**；校验通过后登录成功，
  状态栏与账号区显示当前用户名。
- **注销**：账号下拉菜单选择「注销 <平台>」→ 清除本机保存的令牌并刷新账号区。
- **多平台**：可分别登录 Gitee 与 GitHub；上传时使用当前所选平台。

### 4.3 令牌存储与安全

- 令牌**只写入 Windows 凭据库**（Credential Manager），**不写入 `config.json`、不写入日志、不上传**。
- 若凭据库不可用，登录会**直接失败**，而**不会回退为明文落盘**。
- 错误提示中的令牌内容一律脱敏为 `***`。
- 建议为市场投稿**单独生成一枚最小权限令牌**，仅勾选仓库读写与 PR 所需范围，用后可随时在平台侧吊销。

<a id="upload"></a>
## 5. 上传脚本（5 步向导）

点操作栏「**上传脚本**」打开上传向导，共 5 步（每步在后台执行，界面实时反馈）：

| 步骤 | 名称 | 内容 |
| --- | --- | --- |
| 1 | 选择脚本 | 选择本地 `.xls`；自动识别同目录图片数量 |
| 2 | 填写元数据 | `id` / 名称 / 简介 / 分类 / 作者 / 版本 / 标签 / 图标 / 最低版本等，**实时校验** |
| 3 | 打包预览 | 只读预览 `manifest.json` → 执行打包 → 显示包路径 / 体积 / sha256 |
| 4 | 登录校验 | 显示当前账户；未登录可就地引导登录 |
| 5 | 上传 | 进度条驱动阶段：校验登录 → 建分支 → 传包 → 更新 `index.json` → 发 PR；完成后给出 **PR 链接** |

上传流程（持有令牌时）经对应平台 OpenAPI **建分支 → 提交包 → 提交 `index.json` → 发起 PR**，
由仓库维护者评审合并；投稿基线分支为 **`master`**。

### 5.1 投稿前置自检

提交前请逐项确认（与市场仓库 README 的自检清单一致）：

- [ ] **`id` 唯一**，且**不得以 `builtin_` 开头**；
- [ ] **`category` 仅限**：`办公` / `财务` / `系统` / `其他`（四选一）；
- [ ] **`filename` / `entry` 必须真实存在**：指向的 `.xls` 需确实存在于脚本（或包）内；
- [ ] **必须是真 `.xls`**（Excel 二进制表格，**不支持 `.xlsx`**）；
- [ ] **脚本内命令名须已注册**：所用命令均需在 `src/commands.py` 的命令注册表内。

> 第 2 步会对 `id`、分类、必填字段做实时校验；命令注册校验会读取 `.xls` 的
> 0 行表头（跳过）、1 行标题、2 行起命令列，逐一比对命令注册表，不合规会在向导中直接拦截并指出命令名。

<a id="package"></a>
## 6. `.acrpapkg` 包格式摘要

`.acrpapkg` 是市场 v2 的**脚本分发包**，本质是一个**标准 ZIP 归档**（便于人工审阅与校验），
文件名建议为 `<id>-<version>.acrpapkg`（版本号进文件名，可规避 raw CDN 缓存）。

### 6.1 目录布局

```
<id>-<version>.acrpapkg   (ZIP)
├── manifest.json          # 必需，包根
├── README.md              # 可选，投稿 / 使用说明
├── scripts/
│   └── <entry>.xls        # 必需，脚本主体（二进制 Excel）
└── images/
    └── *.png              # 可选，脚本引用的图像资源（安装时与脚本同目录）
```

包内条目仅允许落在白名单前缀 `manifest.json`、`README.md`、`scripts/`、`images/` 之下，
其它顶层前缀一律拒绝。

### 6.2 `manifest.json` 关键字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `manifest_version` | int | ✅ | 清单格式版本，当前支持 `1` |
| `id` | str | ✅ | 唯一标识，不得以 `builtin_` 开头（`^[a-z][a-z0-9_]{2,49}$`） |
| `name` | str | ✅ | 展示名，≤60 字符 |
| `description` | str | ✅ | 简介，≤300 字符 |
| `category` | str | ✅ | 四选一：`办公` / `财务` / `系统` / `其他` |
| `author` | str | ✅ | 作者标识，≤40 字符 |
| `version` | str | ✅ | 语义化版本 `MAJOR.MINOR[.PATCH]` |
| `entry` | str | ✅ | 包内 `.xls` 相对路径，须命中 `scripts/` 且实际存在 |
| `tags` | str[] | ⭕ | ≤8 个，单个 ≤16 字符 |
| `icon` | str | ⭕ | Emoji 或短字符 |
| `requires` | str[] | ⭕ | 依赖标记 `pywin32` / `ocr` / `playwright` / `dd_driver`（**仅提示，v2 不自动安装**） |
| `images` | str[] | ⭕ | 包内 `.png` 相对路径（须命中 `images/`） |
| `readme` | str | ⭕ | 包内 README 相对路径 |
| `min_app_version` | str | ⭕ | 兼容最低 ACRPA 版本 |
| `script_sha256` | str | ⭕ | **包内 `entry` 脚本内容**的 sha256，由打包自动写入 |
| `signature` | str/null | ⭕ | 预留签名位（v2 不校验，统一为 `null`） |

### 6.3 两种 sha256 的语义

务必区分这两个**命名刻意不同**的校验值：

| 位置 | 字段 | 覆盖对象 |
| --- | --- | --- |
| **包内** `manifest.json` | `script_sha256` | **包内 `.xls` 脚本文件**的哈希（单文件完整性） |
| **市场** `index.json` 条目 | `sha256` | **整个 `.acrpapkg` 文件**的哈希（整包完整性） |

客户端安装包模式脚本时，以条目 `sha256` 对**下载到的整包**做前置校验，不符即拒绝、不打开归档。

### 6.4 安全校验

`unpack` 在执行安装前会强制通过以下硬约束，任一违反即整体拒绝：

1. **sha256 前置校验**：传入期望哈希时，先对整个包计算 sha256，不符立即拒绝；
2. **防 zip-slip（路径穿越）**：拒绝含 `..` 路径段、绝对路径、Windows 盘符的成员，拒绝符号链接成员，
   规范化后断言解压目标落在安装根目录之内；
3. **体积 / 数量上限**：文件数上限 256；解压后总字节与单文件上限 64 MB；
   单条压缩比 > 200:1 且解压后 > 1 MB 视为疑似 zip bomb 并拒绝；
4. **白名单前缀**：成员须命中 `manifest.json` / `README.md` / `scripts/**` / `images/**`；
5. **结构校验**：根有 `manifest.json`、JSON 可解析、版本受支持、必填字段齐备、`entry` 与 `images[]` 实际存在；
6. **原子安装**：先解压到临时目录，全部通过后再整体移动到最终目录；任一步失败则清理临时目录、现场不变；
7. **只读落盘**：安装产物仅含数据文件，**不执行**包内任何内容。

<a id="faq"></a>
## 7. 常见问题

**Q：推送后市场里迟迟看不到新版本？**

- Gitee 的 raw CDN **存在缓存**，推送后新内容可能**延迟可见**。
- 客户端侧可用配置项 `market_index_cache_ttl`（索引缓存秒数，默认 3600）调节客户端本地缓存时长，
  也可点市场窗口「刷新」强制重新拉取。
- 包文件名带版本号（`<id>-<version>.acrpapkg`）本身即为规避缓存的一环。

**Q：上传提示分支 / 目标分支不对？**

- 投稿基线分支**必须是 `master`**；其它分支不作为投稿目标。

**Q：登录提示令牌无效？**

- 确认复制的是**完整令牌串**且未过期；确认已勾选**仓库读写与 PR** 相关权限；必要时在平台侧重新生成。

**Q：导入后脚本报「找不到图片」？**

- 包模式下图片会与脚本**安装到同一目录**，图像识别按脚本目录查找；
  请确认投稿时 `images[]` 已正确列入且文件已在包内。

**Q：`.xlsx` 能投稿吗？**

- 不能。脚本必须为**真 `.xls`**（二进制 Excel）。`.xlsx` 与错误扩展名均不接受。

<a id="ci-sign"></a>
## 8. 投稿侧 CI 与作者签名（规划 / 未实现）

> ⚠️ **以下能力为后续规划项，当前版本尚未实现**，仅作方向说明，请勿据此操作。

- **投稿侧 CI**：规划在投稿 PR 上运行 **AST 静态检查**，对脚本内命令与参数做结构校验，
  并比对**敏感命令清单**，对高风险命令在评审中显式提示。
- **作者密钥签名**：规划引入**作者密钥签名**（如 Ed25519 / HMAC），把作者身份与包内容绑定。
- **客户端验签**：规划在客户端安装前执行**签名验签**，在 sha256 完整性校验之外再确认来源可信。

在以上能力落地前，市场下发的脚本**仅有 sha256 完整性校验**，请**谨慎安装未签名 / 来源不明脚本**，
详见 [`README.md`](../README.md#compliance) 的「合规与使用边界声明」。
