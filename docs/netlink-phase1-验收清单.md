# ACRPA 多设备局域网互联（NetLink）Phase 1 — 双机人工验收清单

> 本清单面向 **两台真实 Windows 机器** 的**人工**验收，纯操作步骤，不含代码。
> 对应代码：`src/netlink/`（协议/连接/发现/服务/客户端/Agent/编排）、`src/netlink_window.py`（「设备互联」窗口）、
> 设置项见 `src/settings_window.py`（网络互联卡）、托盘开关见 `src/tray.py`、主窗口入口见 `src/ACRPA.py`。
>
> 自动验收请另行执行：`python tools/_test_netlink_e2e.py`（同机双节点 10 项断言）与
> `python tools/_verify_netlink_package.py`（打包完整性）。

## 0. 能力边界（务必先读，Phase 1 = 只读）

- **Phase 1 只能“看”**：可查看对端的 **运行进度 / 实时日志 / 定时任务摘要**。
- 「设备互联」窗口底部的四个操控按钮 **`[▶ 远程运行] [⏸ 暂停] [⏹ 停止] [推脚本]` 一律为灰色禁用**（提示「Phase 2 开放远程操控」）。
- 任何来自对端的远程控制指令（`CMD_RUN / CMD_PAUSE / CMD_RESUME / CMD_STOP / CMD_RUN_SCRIPT`）
  **都会被回 `CMD_ERR` 拒绝**，`reason = "netlink phase1: read-only"`，
  且 **绝不会改变本机正在执行的脚本状态**（不会误停/误暂停本机任务）。
- Phase 1 **不含**安全认证、TLS、审计日志（属 Phase 2/3），请仅在可信局域网内使用。

## 1. 前置准备

1. 两台 Windows 机器 **接入同一网段**（同一交换机 / 同一 VLAN / 可互 ping）。
2. 两台安装 **同版本** 的 ACRPA（比对各机根目录 `VERSION` 文件，内容一致）。
3. 记录两台机器的 IPv4 地址：命令行执行
   ```
   ipconfig
   ```
   记下各自的 `IPv4 地址`（下称 **A 机 IP**、**B 机 IP**）。
4. 确认两台可互通（在 A 机执行）：
   ```
   ping <B 机 IP>
   ```
5. 端口规划（默认即可，两机各自监听自己的 IP，端口号可以相同）：
   - 互联 **TCP** 端口：`19710`
   - 互联 **UDP 发现** 端口：`19711`

## 2. 需要修改的设置项（两台都要）

打开 ACRPA → **「设置」→ 左侧导航「🌐 网络互联」卡**（或托盘右键菜单「允许远程连接」快速开关）。

| 设置项 | 界面位置 | 取值建议 | 说明 |
| --- | --- | --- | --- |
| `netlink_enabled` | 「启用设备互联」勾选框 | **勾选** | 两台都必须勾选，否则本机不监听、也无法与对端互联 |
| `netlink_device_name` | 「设备名」输入框（留空自动取主机名） | 建议填好记的名字 | 用于在对端列表中辨认本机，如 `财务机-A` |
| `netlink_port` | 「互联 TCP 端口」 | `19710`（默认） | 本机 TCP 监听端口；对端「手动添加」时填写的是**本机这个端口** |
| `netlink_discovery_port` | 「互联发现端口」 | `19711`（默认） | UDP 广播收发端口，自动发现路径用 |
| `netlink_autodiscover` | 「UDP 自动发现」勾选框 | 自动发现路径**勾选**；降级路径**取消勾选** | 见下方场景 A / B |
| `netlink_static_peers` | 设置卡仅显示数量；**明细在「设备互联」窗口维护** | 降级路径需填 | 「手动添加」按 `对方IP:对方TCP端口` 写入，如 `192.168.1.23:19710` |

> 被控端（要被别人看的那台）与主控端（要去看别人的那台）在 Phase 1 是**对等**的：
> **两台都需要勾选「启用设备互联」**；要“看到对方”的一方，需要能到达对方（自动发现，或手动加入对方 `IP:端口`）。
> 改完设置后点击「应用」（或切换到「设备互联」窗口点「应用」），节点会 **自动重启** 使配置生效。

## 3. Windows 防火墙放行

### 3.1 首次监听的授权弹窗（推荐，最简单）
- 首次勾选「启用设备互联」并启动后，Windows 会弹出 **防火墙授权框**
  「是否允许 …（ACRPA）在此网络上通信」。
- **务必勾选「专用网络」**（公司/家庭内网），然后点「允许访问」。
- 若误点了「取消」，请用下面的 `netsh` 命令手动放行，或到
  「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」里重新勾选 ACRPA。

### 3.2 手动放行命令（管理员 CMD / PowerShell）
TCP 放行（互联监听端口）：
```
netsh advfirewall firewall add rule name="ACRPA NetLink TCP" dir=in action=allow protocol=TCP localport=19710
```
UDP 放行（自动发现端口）：
```
netsh advfirewall firewall add rule name="ACRPA NetLink UDP" dir=in action=allow protocol=UDP localport=19711
```
> 若在设置里改过端口，请把命令行里的端口号替换为实际值；**两台机器都要放行**。

删除规则（撤销时用）：
```
netsh advfirewall firewall delete rule name="ACRPA NetLink TCP"
netsh advfirewall firewall delete rule name="ACRPA NetLink UDP"
```

## 4. 场景 A：自动发现路径（两台都开自动发现）

**操作步骤**
1. A、B 两台均勾选「启用设备互联」+「UDP 自动发现」，TCP/UDP 端口保持默认（`19710` / `19711`），点「应用」。
2. 在 A 机主界面点 **「🌐 互联」** 按钮，打开「设备互联」窗口；B 机同样打开。
3. 等待。

**预期现象**
- **10 秒内**，两台「设备互联」窗口的**设备列表**中应出现**对方**一行
  （`ANNOUNCE` 广播周期为 5s，通常 5~10s 内可见；先显示设备名 + `IP:端口`）。
- 对方若正在跑脚本：状态列显示 **「● 运行」**（暂停时 **「⏸ 暂停」**），
  「当前脚本」「进度（`行/总行 · 循环`）」「延迟」列持续刷新；
  选中该设备后，下方进度条与「日志」面板同步显示对端日志。
- 底部状态行显示 `已就绪 | 设备 N / 在线 M`。

**常见失败现象与原因（自动发现）**
| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 列表始终为空，但两机能互 ping | **防火墙拦截 UDP**（`19711` 未放行） | 见第 3 节放行 UDP；或改用场景 B |
| 列表为空且本机状态显示「已停止」 | 本机 **`netlink_enabled` 未勾选** 或端口被占用（见下） | 勾选启用；检查端口占用 |
| 只在一侧出现对方 / 时有时无 | **VLAN 隔离 / 交换机禁用广播**（广播到不了对端） | 属网络环境限制，直接改用场景 B 手动添加 |

## 5. 场景 B：自动发现失败降级路径（手动添加 IP:端口）

**操作步骤**
1. A、B 两台均 **取消勾选「UDP 自动发现」**（保留「启用设备互联」），点「应用」。
2. 在 A 机「设备互联」窗口的 **「手动添加」** 输入框填写 **B 机 IP : B 机 TCP 端口**，例如 `192.168.1.23:19710`：
   - 点 **「添加」** → 底部提示 `已添加 192.168.1.23:19710，点应用生效`；
   - 再点 **「应用」** → 保存配置并 **重启节点**。
3. 在 B 机同样操作，手动添加 **A 机 IP : A 机 TCP 端口**（例如 `192.168.1.22:19710`），「添加」→「应用」。

**预期现象**
- 应用后 **数秒内**（最长约 6 秒，出站连接重连间隔 3 秒），「设备互联」窗口设备列表出现对方。
- 状态 / 进度 / 日志面板与场景 A 表现一致（订阅后对端会**立即推送**一次当前状态，无需等待）。
- 若先只配一侧：A 添加了 B 并应用，则 **A 能看到 B**（A 主动连 B）；要让 B 也看到 A，需在 B 侧也添加 A。

**常见失败现象与原因（手动添加）**
| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 添加后列表仍无对方，对方端口无响应 | 输入 **端口写错**（应填对方 TCP 端口 `19710`，而非发现端口 `19711`）或 **IP 写错** | 用 `ipconfig` 核对 IP，用 `netstat -ano \| findstr 19710` 确认对方在监听 |
| 列表出现对方但很快变「离线」 | **防火墙拦截 TCP**（`19710` 未放行） | 见第 3.2 节放行 TCP，重试（连接会 3 秒自动重连） |
| 一侧可用、另一侧始终连不上 | **单向路由此可达**（ACL / 子网掩码错误 / 跨 VLAN 未放行） | 在“连不上”的那台 `ping`、`telnet 对方IP 19710` 逐跳排查 |

## 6. 三类典型故障总览（贯穿全流程）

| # | 失败现象 | 根因 | 快速定位 |
| --- | --- | --- | --- |
| 1 | 本机「设备互联」显示「已停止」，或窗口反复无法启动；日志报端口绑定失败 | **TCP 端口被占用**（`19710` 已被其它程序占用） | 命令行 `netstat -ano \| findstr 19710` 找到占用 PID；改 `netlink_port` 为其它空闲端口（两台可不同），或结束占用进程 |
| 2 | 两机能 ping，但自动发现列表一直为空 | **防火墙拦截 UDP**（`19711`），广播包进不来 | 第 3 节放行 UDP；或改用手动添加（TCP 路径） |
| 3 | 同网段但两台互相看不到（手动 TCP 也连不上），`ping` 通 | **VLAN 隔离 / 交换机禁止广播 / 三层 ACL** | 确认两机在同一 VLAN；请网络管理员放行两机之间 TCP `19710`；必要时改用允许互通的网段 |

> 补充：若两台机器 **设备名相同**，列表中可能不易区分，建议在第 2 节为两台分别设置可辨识的「设备名」。

## 7. Phase 1 能力边界复述（验收结论必写）

- ✅ 能看到对端：**运行/暂停状态、当前脚本名、进度（行/总行、循环）、暂停位、实时日志、定时任务摘要**。
- ⛔ 不能控制对端：四个操控按钮 **灰色禁用**；对端发来的任何 `CMD_*` **一律回 `CMD_ERR`（reason 非空）**，

- ⛔ 本阶段无认证 / 无加密 / 无审计；请仅在可信内网使用。
