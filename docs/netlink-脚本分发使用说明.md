# ACRPA 设备互联 — 脚本分发使用说明（NetLink Phase 3-2）

本文面向最终用户，说明在「设备互联」窗口中使用**脚本分发**（推送脚本到被控端并
可立即运行、**批量下发**、「远端脚本」列表与远程运行）的前提条件、交互流程、落盘
位置、完整性校验机制与常见故障排查。

> 适用范围：NetLink Phase 3-2。已开放脚本推送（`[推脚本]`，支持**多选批量下发**）、
> 传输进度列表（「传输」区，含**远端拒绝的红色可见性**）与「远端脚本」对话框
> （`[📂 远端脚本]`），并在设备详情区展示**远端定时任务状态**。
> TLS 加密、远程截图、浏览器面板仍属后续阶段（Phase 4），尚未开放。

---

## 1. 前置条件（被控端必须先授权）

脚本分发方向为「**控制端 → 被控端**」，被控端是实际接收并落盘脚本的一方。使用前必须满足：

1. 双方都打开「设备互联」窗口并点 **启动互联**（状态条出现 `● 运行中`）；
2. 双方完成**配对**（见 `docs/netlink-配对与权限说明.md`）；
3. **被控端**在「已配对设备（本机授予的远程权限）」中，把**控制端**的权限设为
   **允许接收脚本（`script`）**。这是脚本分发的**硬门槛**：
   * 权限为 **仅观察（`observe`）** 或 **允许操控（`control`）** 时，
     控制端的 `[推脚本]` 与 `[📂 远端脚本]` 按钮保持**灰色禁用**；
   * 悬停按钮会显示原因，例如 `需「允许接收脚本」权限（当前：允许操控）`；
   * 即使绕过 UI 强行下发分块，被控端也会以 `permission denied` 拒绝。

权限判定由被控端在**收到每个分块/请求时实时查询**，因此修改权限**即时生效**，
无需重启互联或重新配对。

## 2. 推送流程（控制端）

被控端授权「允许接收脚本」后，控制端在选中该设备时：

1. 点 **`[推脚本]`** → 弹出文件选择框，筛选 `脚本文件`（`*.xls *.xlsx *.json`），
   默认打开本机**脚本目录**（`<脚本目录>`，见第 3 节）；
2. 选择本地脚本文件（用户取消则直接返回，不提示）；
3. 控制端本地先做**前置校验**（不满足则状态行 + 弹窗提示，不发起传输）：
   * 扩展名须为 `.xls / .xlsx / .json`，否则提示 `不支持的扩展名`；
   * 文件必须存在，否则提示 `文件不存在`；
   * 文件大小须 **≤ 32 MB**，否则提示 `文件过大（上限 32 MB）`；
4. 弹出**「推送脚本」小对话框**（自绘，非系统输入框），包含两个字段：
   * **源文件**：只读展示所选本地文件名；
   * **远端文件名**：默认取本地文件名（`basename`），可编辑。命名须满足
     `is_valid_script_name`，**不得含路径分隔符**，且**不接受**以 `received/` 开头
     （服务端会自动把文件放入 `received/` 子目录）；
   * 复选 **`传输完成后立即运行`**：默认**勾选**。勾选时，被控端落盘校验通过后
     会**自动尝试运行**该脚本；不勾选则仅落盘；
5. 点 **`[开始传输]`** → 控制端向该设备发起分块传输：
   * 若当前没有到该设备的可用连接，状态行提示 `未找到到该设备的连接`，不新增传输行；
   * 否则状态行提示 `开始推送 <远端文件名> …`，并在「传输」区新增一行 `进行中`。

### 2.1 批量下发（多选设备）

设备表**支持多选**（`Ctrl/Shift + 单击`，或直接框选多行）：

1. 选中**一台或多台**设备（多选时详情区显示 `已选中 N 台设备`）；
2. 点 **`[推脚本]`** —— 只要选中集合中**至少一台**已认证且权限为「允许接收脚本」，
   按钮即可用；权限不足的设备会在本次批量中**自动跳过**，**不阻止**其余设备；
3. 文件选择与「远端文件名 / 传输后立即运行」对话框与单选流程一致；
4. **多选（≥2 台）**时，点 `[开始传输]` 后会再弹一次确认框
   `将向 N 台设备推送「<文件名>」。确定开始批量传输？`（`N` 为**可推送设备数**）；
   **单选**沿用原有对话框即确认的交互，不再附加确认框（保持既有单设备体验不变）；
5. 确认后**串行**逐台发起（避免同时灌满多个连接的发送队列），每台各自在后台
   daemon 线程里发送，互不影响：
   * 每台成功发起的设备在「传输」区各生成一行，按各自 `tid` 独立更新；
   * 被跳过的设备在「传输」区各生成一行 `失败：<原因>`（红色），并在底部状态行
     汇总 `跳过 M 台：<设备>（<原因>）…`。

**`skip` 语义**：`push_script_many(node, peer_node_ids, local_path, remote_name, run)`
返回 `{"ok": {peer: tid}, "skip": {peer: <原因>}}`，仅在以下情况把设备放入 `skip`
（不进 `ok`）：

| 情况 | `skip` 原因 |
| --- | --- |
| 该设备当前**没有存活连接** | `no connection` |
| **本地源文件**缺失 / 空文件 / 超 32 MB / 扩展名非法 | `local file missing` / `local file empty` / `file too large` / `invalid script name` |

> 注意：本地源文件校验**一次失败即对全部目标统一 `skip`**（不重复读盘）。
> 若设备**连接存活**但**被控端权限不足**，该设备仍会被**发起**（进入 `ok`）；其拒绝
> **异步**发生，控制端随后在「传输」区看到该设备的 `失败：permission denied`
> （见 6.1）。也就是说 `ok` 只代表「**已成功发起**」，**不代表对端已接收**。

**扇出独立性**：一次批量中任何一台失败（连接缺失 / 权限拒绝 / 校验失败 / 中断）都
**不影响**其余设备——各设备使用独立 `tid` 与独立后台线程，进度与终态互不干扰。

**同名覆盖**：落盘时为 `os.replace` **原子覆盖**（回执 `detail` 带 `(overwritten)`）。
批量下发到多台时，各被控端各自独立覆盖自己 `received/` 下的同名文件。

## 3. 落盘位置与覆盖策略（被控端）

* 被控端把收到的脚本落盘到 **`<脚本目录>/received/`**：
  * `<脚本目录>` 即配置键 `netlink_script_dir`；**为空时**默认为
    **`<程序目录>/scripts`**；
  * 接收子目录固定为 `received`，不存在时自动创建；
  * 因此远端脚本的相对名形如 `received/<文件名>`。
* **同名覆盖策略**：若 `received/<文件名>` 已存在，落盘时直接**覆盖**（使用
  `os.replace` 原子替换），成功回执的 `detail` 会带上 `(overwritten)` 标记；
* 传输过程中的半成品先写为临时文件 `received/.tmp_<tid>.part`，**仅在完整性校验
  通过后**才移入正式文件名；任何失败/中断都会删除临时文件，**不留残 file**。

> 提示：被控端「允许接收脚本」的设备，其 `[📂 远端脚本]` 列表会把这两处都列出来：
> 脚本目录下的文件标记为 `脚本目录`，`received/` 下的文件标记为 `已接收`。

## 4. 完整性校验（64KB 分块 + 双重重校验）

传输采用「分块 + 首尾声明」的 JSON 帧（每块原始 **64 KB**，base64 承载），被控端逐块
校验、落盘，并在结束帧做**双重校验**：

1. **分块序号**：每块携带递增 `seq`，必须严格连续（`0,1,2,…`），乱序即
   `chunk out of order` 并拒绝；
2. **结束帧 sha256 与大小双重校验**：
   * 结束帧声明整体 `sha256` 与分块总数；
   * 被控端对临时文件重新计算 sha256，须与**首帧声明的 sha256**、**结束帧声明的
     sha256**、以及**累计字节数==声明大小**三者同时一致；
   * 任一不匹配即 `checksum mismatch` / `size mismatch`，**拒绝落盘且删除临时文件**，
     **不留任何残 file**。

## 5. 「远端脚本」列表与远程运行

* 控制端选中已授权设备后点 **`[📂 远端脚本]`**，向被控端请求脚本列表；失败时状态行
  提示 `无法请求远端脚本列表`；
* 列表以独立对话框（约 `620x460`）展示，列：**名称 / 大小 / 修改时间 / 位置**：
  * `位置` 为 **`脚本目录`**（脚本根下）或 **`已接收`**（`received/` 下）；
  * `received/` 前缀的条目在名称列**保留** `received/` 相对名；
  * 顶部显示 `设备：<设备名> · 目录：<被控端脚本目录名>`（被控端未提供目录名时省略）；
  * 空列表显示灰字 `远端无可用脚本`；
* 选中一条后点 **`[▶ 远程运行选中]`**（或双击该行）：
  * 会先弹**二次确认**（文案含脚本名）；
  * 确认后向被控端下发 `CMD_RUN_SCRIPT`（`name` 为相对名，如
    `received/a.xls` 或 `b.xls`）；
  * **运行结果**在父窗口的「远程指令」列表中体现（与远程运行/暂停/停止一致，
    显示「已受理 → 成功/失败」）；
* 对话框底部另有 **`[刷新]`**（重新请求列表）与 **`[关闭]`**；
* 关闭对话框**不会**取消任何订阅；再次点 `[📂 远端脚本]` 即重新请求即可。
  同一设备在对话框打开期间又收到新列表事件时，对话框内容会**自动刷新**（并按 `name`
  恢复原选中行）。

## 6. 「传输」区（进度展示）

「设备互联」窗口的「传输」区（位于「远程指令」上方）展示本机相关的传输进度，列：
**设备 / 文件 / 进度 / 状态**：

| 状态 | 颜色 | 含义 |
| --- | --- | --- |
| **传输中** | 蓝 | 正在发送/接收；进度列显示 `sent/total (百分比%)`（`total≤0` 显示 `—`） |
| **成功** | 绿 | 传输完成；附加 `detail`（如 `received/a.xls`，截断 80 字） |
| **失败：……** | 红 | 传输失败；冒号后为原因（如 `checksum mismatch`） |

* 每行按传输 `tid` 合并，发送与接收两侧事件都会显示在同一行；
* 列表**最多保留 50 行**，超出时删除最旧一行；
* 空列表显示灰字 `暂无传输`；
* 底部状态行会显示最新传输摘要，例如 `OFFICE-01 推送 a.xls 成功`；失败时以
  **警示配色**显示。

### 6.1 远端拒绝在控制端「传输」列表可见（红色）

被控端**拒绝**传输（如 `permission denied` / `checksum mismatch` / `file too large` /
`chunk out of order`）时，除了给发起方回 `CMD_ACK(failed)` 与 `CMD_ERR` 之外，
两条回执都会**携带该次传输的 `tid`**。控制端据此把远端拒绝**归并到「传输」区已有的
那一行**，显示为红色的 `失败：<原因>`（原因与远端**完全一致**）。

因此在控制端，「对端为什么没收下」**始终可见**，不再只有控制端本地失败
（如本地文件不存在 `local file missing`）才能看到。若极少数情况下事件不带 `tid`，
则**新增一行** `失败：<原因>` 以保证信息不丢失。

## 7. 定时任务状态展示（设备详情区）

选中一台设备后，详情区（进度条下方）新增一行**只读**文本：

`定时任务：<启用|未启用> · 下次运行 <next_run 或 "未安排"/"—"> （N 个任务）`

* 数据来自被控端 Agent 推送的 `TOPIC_PEER_SCHED`（主题名 `netlink.peer_sched`）；
  该推送为**变化驱动**（`SCHED_*` 变化时推送），且**订阅后会立即收到一次初始快照**；
* 展示规则：
  * **无数据**（尚未收到该设备的计划任务快照）→ `定时任务：—`；
  * **启用**且 `next_run` 非空 → `定时任务：启用 · 下次运行 09:30 （3 个任务）`；
  * **启用**但 `next_run` 为空 → `定时任务：启用 · 下次运行 未安排 （N 个任务）`；
  * **未启用** → `定时任务：未启用 · 下次运行 — （N 个任务）`；
* 该行**只读展示**，不提供任何开关；任务的增删改仍在本机「计划任务」中完成；
* 多选设备时详情区显示 `已选中 N 台设备`，该行显示**主选中**设备的计划任务状态。

## 8. 限制

1. **单文件上限 32 MB**，超出即拒（`file too large`）；
2. **允许的扩展名**：`.xls / .xlsx / .json`；
3. **文件名不得含路径分隔符**（`/` `\`）或 `..`；不支持任何目录穿越；
4. 「远端脚本」列表**只列这两处**（脚本根 + `received/`），最多 500 条；
5. **链路仍为明文**：TLS 属 Phase 4，当前仅可在**可信内网**使用。

## 9. 故障排查（5 条）

### 9.1 `permission denied`（权限不足）

**现象**：传输行显示 `失败：permission denied`，或按钮始终灰色。

**处理**：确认**被控端**「已配对设备」中该控制端的权限是否为 **「允许接收脚本」**。
选中有权限需求的行 → 下拉框调到「允许接收脚本」→ 点 **应用**（即时生效）。
若按钮灰色，悬停查看具体原因（`互联未启动` / `未认证` /
`需「允许接收脚本」权限（当前：<权限名>）`）。

### 9.2 `file too large`

**现象**：传输行显示 `失败：file too large`；或本地校验即提示 `文件过大（上限 32 MB）`。

**处理**：脚本单文件上限 **32 MB**。请拆分脚本或压缩数据后重试。

### 9.3 `checksum mismatch`（链路异常 / 被截断）

**现象**：传输行显示 `失败：checksum mismatch`，被控端 `received/` 下**没有**该文件。

**处理**：说明分块数据在链路中被损坏或被截断（也可能是源文件在传输途中被修改）。
请确认网络稳定后**重试**；被控端已自动清理临时文件，不会留残 file。

### 9.4 `chunk out of order`

**现象**：传输行显示 `失败：chunk out of order`。

**处理**：分块序号不连续（乱序或丢失）。通常由链路抖动/拥塞或并发使用同一连接导致。
请稍后重试；避免在同一设备上同时发起多个传输。

### 9.5 `duplicate transfer`（同一传输重复发起）

**现象**：传输行显示 `失败：duplicate transfer`。

**处理**：同一个传输 `tid` 被重复发起（重复点按或重放）。请稍候再试；若反复出现，
关闭对话框/取消操作后重新从 `[推脚本]` 发起一次全新传输。
