# ACRPA 设备互联 — 远程操控使用说明（NetLink Phase 2-2b）

本文面向最终用户，说明在「设备互联」窗口中使用**远程操控**（远程运行 / 暂停 / 恢复 /
停止）的前提条件、交互方式、指令结果含义、审计入口与常见故障排查。

> 适用范围：NetLink Phase 2-2b。已开放远程运行 / 暂停 / 恢复 / 停止；
> **脚本分发（推送 / 远端脚本列表 / 远程运行远端脚本）已在 Phase 3-1b 实现**，
> 详见 `docs/netlink-脚本分发使用说明.md`。

---

## 1. 前置条件（被控端必须先授权）

远程操控方向为「**控制端 → 被控端**」，被控端是实际执行脚本的一方。使用前必须满足：

1. 双方都打开「设备互联」窗口并点 **启动互联**（状态条出现 `● 运行中`）。
2. 双方完成**配对**（见 `docs/netlink-配对与权限说明.md`）。
3. **被控端**在「已配对设备（本机授予的远程权限）」中，把**控制端**的权限设为：
   * **允许操控（`control`）**：可远程运行 / 暂停 / 恢复 / 停止；
   * **允许接收脚本（`script`）**：在 `control` 基础上额外允许脚本推送与远端脚本列表
     （已实现，详见 `docs/netlink-脚本分发使用说明.md`）。
4. 权限为默认的 **仅观察（`observe`）** 时，控制端的三个操控按钮保持灰色禁用；
   即使强行下发指令，被控端也会返回 `permission denied`。

权限判定由被控端在**收到每条指令时实时查询**当前权限，因此修改权限**即时生效**，
无需重启互联或重新配对。

## 2. 四个按钮：行为与前置条件

被控端授权「允许操控」后，控制端「设备互联」窗口底部的操控按钮如下：

| 按钮 | 行为 | 启用条件 | 备注 |
| --- | --- | --- | --- |
| **`[▶ 远程运行]`** | 二次确认后下发 `CMD_RUN`，让被控端**运行其当前已加载的脚本** | 互联运行中 + 选中设备已认证 + 权限达 `control` | 首次操控会在被控端弹窗确认（见第 3 节） |
| **`[⏸ 暂停]` / `[▶ 恢复]`** | **同一按钮**，按被控端当前 `paused` 状态自动切换文案：暂停中显示 `[▶ 恢复]` 并发 `CMD_RESUME`；否则显示 `[⏸ 暂停]` 并发 `CMD_PAUSE` | 上述条件 **且** 被控端设备处于运行中 | 被控端设备未运行（`running` 为假）时禁用 |
| **`[⏹ 停止]`** | 二次确认后下发 `CMD_STOP`，停止被控端当前正在运行的脚本 | 上述条件 **且** 被控端设备正在运行或处于暂停 | 被控端未运行且非暂停时禁用 |
| **`[推脚本]`** | 弹出文件选择与「推送脚本」小对话框，把本地脚本推送到被控端（可选传输后立即运行） | 互联运行中 + 选中设备已认证 + 权限达 **`script`** | 详见 `docs/netlink-脚本分发使用说明.md` |

按钮不可用时，把鼠标悬停其上会显示具体原因：

* `互联未启动` —— 本机尚未启动互联；
* `未认证` —— 选中的设备尚未完成配对认证；
* `权限不足（当前：仅观察）` —— 选中设备已认证但权限不够；
* `设备未运行` —— 暂停 / 停止按钮专属：目标设备当前没有在跑脚本。

> 说明：暂停 / 恢复按钮的文案与发送类型，依赖控制端最近一次收到的该设备运行状态
> （`TOPIC_PEER_STATE`）。若状态尚未刷新，请稍候片刻再看按钮文案。

## 3. 被控端首次确认弹窗（“记住此设备”的落点）

为防止被他人暗中操控，**被控端第一次**收到某台设备的操控指令时会弹出确认对话框
「远程操控请求」，内容包含：设备、指令、来源地址，以及：

* **允许** —— 仅放行本次指令，下次仍会弹窗；
* **允许并记住此设备** —— 放行本次，并把该设备**指纹**写入配置键
  `netlink_confirmed_peers`，此后同一设备的操控不再弹窗；
* **拒绝** —— 拒绝本次（控制端会收到 `user rejected`）；
* 对话框显示 `N 秒后自动拒绝` 倒计时，**30 秒**无操作按拒绝处理（控制端收到
  `confirm timeout`）。

「记住此设备」的落点：配置文件 `config.json` 中的 `netlink_confirmed_peers`（数组，
元素为设备指纹）。如需取消“记住”，可在 `config.json` 中清空该数组或删除对应指纹后
重启程序（当前版本设置界面尚未提供清空按钮）。

> 该确认行为受配置项 `netlink_confirm_control` 控制：设为 `false` 时**不弹窗**、
> 直接放行（仅建议在完全可信的内网临时开启）。

## 4. 指令结果：三种状态的含义

控制端「远程指令」列表（位于操控按钮下方）会逐条显示指令结果，列结构为
`时间 / 设备 / 指令 / 结果`，最新指令显示在最上方，最多保留 100 行。

| 显示 | 含义 | 说明 |
| --- | --- | --- |
| **已受理**（灰） | 被控端**已收到并排队**该指令 | 仅表示指令已被接受，**尚未执行** |
| **成功**（绿） | 被控端**已执行完成** | 附带的 `detail`（如 `mode=script`）会追加显示（截断 120 字） |
| **失败：……**（红） | 被控端**拒绝或执行失败** | 冒号后为原因（如 `permission denied`、`already running`） |

> **重要：`已受理 ≠ 已执行完成`。** 「已受理」只是被控端在同步校验通过后的第一份回执，
> 真正结果由随后的「成功 / 失败」终态覆盖显示。同一条指令的「已受理」与其终态会更新
> **同一行**（按 `指令 + 设备` 匹配最近一条未终态的行），因此看到「已受理」后请稍候，
> 该行会变为「成功」或「失败：……」。
>
> 底部状态行还会显示最新一条指令的摘要，例如 `OFFICE-01 远程运行 成功`。

## 5. 审计日志

被控端会把每一条远程操控指令落盘为单行记录，供事后追责：

* **文件位置**：`logs/netlink_audit_YYYYMMDD.log`（按天轮转，UTF-8）；
* **单行格式**：`[时间] actor=<设备名|指纹前8位> remote=<ip:port> cmd=<指令> args=<json> result=<ok|err|rejected> detail=<文本>`；
* **保留天数**：配置键 `netlink_audit_days`；当其为 `0` 时**跟随** `log_retention_days`
  （默认 7 天），超期文件自动删除；
* **查看入口**：在「设备互联」窗口底部点击 **`[📜 审计日志]`**，弹出只读窗口
  （约 760x520），显示最近 300 行（最新在底部）、当前审计文件路径，并提供 `[刷新]` /
  `[关闭]` 按钮；
* 该窗口**只读展示，不提供清空/删除功能**；
* 互联未启动、无节点或读取失败时，会提示「审计日志不可用」，不会影响主程序。

## 6. 重要限制（务必了解）

1. **远程运行的是“被控端本地已加载的脚本”**。
   `CMD_RUN` 不会更换脚本，只是让被控端运行它**当前已加载**的那一个脚本；
   要更换脚本，请使用已实现的**脚本推送**能力（`[推脚本]`），
   详见 `docs/netlink-脚本分发使用说明.md`。
2. **工作流与脚本的暂停/恢复机制不同**，本实现已自动分叉：
   * 若被控端正在跑**工作流**，暂停 / 恢复作用于工作流引擎；
   * 否则作用于**脚本**（`state.pause_event`）。
   两者互不相通，控制端无需关心，被控端会自动选择正确的路径。
3. **录制中不可暂停**：被控端正在录制时，远程暂停 / 恢复会被拒（`recording in progress`）。
4. **链路仍为明文**：TLS 属于 Phase 4，当前仅可在**可信内网**使用。

## 7. 故障排查（4 条）

### 7.1 权限不足（`permission denied`）

**现象**：控制端「远程指令」列表显示 `失败：permission denied: need control`。

**处理**：确认**被控端**「已配对设备」中该控制端的权限是否为「允许操控」或
「允许接收脚本」。选中有权限需求的行 → 下拉框上调 → 点 **应用**（即时生效）。

### 7.2 目标已在运行（`already running`）

**现象**：点 `[▶ 远程运行]` 后显示 `失败：already running`。

**处理**：被控端设备当前已处于运行态。先点 `[⏹ 停止]` 停止，或改用
`[⏸ 暂停]` / `[▶ 恢复]`。注意窗口的设备状态列可帮助判断是否正在运行。

### 7.3 录制中不可远程暂停（`recording in progress`）

**现象**：点 `[⏸ 暂停]` / `[▶ 恢复]` 后显示 `失败：recording in progress`。

**处理**：被控端正在录制操作，暂停 / 恢复不适用。请等待录制结束，或在被控端本地停止录制。

### 7.4 被控端拒绝或确认超时（`user rejected` / `confirm timeout`）

**现象**：控制端显示 `失败：user rejected` 或 `失败：confirm timeout`。

**处理**：

* `user rejected` —— 被控端在首次确认弹窗中点了「拒绝」，或关闭了弹窗；
* `confirm timeout` —— 被控端 30 秒内未响应确认弹窗，自动按拒绝处理。
* 若希望长期免确认，请让被控端在弹窗中点「**允许并记住此设备**」（落点为
  `netlink_confirmed_peers`）；或由被控端确认 `netlink_confirm_control` 的取值是否符合预期。
