# ACRPA 设备互联 — 配对与权限说明（NetLink Phase 2-1 / 2-2）

本文面向最终用户，说明 ACRPA「设备互联」功能中**配对码**、**权限分级**、**撤销**
与**远程操控**的使用方式与安全边界。适用版本：NetLink Phase 2-2b（**已开放远程操控**：
远程运行 / 暂停 / 恢复 / 停止；**推脚本**为 Phase 3，暂未开放）。

---

## 1. 三种权限：能做什么、不能做什么

被控端（提供查看/被操作的一端）为每一台已配对设备单独授予一个权限，共三档：

| 权限 | 中文标签 | 能做什么 | 不能做什么 |
| --- | --- | --- | --- |
| `observe` | 仅观察 | 只读查看被控端的运行状态、当前脚本与进度、日志、定时状态 | 不能发送任何运行/暂停/停止指令，不能推送脚本 |
| `control` | 允许操控 | 在「仅观察」基础上，可对被控端发起运行 / 暂停 / 恢复 / 停止等操控指令 | 不能推送或接收脚本文件 |
| `script` | 允许接收脚本 | 在 `control` 基础上，可接收被控端推送的脚本文件（脚本清单与二进制分块传输） | 不能越过被控端的其它安全设置 |

说明：

* 权限是**被控端授予远程设备**的权限，方向为「远程设备 → 本机」。
* 新配对成功的设备，默认权限为 **仅观察（observe）**，需要被控端手动上调。
* **远程操控已实现（Phase 2-2b）**：只有被控端把该设备权限设为 **「允许操控」（control）**
  或 **「允许接收脚本」（script）**，控制端的 **▶ 远程运行 / ⏸ 暂停 / ⏹ 停止**
  按钮才会由灰变亮并可下发指令；权限为「仅观察」时按钮保持灰色禁用，即使强行下发，
  被控端也会回 `permission denied`。
* **推脚本** 按钮仍为灰色禁用（Phase 3 开放，悬停提示「Phase 3 开放脚本推送」）。
* **首次操控需在被控端确认**：控制端第一次下发操控指令时，被控端会弹出确认对话框，
  可点「允许」「允许并记住此设备」或「拒绝」（30 秒无操作按拒绝处理）。
  勾选「允许并记住此设备」后，该设备的指纹写入 `netlink_confirmed_peers`，
  后续操控不再弹窗；可在「设置 → 网络互联」中清空该列表。
* **网页面板本地控制（Phase 4-2 演进，独立门）**：除上述「远程设备 → 本机」的权限外，
  还有一种**本机所有者自己使用**的控制入口——浏览器网页面板的「有限控制」。它**不经过**
  白名单/权限等级，而走**独立的三层门**：
  1. **L1 面板令牌**（读，同只读面板）；
  2. **L3 强制 HTTPS**（证书不可用则**拒绝启用**，绝不回落明文）；
  3. **L2 控制 PIN 解锁的短期会话** + 控制请求头 `X-NL-CSRF`（CSRF 令牌只存前端 JS 内存）。
  白名单**仅** `run`（运行当前已加载脚本）/ `stop`（停止当前运行）；`pause`/`resume`、
  推脚本与截图**不开放**（返回 `action not allowed`）。
* **免受「首次操控确认」门控（可配置）**：本面板控制**默认不弹**桌面二次确认
  （PIN 即视为本机所有者授权），对应键 `netlink_web_confirm_control`（默认 `false`）；
  置为 `true` 时保留与远程一致的桌面确认弹窗。本面板控制**不读写**
  `netlink_confirmed_peers`（那是远端设备指纹集合），避免语义混淆。

## 2. 首次配对流程

配对需要「被控端」与「控制端」双方配合，配对码（6 位数字 PIN）始终由被控端生成。

### 2.1 被控端：生成配对码

1. 打开「设备互联」窗口，点击顶部 **启动互联**（状态条出现 `● 运行中`）。
2. 点击顶部 **配对码** 按钮，弹出配对码对话框：
   * 对话框顶部说明：`其它设备在本窗口输入此配对码即可连接（默认获得「仅观察」权限）`；
   * 中间以大号字体显示 6 位 PIN（每位之间以空格分隔，便于朗读），例如 `1 2 3 4 5 6`；
   * 下方显示 `剩余 mm:ss` 倒计时。
3. 点击 **生成/重新生成** 生成一个新的 PIN，把它**口头或当面**告知控制端使用者。
4. 需要时点击 **关闭配对** 使当前 PIN 立刻失效；点 **关闭窗口** 只关闭对话框，
   不影响已开启的配对窗口（PIN 仍在有效期内）。

### 2.2 控制端：选中设备并配对

1. 打开「设备互联」窗口并**启动互联**。
2. 在设备列表中找到目标设备（自动发现或「手动添加」`IP:端口` 后点应用）。
3. 选中该设备行（此时设备详情区的 **🔗 配对** 按钮可用；未认证设备权限列显示 `未认证`）。
4. 点击 **🔗 配对**，在弹窗中输入对方告知的 **6 位数字** 配对码。
   * 非 6 位纯数字会在底部状态行提示 `配对码为 6 位数字`，不会继续。
5. 确认后底部状态行显示 `已发起配对…`，配对结果异步返回：
   * 成功：状态行显示 `配对成功：<设备名>（<权限>）`，该设备权限列显示实际权限；
   * 失败：状态行以告警配色显示 `配对失败：<设备名> — <原因>`。

配对成功后，双方会把对方的凭据 token 写入 **Windows 凭据库**（见第 4 节），
被控端同时把该设备加入白名单。

## 3. 免配对重连 与 权限撤销

### 3.1 免配对重连（Windows 凭据库记忆）

首次配对成功后，token 已安全保存在 Windows 凭据库中（target 形如
`ACRPA/netlink/peer/<设备指纹>`）。此后同一设备再次连接时，会自动走 `resume` 流程，
**无需再次输入配对码**。

### 3.2 撤销位置（被控端「已配对设备」）

被控端可在「设备互联」窗口下半部分的 **已配对设备（本机授予的远程权限）** 区域管理白名单：

* 列表列：`设备名 / 指纹 / 权限 / 最近连接`（最近连接为 `HH:MM:SS`，从无连接显示 `—`）。
* 选中一行 → 在下方下拉框选择 `仅观察 / 允许操控 / 允许接收脚本` → 点 **应用** 修改权限。
* 选中一行 → 点 **移除** → 在确认对话框中确认（对话框会显示设备名与指纹前 8 位）→
  该设备从白名单删除，其凭据库 token 一并清除，之后需**重新配对**才能再次连接。
* 列表为空时显示灰字 `暂无已配对设备`；互联未启动时该区域整体禁用。

## 4. 权限变更即时生效

被控端在「已配对设备」区域修改某设备权限并点 **应用** 后，**无需重启互联、无需重新配对**，
该设备**下一次指令即按新权限判定**：

* 从「仅观察」上调到「允许操控」后，对方随后的操控指令立刻通过权限门槛；
* 从「允许操控」下调到「仅观察」后，对方随后的操控指令立刻被拒（返回 `permission denied`）。

判定由被控端在收到每条消息时实时查询当前权限完成，不缓存到连接建立时刻。

## 5. 安全边界与限制

1. **配对码有效期**：PIN 有有效期（默认 600 秒，可在「设置 → 网络互联 → 配对码有效期(秒)」
   调整）。倒计时归零后对话框显示 `已过期，请重新生成` 并置灰 PIN，旧码立即失效。
2. **连续错误锁定连接**：同一连接连续输错 **5 次** 配对码后，被控端会**主动关闭该连接**，
   需重新建立连接。
3. **密钥只进凭据库**：PIN 从不明文上网（PIN 与 salt 经 PBKDF2-HMAC-SHA256 派生 token，
   线路只传挑战与证明），token/proof/salt **只写入 Windows 凭据库，绝不写入 `config.json`**。
4. **远程操控（Phase 2-2b）**：被控端授予「允许操控」后，控制端可远程运行 / 暂停 /
   恢复 / 停止被控端**当前已加载的脚本**；首次操控会在被控端弹窗确认，可勾选
   「允许并记住此设备」。脚本推送 `SCRIPT_*` 仍属 Phase 3，暂未开放，`推脚本` 按钮
   保持灰色禁用。详见 `docs/netlink-远程操控使用说明.md`。
5. **TLS 尚未实现**：当前链路为**明文**（仅认证与权限分级），仅可在**可信内网**使用；
   请勿在不可信网络或跨公网环境开启互联。
6. **关闭配对的代价**：在「设置 → 网络互联」中关闭「启用配对认证」后，同网段任意设备
   都可免配对读取本机运行状态与日志（只读）。关闭时界面会显示红色告警文字，请谨慎操作。

## 6. 故障排查

### 6.1 配对码过期

**现象**：控制端输入配对码后配对失败；被控端配对码对话框显示 `已过期，请重新生成`。

**处理**：在被控端重新点击 **生成/重新生成** 得到新 PIN，再让控制端重试。
如需更长的有效期，调大「设置 → 网络互联 → 配对码有效期(秒)」。

### 6.2 权限不足（`permission denied`）

**现象**：控制端发起的某个操作被拒，被控端返回 `permission denied`。

**处理**：确认被控端「已配对设备」中该设备的权限是否达到所需档位
（只读需 `observe`，操控需 `control`，脚本需 `script`）。选中有权限需求的行 →
下拉框上调 → 点 **应用**（即时生效，无需重启）。

### 6.3 凭据库写入失败（`secret_stored:false`）

**现象**：配对返回结果中 `secret_stored` 为 `false`（凭据未能写入 Windows 凭据库），
此时本次连接可用，但**下次连接无法免配对重连**。

**处理**：在被控端「已配对设备」中 **移除** 该设备（清除残留），确认系统凭据库可写
（非受限账户、凭据管理器未被策略禁用）后，**重新配对**一次。
