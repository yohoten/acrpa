# ACRPA v0.1.26

> 本文件可直接作为 GitHub Release 正文。打包完成后执行
> `python tools/make_release.py` 会依据实际产物重新生成本文件并回填真实 sha256 与体积。

## 本版更新

**更新机制重构**，以及一处影响所有打包版本的版本号失真修复。

- 新增应用内更新窗口：状态栏「新版本 vX.Y.Z 可用 — 点击更新」→ 查看更新内容 → 下载（显示进度与体积）→ 自动校验 sha256、体积与 ZIP 格式 → 一键重启更新。
- 便携版一键自更新：程序退出后由独立助手校验包内版本号，并以 `.new` 文件中转原子替换主程序与 `VERSION`，随后自动重启。只替换主程序，配置、脚本、模板、日志一律不动。
- **修复打包后版本号失真**：此前版本号只从项目根目录读取，打包成 EXE 后必然读不到而回退到内置值，导致「关于」页与更新判断永远停留在旧版本。现按 `EXE 同级目录 → 内嵌副本 → 项目根目录` 依次查找，并让打包过程带上 `VERSION` 文件。
- **检查更新多源降级**：GitHub Releases API → raw.githubusercontent → jsDelivr → Gitee，任一可用即返回。某来源报出的版本不比本机新时不会立刻定论，而是继续探测其余来源取版本最高者 —— 避免某个镜像缓存落后把真实的新版本静默吞成「已是最新」。
- **传输双栈**：`requests` 因证书校验失败时自动改用系统证书库重试。在启用 TLS 拦截的企业网络里，`requests` 自带的 certifi 验不过代理自签证书，而系统证书库可以 —— 只走 `requests` 会让两个权威来源永久不可达。
- **版本比较语义化**：支持 `v` 前缀、位数不齐与预发布后缀（`0.1.26-beta` 现能被正确判为低于 `0.1.26`；此前该写法会因 `int()` 抛错被静默判为无更新）。
- **检查结果结构化**：明确区分「已是最新 / 网络故障 / 清单损坏」，网络问题只写日志，不打扰正常使用。
- **多候选直链**：按清单声明 → Release 约定推导（同时覆盖 `v0.1.26` 与 `v0.1.26.0` 两种 tag 写法）→ 仓库 `dist/` 副本的顺序逐个尝试；未声明直链时也能自动推导。
- **下载产物校验**：落盘后校验 sha256、体积与 ZIP/EXE 容器格式，拒绝 HTML 错误页与半截包；并复核包内 `VERSION`，镜像返回旧包时自动换源。无校验和时不再使用不带版本信息的 `dist/` 兜底通道。
- 更新包统一存放于程序目录 `updates/` 下，保留最近一个，其余自动清理。
- 新增 `tools/make_release.py` 发版助手（强制包内带 `VERSION`、UTF-8 文件名、自动计算 sha256、生成本文件、可选清理 CDN 缓存）；`tools/bump_version.py` 现同步 README 版本标记。
- 修复 `engine` 命令失败静默成功：`execute()` 此前算出成功标志却恒返回 `True`，找图超时只记 `warning` 不抛异常，导致重试与「出错立即停止」对最常见的失败模式永不生效；工作流中失败的脚本步骤此前会被标为 `ok`。现失败可传播、可重试、可停。

## 下载

- 直链：`https://github.com/yohoten/acrpa/releases/download/v0.1.26/ACRPA.zip`
- SHA-256：见 Release 页面或 `dist/ACRPA.zip.sha256`（以打包产物的实际值为准）

## 安装

解压后直接运行 `ACRPA/ACRPA v0.1.26.exe`（便携版，无需安装）。

已装旧版的用户：启动后状态栏会提示新版本，点击即可在应用内下载并重启更新，
**配置、脚本、模板、日志均不受影响**。

## 校验

```powershell
# Windows
certutil -hashfile ACRPA.zip SHA256
```

## 已知限制

- 自更新只替换主程序与 `VERSION`。模板、使用说明等资源若在本版有变动，请下载完整包。
- 程序安装在受保护路径（如 `Program Files`）时无法自动替换，会提示手动解压。
- 仓库内 `dist/ACRPA.zip` 副本不带版本信息，仅在配置了 sha256 时才作为兜底通道；
  Gitee 的 raw 路径对 `dist/` 下的大文件实测返回 403，不作推荐通道。
