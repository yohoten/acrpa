# ACRPA v0.1.27.0

## 本版定位

**以 v0.1.25 为基线重建，修复 v0.1.26 的不稳定接线，同时完整保留 v0.1.26 的优点。**

v0.1.26 引入了更新机制重构与命令失败语义修复（方向正确），但在新增的“更新 UI”接线上
留下了两处缺陷，表现为运行期异常与功能失效。本版不改动 v0.1.26 已修复/已新增的能力，
只把基线拉回 v0.1.25 后分组重放、逐个验证，并修正接线。

## 修复（v0.1.26 遗留缺陷）

- **`_update_pending` 未定义** —— 该名字在 `src/ACRPA.py` 中被 `_periodic()`
  （每 100ms 运行）与更新提示回调 `_on_update_hint()` 引用，却从未定义。后果：
  `_periodic` 每次都抛 `NameError`，导致状态栏文本与执行进度/行号等刷新链路中断，
  界面表现为“日志与状态不更新”。本版定义 `_update_pending = {}` 修复。
- **`show_update_dialog` 未导入** —— `src/ACRPA.py` 顶部的 `from dialogs import (...)`
  未包含 `show_update_dialog`，而状态栏绑定 `status_text.bind("<Button-1>",
  lambda e: show_update_dialog())`。后果：点击状态栏触发 `NameError`，更新入口失效。
  本版将其纳入导入。

## 保留的 v0.1.26 优点（分组重放并验证）

1. **更新机制重构**（`src/updater.py` / `src/version_info.py` / 更新窗口）
   - 修复打包后版本号失真：`VERSION` 搜索顺序扩展为 EXE 同级 → `_MEIPASS` → 项目根，
     冻结后能读到真实版本号（此前永远回退到内置值）。
   - 多源降级：GitHub Releases API → raw/jsDelivr/Gitee 清单镜像；不再把网络故障
     伪装成“已是最新”。
   - 完整语义化版本比较：支持 `v` 前缀、位数不齐、预发布后缀。
   - 下载：多候选直链逐个重试、流式进度、sha256 与体积/容器格式校验、复核包内 `VERSION`。
   - 便携版一键重启自更新（仅替换主程序与 `VERSION`，不触碰用户数据）。
2. **engine 命令失败语义**（`src/engine.py` / `src/workflow.py`）
   - `execute()` 返回结构化结果，不再恒 `return True`；找图超时抛 `ImageNotFound`；
     `_exec_timings` 记录真实成功标志；工作流错误向上传播，落实 `stop_on_error` 与重试。
3. **发布工具链**：`tools/make_release.py`、`tools/publish_release.py`、`tools/bump_version.py`。
4. **仓库规整与文档**：`res/` 等构建资源纳管、`docs/`、`img/`、`index.html`、README。
