# ACRPA v0.1.29

> 发布 tag：**`v0.1.29`**（正式版 / Stable） · 发布日期：**2026-10-07** · 平台：**Windows x64** · 许可证：**MIT**

## 本版更新

本次为 **v0.1.29 正式版**：由本版源码重新构建（此前 0.1.29 仅以 `-beta` 口径、四段 tag `v0.1.29.0` 的形态发布），在 v0.1.29 功能基线（界面美化、底部常驻日志面板、设置窗口优化 P0、PaddleOCR.dll 原生 OCR 后端）之上，**新增窗口标题显示版本号**，并去除 `-beta` 预发布标识、程序内自报版本同步为 `0.1.29`。

### 一、窗口标题显示版本号（本次新增）

- 窗口标题（标题栏 / 任务栏 / Alt-Tab）统一为 **`A/C RPA v0.1.29`**，版本号取自 [`VERSION`](../../VERSION) 这一唯一事实来源，不再手写。
- `root.title()`（标题栏）与 `SetWindowTextW()`（任务栏 / Alt-Tab）**共用同一个取标题函数**，避免两处文案不一致。
- 取版本失败时**不抛异常、不影响启动**，退回不带版本号的 `A/C RPA`。
- 界面内自绘标题 Label（默认文案 `Adaptive Control Automation Workflow`、可双击自定义）**保持不变**。

### 二、界面美化（经典桌面软件 × Windows 设计语言）

- 色板与设计令牌扩充：新增 `surface_alt` / `border_strong` / `gridline` / `gutter_bg` 等键，控件配色全部走令牌而非散落字面量。
- ttk 按钮统一为**扁平 + 1px 描边 + 键盘焦点环 + hover 底色/描边双变化**，去掉默认浮雕感。
- 树形列表新增**选中左缘 2px 强调条**（随主题 / DPI 变更重建）、**行 hover 高亮**；`show="headings"` 类列表降级为**整行加粗 + 整行底**。
- 日志新增**级别徽标**（ⓘ 信息 / ✔ 成功 / ⚠ 警告 / ✘ 错误），按 tag 与级别统一映射。
- 新增 UI 缩放切换钩子（`register_ui_scale_hook`），缩放后样式、图标、选中条自动重建。
- 覆盖范围：`src/utils.py`、`src/ACRPA.py`、`src/dialogs.py`、`src/help_window.py`、`src/netlink_window.py`、`src/market_window.py`。

### 三、底部常驻日志面板 + 常驻执行控制工具栏

- 日志面板由「执行控制」Tab **迁移到底部常驻**（两个 Tab 共用），运行日志与内容同屏，不必来回切 Tab。
- 支持**一键收起 / 展开**（▾ 日志 / ▸ 日志）与**拖高**，默认高度 160 px、最小 60 px，收起前高度会被记忆。
- 运行控制条常驻标题栏下方：**▶ 运行 / ■ 停止**按当前激活 Tab **自动分派**脚本或工作流。

### 四、设置窗口优化（P0）

- **保存失败可定位**：保存出错时自动高亮对应卡片并给出明确原因（`_flash_failed` / `_show_save_error`），不再"点了保存没反应"。
- 新增**「高级设置」可折叠卡片**：执行 / 录制 / OCR / 浏览器 / 定时 / DD 六组集中收纳。
- 新增 **OCR 真实状态行**：显示当前实际后端与不可用原因，并提供「刷新状态」「重置后端」（重置后下次识别按新设置重新探测）。
- OCR 后端下拉新增 **`PaddleOCR.dll`** 选项；数值项输入越界自动回退默认值（`_int_or`）。

### 五、PaddleOCR.dll 原生 OCR 后端（可选，默认关闭）

- 新增 `src/paddle_dll.py`：以 ctypes 封装 `lib/paddle_ocr/PaddleOCR.dll`（`Initializejson` / `DetectByte` / `GetStructureDetect*` / `libaddLicense` 等导出）。
- DLL 目录、模型目录、**调用原型**与许可证串均可在设置中配置，便于按实际 DLL 版本适配。
- **崩溃隔离**：初始化与推理先在子进程预检，通过后才在主进程加载，避免一次 Access Violation 打死整个程序。
- **失败不抛异常**：依赖 / 模型缺失时记录原因并静默回退到 pip 版 PaddleOCR → Windows OCR → Tesseract；默认配置下后端优先级与旧版完全一致。
- 打包侧仅在 `lib/paddle_ocr` 集齐 4 个原生依赖时才随包分发（本仓库当前仅有 `PaddleOCR.dll`，因此未打入包内，需自备依赖与模型）。

### 六、AI 与稳定性修复

- AI 密钥可用性统一为单一真源 `ai_client.has_ai_key()`（带缓存失效），AI 增强各处复用；未配置密钥时给出明确提示而非静默失败。
- AI 生成脚本统一经 `normalize_ai_output` 规范化，状态区分「✔ 生成成功 / ✘ 认证失败」。
- `engine`：DD 驱动 / PyAutoGUI 输入与代码执行结果日志细化；DD 驱动 DLL 缺失或加载失败时明确提示回退 PyAutoGUI。
- 命令模板与参数填写说明补充（空参数必须写 `None` 的显式正/反例）。

### 七、文档与截图

- 新增 `docs/UI美化设计方案.md`、`docs/设置窗口优化设计方案.md`、`docs/底部常驻日志面板重构设计方案.md`、`docs/paddle-ocr-dll-使用说明.md`。
- 更新首页截图 `img/image1.png`、`img/image3.png`、`img/image5.png`。
- 发版文案（`README.md`、`index.html`、`index.en.html`、`使用说明.md`）由 `-beta` 口径统一改为正式版口径。

### 关于发布 tag

本版发布 tag 为 **`v0.1.29`**。（历史说明：上一轮因仓库启用了 GitHub **immutable release**，`v0.1.29-beta` 的 tag 被已发布的空 Release 永久占用，只能改用四段 tag `v0.1.29.0`；本次使用此前未占用过的 `v0.1.29`。）应用版本号即 `0.1.29`，客户端的下载直链以 [`VERSION`](../../VERSION) 首行 / 第二行声明为准。

### 已知限制

- 真机跨机验收未执行；NetLink TLS 真实握手未在开发机验证（缺 `cryptography` / `openssl`）。
- 浏览器只读面板为明文 HTTP + 令牌；UDP 广播发现在 VLAN / 多网卡环境不可靠，需静态对端兜底。
- Python 脚本级钩子仅在单脚本场景生效（工作流不触发）；`python_full_enabled` 与 `netlink_tls` 默认关闭。
- PaddleOCR.dll 后端需自备 4 个原生依赖（`paddle_inference.dll` / `tbb12.dll` / `yaml-cpp.dll` / `opencv_world470.dll`）与 PP-OCR 模型目录，默认关闭。
- 附件为本次由 `build.py` 在本地生成的构建产物，**未做代码签名**（首次运行如出现 SmartScreen 提示，选择「更多信息 → 仍要运行」即可）；Gitee 侧同步代码与 tag，Release 附件视上传情况而定。
