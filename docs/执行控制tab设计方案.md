### 0.2 问题诊断（按严重度排序）

| # | 问题 | 现象 | 影响 |
| --- | --- | --- | --- |
| P1 | **控制按钮语义分散** | 运行/暂停/单步在「配置卡」，停止却在「日志卡底部动作条」 | 违反「主控集中」直觉，用户找不到「停止」 |

## 1. 设计目标与非目标

### 1.1 目标

1. **单一主控区（Single Control Focus）**：运行/暂停/单步/停止四个核心动作聚合为一组状态机按钮，且状态可见。
2. **调试内聚**：将「调试模式、单步模式、断点、变量监视」纳入「执行控制」Tab 的调试子区，与运行态联动。
3. **可观测性升级**：进度区展示 循环 / 行 / 耗时 / ETA / 成功·失败计数，并可一键查看统计。
4. **可靠性**：用**事件驱动断点**替换 200ms 时间窗单步，做到「执行一行、停一行」可预期。
5. **零回归**：所有新增控件的默认值 = 现状行为；不改动 `engine` 既有语义与 `exec_state` 字段名。

### 1.2 非目标（明确不做）

* 不重写 `autorun` / `engine.execute_script` 的执行模型与线程结构。
* 不改变 `.xls` 脚本格式与命令字典。
* 不引入第三方 UI 依赖（继续 tkinter/ttk 原生）。
* 不迁移「设置」窗口已有的参数卡逻辑，只做**镜像展示 + 快捷入口**。
* 不改动 NetLink 远程控制的协议与权限模型（仅保证本 Tab 与远程 `run/stop` 语义一致）。

## 2. 信息架构：从「两段式」到「三段式」

现状是 `[配置卡] + [日志卡]` 两段。建议重组为**三段式**，遵循「控制在上、观测在中、输出在下」的自上而下阅读流：

```text
┌──────────────────────────────────────────────────────────────┐
│  ①  运行控制条 (Run Control Bar)  —— 常驻，一行高              │
│     脚本▾  次数[∞▾]  │ ▶运行  ⏸暂停  ⏭单步  ■停止  │ [调试][变量] │
├──────────────────────────────────────────────────────────────┤
│  ②  执行仪表盘 (Execution Dashboard) —— 状态 + 进度 + 统计     │
│     ●运行中  循环 3/∞  行 12/40  已用 01:23  ETA ~00:45  ✅38 ❌2 │
│     ▓▓▓▓▓▓▓▓░░░░░░░░░░░░  32%                                  │
├──────────────────────────────────────────────────────────────┤
│  ③  运行日志 (Run Log)  —— 占满剩余高度                        │
│     [级别▾ 全部][🔍搜索____][清空][导出]               自动滚动▢ │
│     ────────────────────────────────────────────────────────  │
│     12:03:01 [INFO ] 开始第1次循环                              │
│     12:03:02 [ERROR] 图像未找到: login.png (第 12 行)           │
└──────────────────────────────────────────────────────────────┘
```

**分区职责**

| 分区 | 职责 | 是否常驻 | 伸缩 |
| --- | --- | --- | --- |
| ① 运行控制条 | 脚本选择、次数、四个主控动作、调试入口 | 是 | 否（固定高） |
| ② 执行仪表盘 | 状态点、进度、耗时/ETA、成功失败计数 | 是 | 否（固定高） |
| ③ 运行日志 | 日志、过滤、搜索、导出、自动滚动 | 是 | 是（`weight=1`） |

## 3. 分区详细设计

### 3.1 ① 运行控制条

**布局（单行，横向可滚动以兼容窄窗/缩放）**

```text
脚本: [recent.xls        ▾] [选择脚本]   次数:[∞ ▾]   │  [▶ 运行] [⏸ 暂停] [⏭ 单步] [■ 停止]   │  [🐞 调试] [📊 变量]
```

**要点**

* 复用现有 `_script_switcher` / `select_script`（[`3265`](../src/ACRPA.py#L3265)、[`3163`](../src/ACRPA.py#L3163)），不改变最近脚本逻辑。
* 「停止」按钮**上移**到此条，与运行/暂停/单步同组；底部动作条的「停止」移除（避免重复）。
* 「运行次数」由只读下拉升级为**可编辑 Combobox + 预设**：`∞` / `1` / `5` / `10` / `50` / `自定义…`；`自定义…` 弹出输入框（仅接受正整数）。默认值保持 `无限循环` → **行为不变**。
* 调试入口按钮 `🐞 调试`、`📊 变量` **复用**已有 `_toggle_debug_mode` / `_show_variables_window`（[`2749`](../src/ACRPA.py#L2749)、[`2780`](../src/ACRPA.py#L2780)），不改逻辑，只增入口。

**按钮状态机（关键改进）**

四个按钮不是静态的，需按运行态启用/禁用并切换文案：

| 状态 | ▶运行 | ⏸暂停 | ⏭单步 | ■停止 |
| --- | --- | --- | --- | --- |
| 就绪（未运行） | 启用 | 禁用 | 禁用 | 禁用 |
| 运行中 | 禁用 | 启用（文案「⏸ 暂停」） | 启用 | 启用 |
| 已暂停 | 禁用 | 启用（文案「▶ 继续」） | 启用 | 启用 |
| 已停止 | 启用 | 禁用 | 禁用 | 禁用 |

> 现状：运行中再点运行靠 `main_run` 内 `if state.running` 拦截并提示（[`1235`](../src/ACRPA.py#L1235)）；建议改为**按钮级禁用**，减少无效点击与日志噪音。

### 3.2 ② 执行仪表盘

**布局（两行）**

```text
行1: ●运行中   循环 3/∞    行 12/40    已用 01:23    ETA ~00:45    成功 38   失败 2
行2: ▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░  32%
```

**要点**

* **状态点 + 文案**：直读 `state.running` / `pause_event` / `quit2`，与底部状态栏同一判定（[`4912`](../src/ACRPA.py#L4912) – [`4934`](../src/ACRPA.py#L4934)），保证一致性。
* **进度条**：从 4px「Micro」升级为常规高度（约 8–10px），保留 `Success.Horizontal` 完成后变色（[`1874`](../src/ACRPA.py#L1874)）。
* **ETA**：`ETA = elapsed / done_rows * (total_rows - done_rows)`；在首行完成前显示 `ETA --:--`。纯前端计算，不侵入 engine。
* **成功/失败计数**：需 engine 侧配合（见 §4.2）；未接入前隐藏该两列，接入后显示。
* **耗时格式**：`mm:ss` / `hh:mm:ss`（现状仅 `{:.0f}s`，长任务可读性差）。
* **刷新策略**：复用 `_periodic` 的 `_cache` 去重机制（[`4911`](../src/ACRPA.py#L4911)），新增字段一并纳入 cache 比对，避免每帧重绘。

### 3.3 ③ 运行日志

**工具条（新增，位于原「自动滚动」位置扩展）**

```text
[级别 ▾ 全部] [🔍 关键字________] [清空] [导出]
```

**要点**

* **级别过滤**：下拉 `全部 / INFO / SUCCESS / WARNING / ERROR`，基于现有 tag（[`3392`](../src/ACRPA.py#L3392) – [`3395`](../src/ACRPA.py#L3395)）实现——过滤时用 `tag_remove`/隐藏行或用第二个 `Text` 视图，**推荐**：过滤 = 遍历 `Text` 的段（`dump`）按 tag 决定是否 `elide`。
* **关键字搜索**：高亮匹配或仅显示命中行；提供「下一个」跳转。
* **清空 / 导出**：清空仅清 `Text` 视图（不删磁盘日志）；导出另存当前视图为 `.log`/`.txt`。磁盘日志路径已有 [`3400`](../src/ACRPA.py#L3400)。
* **自动滚动**：保持现状（默认开），滚动到底部时自动跟随。
* 不改动 `ThreadSafeLog` 注入（[`3397`](../src/ACRPA.py#L3397)）。

## 4. 交互与数据设计

### 4.1 单步执行的可靠化（替换 200ms hack）

**现状缺陷**：`_step_once`（[`3334`](../src/ACRPA.py#L3334)）执行 `pause_event.set()` → `root.after(200, clear)`，用固定时间窗"放行"引擎。慢操作会跨多步，快操作会漏放行。

**建议方案：行级门控**

* 在 `engine.execute_script` 的行循环处，读取一个「步进许可令牌」`state.step_token`（`threading.Event` 或计数器）。
* 单步按钮：`step_token.set()`（放行一行）后引擎在**每一行执行前** `wait()` 并**立即清除**（一次性放行），实现「点一次 = 走一行」。
* 与 `state.step_mode`（[`2761`](../src/ACRPA.py#L2761)）联动：开单步模式后天然每行暂停。

> 兼容：`step_token` 为**新增** state 字段，默认永远 `set()`（即无单步时为直通），对既有执行**零影响**。

### 4.2 执行统计（成功/失败计数）

* engine 已维护 `engine._script_failed`（见 [`1302`](../src/ACRPA.py#L1302) 附近语义）。建议扩展为 per-run 计数：`exec_state["ok_cmds"]` / `exec_state["fail_cmds"]`。
* `autorun` 每轮结束汇总（[`1306`](../src/ACRPA.py#L1306) 附近）。
* 仪表盘读取上述字段；**未接入时隐藏计数列**，保证渐进兼容。

### 4.3 运行参数就地化（镜像而不迁移）

把「设置」窗口里最影响单次运行的 3 项**镜像**到控制条次级区（可选折叠面板）：

* 最大执行时间（`max_execution_minutes`）
* 出错即停（`stop_on_error`）
* 重试次数/间隔（`retry_max`/`retry_interval`）

写回仍走现有配置保存通道（`state` schema → config.json），**不复制**业务逻辑，仅提供快捷入口 + 当前值展示。

### 4.4 运行历史（P2，可选）

* 每次 `autorun` 结束写入一条记录：`{脚本, 开始时间, 耗时, 循环数, 成功, 失败, 结果}`，落盘于 `APP_ROOT/recent_runs.json`（与既有 `recent.json` 同级，见 [`3274`](../src/ACRPA.py#L3274)）。
* 在仪表盘加「历史」按钮，弹窗表格（复用 `_show_variables_window` 的 `Treeview` 范式，见 [`2816`](../src/ACRPA.py#L2816)）。

## 5. 视觉与样式规范

* **颜色令牌**：全部复用 `C[...]`（`ac/ach/sc/wn/dg/fgb/fgm/bgc/bd/ebg/...`）与 `_darken()`（如 [`3327`](../src/ACRPA.py#L3327)），不新增硬编码色，保证深色/浅色主题一致。
* **字体令牌**：`FONT_BODY/FONT_SMALL/FONT_BUTTON/FONT_TINY`（[`1319`](../src/ACRPA.py#L1319) – [`1323`](../src/ACRPA.py#L1323)）。
* **控件基线**：
  * 主控按钮：`relief="raised", bd=3, cursor="hand2"`，颜色语义 运行=绿(`sc`)、暂停=橙(`wn`)、单步=蓝(`ac`)、停止=红(`dg`)，与现状一致（[`3326`](../src/ACRPA.py#L3326) – [`3353`](../src/ACRPA.py#L3353)）。
  * 禁用态：`state="disabled"` 或 `fg=C["fgm"], bg=C["bgc"]`。
* **缩放**：所有新控件尺寸需兼容 `ui_scale`（[`state.py:140`](../src/state.py#L140)）与 DPI 感知（[`1338`](../src/ACRPA.py#L1338)）；避免硬编码像素高，优先 `pack/pady` 与字体驱动。
* **横向滚动条**：控制条沿用现有 `Canvas + Scrollbar` 横向滚动范式（[`3427`](../src/ACRPA.py#L3427) – [`3448`](../src/ACRPA.py#L3448)）与滚轮绑定，兼容窄窗。

## 6. 分阶段实施计划

### P0 — 低成本高收益（不触碰 engine）

1. 三区重排：控制条聚合四个主控按钮（含「停止」上移）；移除底部动作条重复「停止」。
2. 按钮状态机（§3.1）：按 `running/paused/stopped` 启用禁用 + 暂停文案切换。
3. 仪表盘升级：状态点、耗时 `mm:ss`、ETA、进度条加高。
4. 日志工具条：级别过滤 + 清空 + 导出 + 自动滚动开关。
5. 运行次数可编辑 + `自定义…`。

**验收**：默认参数下行为与旧版一致；切 Tab、缩放、深色模式下布局不破。

### P1 — 需 engine 轻配合

6. 单步行级门控（§4.1）：新增 `state.step_token`，替换 200ms hack。
7. 成功/失败计数（§4.2）：`exec_state` 新增两个键，仪表盘消费。
8. 调试入口内聚（§3.1）：调试/变量按钮并入控制条（复用已有函数）。

**验收**：单步「点一次走一行」可预期；统计与日志实际一致。

### P2 — 增强

9. 运行参数就地化（§4.3）。
10. 运行历史（§4.4）。
11. 日志关键字搜索 + 命中跳转。

## 7. 兼容性与风险

| 风险 | 规避 |
| --- | --- |
| 改动 UI 导致 `_periodic` 引用未定义控件 | 新增控件先声明再在 `_periodic` 内 `hasattr`/`try` 保护；cache 字段一并更新 |
| 单步新逻辑影响既有执行 | `step_token` 默认放行；仅在显式单步/断点时消费 |
| 运行次数默认值变化 | 默认仍为「无限循环」，`main_run` 解析逻辑保持 [`1238`](../src/ACRPA.py#L1238) 语义 |
| 主题/缩放不一致 | 只用 `C`/`FONT` 令牌与 `ui_scale`，禁止硬编码 |
| 设置项双入口不一致 | 就地面板只镜像 + 快捷写回，唯一权威仍在 config schema |
| 与 NetLink 远程控制冲突 | 本 Tab 与远程 `run/stop` 复用同一 `main_run`/`stop_execution`，语义天然一致 |

## 8. 结论与建议优先级

1. **先做 P0 的「控制按钮聚合 + 状态机 + 仪表盘」**：这三项直接解决 §0.2 中 P1/P4/P8 三个最痛问题，且**零 engine 侵入**，回归风险最低。
2. **再做 P1 的「单步行级门控」**：这是唯一涉及执行核心的改动，收益明确（可预期调试），但需 engine 配合，安排在 P0 稳定后。
3. **P2 视需求排期**：历史与搜索是「锦上添花」，可后置。
