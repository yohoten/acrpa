## 1. 背景与目标

设置窗口是 ACRPA 的"配置中枢"，承载 11 张卡片、约 90 个配置项、若干带副作用的动作
（快捷键录制、凭据库读写、调度器重启、TLS 证书选择、DLL 自检等）。

当前实现**功能齐全但结构脆弱**：所有 UI 与保存逻辑都写在单个函数里，手写控件重复度高，
保存路径不统一，且在本次评审中发现**两个会静默丢配置的缺陷**。

优化目标（按优先级）：

| 目标 | 可量化指标 |
|---|---|
| 配置不丢、不静默失败 | 0 个"永不落盘"字段；保存失败 100% 可见可重试 |
| 可维护 | `settings_window.py` < 300 行；重复样式字面量 0；卡片/字段各自模块化 |
| 可发现 | 搜索 3 秒内定位任意设置；导航有分组；需重启项有统一标识 |
| 可测试 | 离屏冒烟 + schema 一致性脚本可自动跑通 |
| 零破坏 | config.json 键名、对外函数签名（`open_settings_window` / `init_ctx` / `refresh_theme` / `update_sched_next_label`）不变 |

## 3. 问题清单（按严重度）

### P0-1 「高级设置」卡 apply 缩进错位 → 静默丢配置

位置：[`_apply_advanced_settings`](../src/settings_window.py:640)

```python
try:
    state.MAX_EXECUTION_MINUTES = int(max_minutes_var.get())
except ValueError:
    state.MAX_EXECUTION_MINUTES = int(max_minutes_var.get())     # 再抛一次
    state.BOUND_WINDOW_TITLE = bound_window_var.get().strip()    # 只在异常分支
    state.STOP_ON_ERROR = stop_on_error_var.get()                # 只在异常分支
    state.OCR_PREFERRED_BACKEND = _OCR_BACKEND_MAP.get(...)      # 只在异常分支
state.OCR_PADDLE_DIR = ocr_paddle_var.get().strip()              # 平铺部分
```

后果：

1. 正常输入时，**「绑定窗口」「出错立即停止」「OCR 后端」三项永不落盘**；
2. 一旦「最大执行」非法，异常分支里的 `int()` 再次抛出 → `_do_save` 捕获后
   **该卡后续所有赋值（OCR 模型目录 / 浏览器 / 调度轮询 / DD DLL / PaddleOCR.dll 开关）整批跳过**；
3. 界面角标不显示失败（见 P0-3），用户完全无感。

最小修复建议：

```python
def _apply_advanced_settings():
    state.MAX_EXECUTION_MINUTES = _int_or(max_minutes_var, state.MAX_EXECUTION_MINUTES, 0, 1440)
    state.BOUND_WINDOW_TITLE = bound_window_var.get().strip()
    state.STOP_ON_ERROR = stop_on_error_var.get()
    state.OCR_PREFERRED_BACKEND = _OCR_BACKEND_MAP.get(ocr_backend_var.get(), "auto")
    state.OCR_PADDLE_DIR = ocr_paddle_var.get().strip()
    ...
```
（`_int_or` 为"取整数或回退既有值/默认值"的小工具，集中处理非法输入，不再用 try/except 包整块赋值。）

### P0-2 OCR 状态与"应用并重载"引用了不存在的接口

位置：[`_reload_ocr`](../src/settings_window.py:1815)、[`_detect_ocr_status`](../src/settings_window.py:1887)

```python
from ocr_backend import get_ocr_engine     # ← ocr_backend 中不存在此函数
```

`ocr_backend` 实际导出的是 `ocr_get_backend_info()` / `ocr_reset_backend()` /
`ocr_read_region()` / `ocr_find_text_position()`。因此这两处**永远走 except**：
"OCR 状态"恒显示"未初始化/未安装"，"应用并重载"必然失败。

修复：状态用 `ocr_get_backend_info()`（返回 `{backend, name, available}`），
重载用 `ocr_reset_backend()`。

### P0-3 保存失败静默

位置：[`_do_save`](../src/settings_window.py:244)

异常只 `log1(...)`，界面无提示，角标也不切换成失败态 → 用户以为已保存。
建议：行级红框 + 卡角标 `⚠ 保存失败（点击查看）` + 重试按钮。

### P0-4 「高级设置」卡行内语义混杂

[`adv_exec_frame`](../src/settings_window.py:1759) 把"最大执行 / 绑定窗口"同排，
[`adv_sys_frame`](../src/settings_window.py:1922) 把"调度轮询 / DD DLL 路径"同排，
PaddleOCR.dll 行把"DLL 目录 / 模型目录 / 自检按钮"挤一排。窄窗口（min 580px，
[`_win.minsize`](../src/settings_window.py:456)）下必然错位。

### P1-1 单函数 2200 行 + 闭包互引

`open_settings_window` 从 [458](../src/settings_window.py:458) 延伸到文件末尾；
[`_apply_advanced_settings`](../src/settings_window.py:640) 引用的 `paddle_dll_enabled_var`
在 1800 行之后才创建（靠闭包延迟解析才"看似能跑"）。任何重排都可能踩空，
且无法单元测试、diff 噪音极大。

### P1-2 手写控件重复

`font=… fg=C["fgb"] bg=C["bgc"] relief="solid" bd=1` 这类参数贯穿全文件 300+ 处，
主题色、圆角、内边距靠人肉保持一致；`_validate_number(...)` 的范围参数又与
Spinbox 的 `from_/to` 各写一遍（例：[1834](../src/settings_window.py:1834)）。

### P1-3 保存路径不统一

- [`_close`](../src/settings_window.py:213) 直接写 `state.WIN_GEOMETRY` + `save_config()`
- [`_toggle_auto_start`](../src/settings_window.py:1380)、[`_toggle_tray`](../src/settings_window.py:1418)、
  [`_toggle_help_modal`](../src/settings_window.py:1450)、[`_toggle_mini_bar`](../src/settings_window.py:1465)
  直接写 state（立即生效），而这些变量同时被
  [`_track_card_vars("system", …)`](../src/settings_window.py:1688) 防抖保存 → **一条设置两条写盘路径**，
  行为取决于时序。

### P1-4 UI 变量泄漏到 state

[`state._sched_enabled_var`](../src/settings_window.py:1234)：tkinter 变量被 state 模块持有，
破坏"UI 只读 state、只通过 save 写 state"的单向数据流，也让离屏测试无法只替换 UI 层。

### P1-5 注释与实现漂移

[`_nav_cards` 注释](../src/settings_window.py:48) 写 `(key, icon, label, card_widget)`，
实际 [`_register_nav_card`](../src/settings_window.py:419) 只 append `(key, card_widget)`。

### P2-1 可发现性

无搜索；11 张卡无分组；导航跳转用 `winfo_y()` 比例估算滚动
（[`_on_nav_click`](../src/settings_window.py:425)），卡片折叠/展开改变高度后定位会漂移。

### P2-2 状态不可见

没有区分"控件值 / 已落盘值 / 运行时已生效值"，也没有"需重启生效"的统一标识；
而 OCR、DD、浏览器、NetLink 都有明确状态语义。

### P2-3 无依赖联动

`paddle_dll_enabled=false` 时 DLL/模型目录仍可编辑；NetLink 的认证/面板/TLS 子项同理，
用户容易配出一堆无效组合。

### P2-4 校验体验

`_validate_number` 仅在 FocusOut 生效，输入过程无反馈；非法值处理是"弹 toast + 重置默认"，
会丢掉用户原本的合法值。

### P2-5 新配置没有 UI

`paddle_dll_config`（高级参数 JSON）、`paddle_dll_license`、`paddle_dll_proto_init/detect`
（[state.py 键](../src/state.py:67)）目前只能手改 config.json。
更早的 `browser_*` 若干键也处于同样状态 —— 说明缺少"高级参数（JSON）"这类通用控件，
属于**结构性**缺口，不修会持续累积。

## 5. 交互与视觉规范（统一约定）

### 5.1 行语义表（每行只承担一种角色）

| 行类型 | 组成 | 行为 |
|---|---|---|
| 开关行 | `☑ 标题` + 可选说明 | 立即防抖保存；关闭时联动禁用子行 |
| 数值行 | `标题 [值] 单位 (范围)` | 即时校验（输入即提示）、超范围不落盘 |
| 路径行 | `标题 [输入] [浏览]` + 存在性标记 | 失焦校验存在性/是否为目录；不存在黄框提示 |
| 选择行 | `标题 (下拉 ▾)` + 说明 | 选项变化时更新依赖项的可编辑状态 |
| 危险行 | 红字标题 + 说明 + 二次确认 | 如恢复默认、清除配对、删除凭据 |
| 只读状态行 | `● 状态文本 [动作按钮]` | 不参与保存；动作就地给结果 |
| 联动子行 | 缩进 12px | 由父开关/父选项决定 `state=disabled` |

### 5.2 字段三态与徽标

> 图标一律使用 `Segoe UI Symbol` 单色字形（**禁彩色 Emoji**），口径见 [`docs/UI美化设计方案.md`](./UI美化设计方案.md) §3 / §3.1。

| 态 | 视觉 | 触发 |
|---|---|---|
| 未修改 | 默认 | 打开窗口 |
| 已修改（待生效） | 行左侧黄点 `●`(U+25CF) + 卡角标 `●` | 控件改动、尚未落盘/生效 |
| 已生效 | 行左侧绿点 `●`(语义色 `sc`) + 卡角标 `✔ 已保存`(U+2714) | `state.save_config()` 成功 |
| 需重启 | 行尾 `⏱`(U+23F1) + 卡角标汇总 `⏱2` | 字段元数据 `needs_restart=True` |
| 保存失败 | 行红框 + 卡角标 `⚠ 保存失败（点击查看）`(U+26A0) | apply/落盘抛异常 |

> 说明：原方案中的 🕓 / ⚠️ 等 Emoji 一律替换为 `⏱` / `⚠`（**并去除 VS16 `U+FE0F`**），映射结论见主设计文档 [§3.1](./UI美化设计方案.md#31-emoji--segoe-ui-symbol-映射表v7-裁决)；**`🔍` 在代码中不存在**（日志工具条为文字「搜索」，[`ACRPA.py:4105`](../src/ACRPA.py#L4105)），**无需替换**。

### 5.3 其他约定

- 自检类动作（DLL 自检 / 测试连接 / 刷新状态）**就地展示结果**，不再弹模态框；
- 校验失败不清空用户输入，只在行下方给出原因与自动修正建议（点击应用）；
- 所有说明文字统一 `FONT_TINY` 灰色，不再用 hover tip 承载关键信息（触屏/新用户发现不到）。

### 5.4 与主设计文档的对齐（强制）

本窗口的控件外观**必须**与 [`docs/UI美化设计方案.md`](./UI美化设计方案.md) 的令牌口径一致，不得自建：

| 项 | 规范 | 主文档条款 | 现状落点（须改） |
|---|---|---|---|

## 6. 架构重构方案

### 6.1 模块划分（对外 API 不变）

```
src/settings/
  __init__.py     # re-export：open_settings_window / init_ctx / refresh_theme /
                  #            update_sched_next_label  → ACRPA 侧调用零改动
  registry.py     # 配置字段元数据（label/类型/范围/分组/依赖/是否需要重启/是否敏感）
  widgets.py      # Row / Section / Card / Nav / SearchBar / StatusBar 等工厂
  store.py        # 唯一写入口 set_value()/save_now()/dirty 跟踪/失败回滚/失败回调
  cards/*.py      # 每卡一个模块：声明字段 + 少量特殊控件（快捷键录制、账户面板等）
  legacy.py       # 迁移期兼容层：老 import 路径与老 helper 转发
```

### 6.2 字段元数据（registry）

```python
ConfigField(key="paddle_dll_dir", group="ocr", label="DLL 目录",
            kind="path", mode="dir", enabled_when="paddle_dll_enabled",
            needs_restart=False, help="包含 PaddleOCR.dll 的纯英文路径")
ConfigField(key="ocr_threads", group="ocr", label="CPU 线程", kind="int",
            min=1, max=32, unit="个", needs_restart=True)
ConfigField(key="paddle_dll_config", group="ocr", label="推理参数 JSON",
            kind="json", advanced=True, ui_pref="collapsed")
ConfigField(key="api_key", group="ai", label="API Key", kind="secret",
            store="credential")          # 敏感项不进 config.json
```

好处：范围/单位/依赖/是否重启/是否敏感**只声明一次**，UI、校验、落盘、状态徽标全部由元数据驱动；
新增设置只需加一行元数据（或显式 `ui=False`），从结构上杜绝 P2-5 那类"有配置没 UI"。

### 6.3 唯一写入口（store）

```python
class SettingsStore:
    def set_value(self, key, value): ...      # 标脏 + 防抖
    def save_now(self, group=None): ...       # 批量落盘，返回成功与否
    def dirty(self, key=None): ...            # 三态查询
    def on_error(self, cb): ...               # 失败回调 → 徽标/行级红框
    def reset_group(self, group): ...         # 按卡恢复默认（含二次确认）
```

所有写路径（含当前的 `_close`、`_toggle_*` 旁路）统一收敛到这里，`config.json` 只在
`save_now` 内被写一次，`_apply_map` 的卡级 apply 退化为"派生动作"（如重启调度器、
同步 NetLink 监听器）而非"赋值入口"。

### 6.4 兼容策略

- 保留 `src/settings_window.py` 作为**薄壳**（<300 行）：
  `from settings import open_settings_window, init_ctx, refresh_theme, update_sched_next_label`；
- 迁移期新老并存：先把 [widgets.py] 抽出来替换重复样式，再逐卡搬迁，最后删除旧函数；
- config.json 键名、默认值、读写时机完全不变 → 用户无迁移成本，可随时回滚到旧实现。

## 8. 回归与自动化保障

1. **离屏冒烟脚本** `tools/_debug_settings_smoke.py`（沿用仓库 `tools/_debug_*.py` 惯例）：
   `root.withdraw()` → 打开设置窗口 → 遍历 registry 逐字段 `set_value` → 断言
   `state.*` 与 config.json 值一致 → 输出差异报表；可在提交前跑。
2. **schema 一致性脚本** `tools/_check_settings_schema.py`：
   ① registry 的 key ⊆ `state._config_schema`；② 每个 key 有 UI 或显式 `ui=False`；
   ③ registry 的默认值与 state 默认值一致。→ 直接防止 P0-1 / P2-5 类问题复发。
3. **视觉回归**：主题切换 + 两档缩放（现有 `ui_scale`）下的截图对比，重点看行对齐与徽标位置。
4. **手工验收清单**（每阶段内固定 12 条）：11 张卡各改 1 项 + 关闭重开窗口验证持久化。

## 10. 风险与取舍

| 风险 | 应对 |
|---|---|
| 全量 schema 化会削弱自绘控件体验（快捷键录制、账户面板、TLS 选择） | 采"简单字段 schema 化 + 复杂块手写"的混合策略，不追求 100% 覆盖 |
| P1 拆模块可能引入闭包顺序问题（如 [640](../src/settings_window.py:640) 引用后置变量） | 按卡逐个搬迁、每卡独立提交；搬迁时显式把依赖变量上移为参数 |
| 迁移期双实现并存造成困惑 | `settings_window.py` 只做转发，标识 `# legacy shim`；P2 完成后删除旧实现 |
| 主题/缩放回归 | 每阶段跑视觉回归 + 手工 12 条清单 |
| 改动面大导致评审困难 | P0/P1/P2 三批独立 PR，每批自带验收证据（config.json 截图/脚本输出） |
