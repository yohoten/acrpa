# ACRPA 结构优化建议 —— 面向后续开发的目录与依赖治理

> 本文基于 2026-11-02 对 `D:\CodingEmber\ACRPA` 的实测体检（行数、导入图、循环依赖、打包与工程目录），
> 对照 `docs/ACRPA-完善路线图.md` §3 软件设计 / §9 分阶段路线图，给出**当前结构下**的优化顺序。
> 所有数字均为脚本实测，非估计。

---

## 0. 结论先行

1. **阶段性重构已过半，剩余的是"硬骨头"而非"体力活"。** 路线图 §3.2 列的 7 项拆分，1/2/3/5/6 已完成
   （`ui/workflow_view.py`、`ui/log_dock.py`、`ui/exec_bar.py`、`ui/theme.py`、`ui/settings/` 均已落地），
   剩下的 #4 脚本表格、`#7` NetLink 窗口是最难的两项——它们不是"搬代码"，而是要先造出模型层和契约层。

2. **真正的瓶颈不是"文件太大"，而是两个万能模块。** `state.py`（54 个模块导入）与 `utils.py`（51 个）
   构成了星形依赖的中心。只要它们还是全局杂物抽屉，任何拆分都只是把 6299 行的耦合换成 6 个 1000 行
   文件之间的耦合。

3. **有一处"低成本、高解锁"的改动应当优先做**：把 `utils.py` 里的日志总线与三个纯工具组抽出为
   `core/log.py` / `core/fs.py` / `core/version.py`。实测 `engine.py` 与 `workflow.py` 依赖 tkinter
   **唯一的原因**是 `from utils import log1`（`engine.py:18`、`workflow.py:15`）——为了一个日志函数，
   整个领域层被拽进 GUI 依赖。抽完之后核心域可在无 tkinter 环境导入，直接解锁 §6.5 CLI/无头模式。

4. **依赖图有 6 组运行期环**（全部靠函数内惰性 import 掩盖，导入期不报错，因此静态检查看不见）。
   它们是后续"命令插件化""工作流 CFG 化"最大的阻力，建议用**接口 + 构造注入**逐个拆掉，
   而不是继续加惰性 import。

5. **不建议现在做大规模目录搬迁。** `src/` 56 个平铺文件确实不好导航，但它换来的是
   `run.py` / 两个 `.spec` / `build.py` / `tools/` 全量路径稳定。正确顺序是
   **先解耦（L1–L2），再搬迁（L3）**；反过来做会同时踩"路径错"和"耦合深"两个坑。

## 3. 四个结构性问题（按严重度排序）

### 3.1 `utils.py` 是"假公共层"——核心域被 tkinter 绑架（最该先修）

`utils.py` 1431 行，顶层 `import tkinter` / `import tkinter.font`（`:7-8`），同时塞了 7 类互不相关的东西：

| 类别 | 符号 | 是否需 tkinter |
| --- | --- | --- |
| 日志总线 | `log1`、`register_log_sink`、`_broadcast_log`、`set_tlog`、`ThreadSafeLog` | **否** |
| 文件原子写 / 净化 | `atomic_save`、`atomic_write_bytes`、`safe_filename`、`_sanitize_segment` | **否** |
| 版本比较 | `parse_version`、`compare_versions`、`version_tuple`、`version_gt` | **否** |
| 颜色对比度 | `_darken`、`rel_luminance`、`text_on`、`_colors`、`themed` | 部分 |
| 缩放 token | `dpi_factor`、`scaled`、`sp`、`tk_px`、`radius`、`ctrl_h`、`gap`、`icon_size`、`font` | 是 |
| 控件工厂 | `create_card`、`_btn`、`attach_tooltip`、`set_accessible_name`、`bind_icon_activate` | 是 |
| 窗口几何 | `win_virtual_bounds`、`center_geometry`、`dialog_geometry`、`place_dialog`、`show_toast` | 是 |

实测后果（用不含 tkinter 的解释器导入）：

```
OK    state        OK    commands      OK    scriptdata    OK    script_io
OK    script_model OK   flow_graph     OK   script_validate
FAIL  utils     → ModuleNotFoundError: No module named 'tkinter'
FAIL  engine    → 同上（经 engine.py:18 `from utils import _safe_get, log1`）
FAIL  workflow  → 同上（经 workflow.py:15 `from utils import log1`）
```

`log1` 被 **27 个模块**使用，其中 13 处是顶层 `from utils import log1`。
也就是说：**27 个模块为了写一个日志，集体依赖了 tkinter。**

这不是洁癖问题，它直接卡住三件事：

- §6.5 CLI / 无头模式 —— 无 tkinter 环境跑不起来；
- 领域层单测 —— 必须连带 GUI 依赖一起装；
- 打包瘦身 —— 无法把核心域单独打成轻量 CLI 产物。

### 3.2 `state.py` 是事实上的全局总线

699 行里混了四个生命周期完全不同的东西：

| 关注点 | 代表符号 | 生命周期 |
| --- | --- | --- |
| 配置 schema / 单例 / 变更订阅 | `_config_schema`、`config`、`on_config_change`、`config_to_dict` | 持久化，跨会话 |
| 运行态 | `running`、`pause_event`、`exec_state`、`recording`、`breakpoints`、`_exec_timings`、`debug_mode` | 单次运行 |
| 编辑器态 | `_editor_rows`、`_editor_clipboard`、`_undo_stack`、`_redo_stack`、`_editor_modified` | 单个文档 |
| 路径解析 | `APP_DIR`、`DATA_ROOT`、`USERDATA_DIR`、`PORTABLE`、`_resolve_data_paths` | 进程级，启动算一次 |
| UI 偏好 | `LAST_TAB`、`MAIN_GEOMETRY`、`HELP_GEOMETRY`、`COMPACT_MODE` | 持久化（应并入配置） |

后果：任何模块都能读写 `state.anything`，模块之间没有接口，只有约定。
`_editor_rows` 放在 `state` 里，正是 §3.4「行索引即主键」无法推进的原因——
表格模型没有自己的家。

### 3.3 六组运行期环（见 1.3）

惰性 import 是一种"局部最优的止痛药"：它解决了导入期报错，但把依赖方向问题
从"编译期可见"变成了"只有运行时才暴露"。`acrpa_api.py` 的注释已经承认这一点。

### 3.4 `init_ctx` / `bind(**kw)` 全局注入

`mini_bar.bind(**kw)` 把 17 个宿主符号用 `globals().update(kw)` 写进模块命名空间，
模块自己的 docstring 写着"漏一个就是运行期 NameError"。同类还有 `dialogs.init_ctx`、
`settings.init_ctx`、以及直接改调色板 `settings_window.C = C`（`ACRPA.py:1406`）。

这套机制**是上一轮拆分能落地的前提**（值得肯定），但它同时也是那些模块至今仍无法
脱离宿主独立测试的原因。路线图 §3.3 已指出 `tools/_test_minibar_split.py` 护栏丢失——
**护栏没了，这套高危模式的退化就没人报警。**

## 4. 优化方案（L0 → L3，按"风险递增 / 收益递减"排列）

### L0 · 止血与清理（1–2 天，零架构风险，建议立即做）

| # | 动作 | 理由 |
| --- | --- | --- |
| L0-1 | **补回护栏**：重建 `tools/_test_minibar_split.py`，并把现有静态断言（`_test_import_side_effect_free`、`_test_module_catalog`、`_check_spec_excludes`）打包成一条 `tools/static_checks.py` 命令，纳入 `run_tests.py --safe` | 路线图 §3.3 明写护栏已丢失；现在改动越多、越需要它 |
| L0-2 | **新增一条静态断言：禁止新增函数内惰性 import 形成环**。扫描 `src/**.py`，对"函数体内 import 本项目模块"且构成回边的情况报错 | 6 组环是惰性 import 堆出来的；先冻结增量，再治存量 |
| L0-3 | `tools/` 分家：78 个 `_test_*` 移入 `tests/`；一次性逆向/提取脚本（`batch_decompile*`、`extract*`、`step1_extract*`、`debug_pyc`、`diagnose`）移入 `tools/_archive/`；38 个非 .py 产物移到 `tools/_out/` 或直接删 | 157 个 .py 混在源码目录，新人无法分辨"哪个是测试" |

| L0-5 | `.ipc_key` 从项目根移入 `userdata/`（当前仅靠 `.gitignore` 兜底，一旦 `git add -f` 或换机器就泄露） | 该文件是 64 位十六进制 IPC 密钥 |

### L1 · 拆完剩余的两个上帝模块（延续既有手法）

**L1-A　`netlink_window.py` 3,696 行 → `ui/netlink/`（先做这个，边界比脚本表格干净）**

方法名前缀实测分布（123 个方法）：`_on_*` 35、`_shot_*` 9、`_refresh_*` 7、`_tip_*` 5、
`_close_*` 5、`_pair_*` 4、`_open_*` 4、`_rs_*` 3、`_audit_*` 3、`_xfer_*` 2、`_web_*` 2，其余零散。

建议拆法（与 `src/netlink/` 领域层一一对应，后者已是 16 个文件的干净分层）：

```
ui/netlink/
  window.py      # NetLinkWindow 门面 + _build + 事件泵（保留类名与公开方法，宿主零改动）
  panels.py      # _refresh_* / _refresh_table / _refresh_detail / _row_tag / _perm_text
  shot.py        # _shot_*  远程截图
  pairing.py     # _pair_*  + _on_auth
  remote.py      # _rs_*    远程操控 / _xfer_* 传输
  web.py         # _web_*   网页面板
  audit.py       # _audit_* 审计
  sched.py       # _sched_text / _refresh_sched_label
```

手法与 `settings_window.py` 完全一致：**薄壳 + `__getattr__` 动态转发**，
`netlink_window.py` 退化为 re-export，宿主 `ACRPA.py` 与 `tools/_smoke_netlink*.py` 不用改一行。

**L1-B　`ACRPA.py` 6,299 行 → 抽出脚本表格（配合 §3.4 一起做）**

顺序很重要：**先建模型，再搬视图**。

1. 先落地 `ScriptTableModel`（路线图 §3.4）：把 `state._editor_rows` / `_undo_stack` /
   `_redo_stack` / `_editor_clipboard` / `breakpoints` 收进模型对象，
   行身份用**稳定 ID** 而非 `tree.index(item)`（当前 `ACRPA.py:1926/1994`）；
2. 模型变更发射**行级失效事件**，替换 `ACRPA.py:2072-2089` 的全量 `tree.delete(...)` 重建；
3. 最后把视图函数搬进 `ui/script_table.py`，`ACRPA.py` 只保留装配。

不做第 1、2 步直接搬文件，等于把 500 行 O(n) 控件 churn 换个地方放着。

### L2 · 切断全局状态与依赖环（**本轮的核心**）

**L2-A　`utils.py` 溶解为 4 个无 tkinter 的核 + 4 个 UI 模块（优先级最高）**

```
core/log.py        # log1 / register_log_sink / _broadcast_log / set_tlog / ThreadSafeLog  ← 27 个模块等着它
core/fs.py         # atomic_save / atomic_write_bytes / safe_filename / _sanitize_segment
core/version.py    # parse_version / compare_versions / version_tuple / version_gt
core/util.py       # _safe_get 等纯函数
ui/theme.py        # 已有；把 _darken / rel_luminance / text_on / _colors / themed 收进来
ui/scale.py        # dpi_factor / scaled / sp / tk_px / radius / ctrl_h / gap / icon_size / font
ui/widgets.py      # create_card / _btn / tooltip 家族 / set_accessible_name / bind_icon_activate / bind_sel_bold
ui/geometry.py     # win_virtual_bounds / center_geometry / dialog_geometry / place_dialog / show_toast
```

`utils.py` 保留为**薄壳 re-export**（沿用 `settings_window.py` 已验证的手法），存量 51 个导入点一行不改。

**验收（可量化）**：在无 tkinter 解释器下 `import engine`、`import workflow` 成功；
`import utils` 仍然可用（走兼容壳）。

**L2-B　`state.py` 拆为 `state/` 子包**

```
state/
  __init__.py   # 薄壳 re-export：state.running / state.config / state._editor_rows 全部照旧可访问
  config.py     # _config_schema / config / config_to_dict / on_config_change / UI 偏好键
  runtime.py    # running / pause_event / exec_state / recording / breakpoints / debug_* / _exec_timings
  editor.py     # _editor_rows / _editor_clipboard / _undo_stack / _redo_stack / _editor_modified
  paths.py      # APP_DIR / DATA_ROOT / USERDATA_DIR / PORTABLE / _resolve_data_paths
```

关键点：`state/__init__.py` 必须用 `__getattr__` 转发（而非 `from .config import *`），
否则 `state.running = True` 这类**写操作**会写到子模块而非壳，`ACRPA.py` 读到的是旧值。
这是本项目薄壳手法唯一需要小心的坑（`settings_window.py` 只转发只读属性，没遇到）。

`paths.py` 拆出后顺带解决：路径解析目前与运行态混在一起，导致 `config.json` 落盘时机难以测试。

**L2-C　用接口 + 构造注入逐个拆环**

以环 3（`engine ↔ acrpa_api`）为模板，`acrpa_api.py` 已经在注释里承认了问题，改造意愿最明确：

1. 定义 `core/api.py`：`class EngineFacade(Protocol)`，声明 `acrpa_api` 真正用到的引擎能力；
2. `acrpa_api.AcrpaAPI(engine_module=...)` 改为接受 `EngineFacade`（其文档说已支持构造注入，只需把类型换掉）；
3. `engine.py:1877/1989` 处改为注入自身实现的 facade，删除惰性 `import acrpa_api`。

环 1/2/4 同法处理：把 `engine` 需要的能力抽成窄接口，由 `workflow` / `browser_backend` /
`ai_enhance` 在构造时接收。环 5（`dialogs ↔ help_window`）建议直接把公共部分下沉到
`ui/dialog_base.py`。环 6 让 `single_instance` 只回调注册进来的函数对象，不再 `import ACRPA`。

**每拆一组，L0-2 的静态断言就少一条告警——这是可度量的进度。**

**L2-D　`bind(**kw)` → `AppContext` 注入对象**

```python
# 现状（mini_bar.py:86-91）：17 个符号写进模块 globals
def bind(**kw): globals().update(kw)

# 目标：显式上下文对象，缺字段在构造时即失败，而非运行期 NameError
class AppContext:
    root, colors, fonts, tlog, callbacks...  # 字段显式声明
```

先迁移 `mini_bar`，再 `dialogs`，最后 `settings`。每迁一个补一个静态断言。

## 7. 明确不建议做的事

1. **不要为了"目录好看"提前做 L3。** 56 个平铺文件确实不好看，但在环未拆、`state`/`utils`
   未溶解之前搬迁，只会把耦合搬到新目录里，同时引入路径错误风险。
2. **不要把 `src/` 改成正式包（`from acrpa import state`）。** 这会全量改写 71,828 行里的每一个
   本地 import，收益（命名空间干净）远小于风险。保持扁平 sys.path + 增量加子包即可。
3. **不要一次性删掉 `utils.py` / `state.py` 的兼容壳。** 它们有 51 / 54 个调用点，
   壳留着成本几乎为零，删掉则每次都要改调用点。
4. **不要为 L1-A 新造抽象。** NetLink 的 8 个分组是方法名前缀实测出来的既有边界，
   照搬即可；新造抽象反而会打断与 `src/netlink/` 领域层的对应关系。
5. **不要用惰性 import 解决新的循环依赖。** L0-2 的静态断言就是为了把这条路堵上。
