HOW IT WORKS

Up and Running in 3 Steps

From "record it once" to "fully automated" — in as little as 3 minutes.

①

Record it, or write it in Excel

Use the built-in recorder to run through the steps once and generate a script automatically; or write one command per row directly in a .xls sheet — 51 built-in commands, if you can fill a spreadsheet you can write a script.

②

Tune parameters, let AI locate

Just adjust the window title and parameters; if fixed coordinates are unstable, switch to "AI Find Image" and describe the element in plain language, or use OCR "Click Text" to locate by text — small UI changes stay adaptive.

③

Run it, then let it run

Run immediately, debug with breakpoints, or hand it to the scheduler; you can also distribute scripts in bulk over NetLink to many machines on the LAN.

CORE FEATURES

Core Features

From basic automation to intelligent workflows, ACRPA covers the entire desktop automation stack.

📦

Excel-driven scripts

Uses .xls spreadsheets as script files — commands in column A, parameters in columns B–J. Orchestrate automation without programming; the learning cost is minimal.

🖱

Image-based localization

Image recognition built on OpenCV / Pillow: full-screen and region-limited search, grayscale accelerated matching — locate and click any UI element precisely.

🪟

Window management

Operate Windows directly: activate, close, minimize, wait for a window to appear or disappear. Window-relative coordinates make it 10–100× faster than image matching.

🎬

Record & replay

Record mouse and keyboard actions (including drag, scroll and window activation), with wait intervals inserted automatically. Replay in one click — repetitive work is never manual again.

⏱

Scheduled tasks

Daily / weekly / interval / one-shot scheduling modes, executed silently in the background alongside the system tray and Mini Bar.

⚡

DD driver boost

Optional kernel-level high-performance input backend that simulates real keyboard and mouse input and is hard to detect. Supports direct / simulate / auto write modes with automatic fallback.

🧩

Workflow orchestration

Chain multiple scripts with a visual flow diagram (nodes / connectors / drag-and-drop) supporting four step types: script, parallel, condition and wait.

📊

Variable system

Set variables, read the clipboard, substring / replace, math operations — ${var} syntax works throughout, so complex data is easy to handle.

🔍

OCR recognition

Recognize text in a screen region, wait for text to appear, click on text. Compatible with PaddleOCR / Windows OCR / Tesseract — even dynamic interfaces can be automated.

🐞

Professional debugger

Breakpoints / conditional breakpoints, single-step, variable watcher, call stack, execution timing, run-to-cursor and skip-line — problems become obvious.

🌓

Dark mode

Switch between light and dark themes in one click. With the system tray and the Mini Bar floating status strip, automation runs quietly in the background.

📜

Logs & marketplace

Structured levelled logs with daily rotation, automatic cleanup and one-click export; built-in script marketplace (works offline) that keeps expanding the script ecosystem.

🔄

Automatic updates

Self-checks for new versions at startup and fetches the manifest with multi-source fallback (GitHub Releases → raw manifest → CDN mirror). Downloads show progress and are verified by sha256; if a mirror serves an old package it switches source automatically, then a one-click restart completes the replacement without touching your config or scripts.

🌐

Browser automation

Built-in Playwright web automation: open a page, click, type, wait for elements, full-page or element screenshots — desktop and web steps can be chained in the same script.

🛡️

Safety guards

Runaway protection (flick the mouse to abort immediately), maximum execution time limits, stop-on-error and failure retry policies — unattended runs still end safely.

NETLINK · MULTI-DEVICE

One PC, Many LAN Machines · NetLink

See the progress of every machine on the LAN at a glance, run / pause / stop remotely, distribute scripts in bulk, and view it all from a phone browser — built entirely on the Python standard library with zero extra dependencies, a multi-machine control plane rarely found in tools this lightweight.

⚡ Zero extra dependencies (pure stdlib) 📱 Phone browser dashboard 📦 Bulk script push · run after push 🔐 Pairing code + privilege levels + audit log
🖥️

Real-time multi-machine monitoring

Device list plus run state, current script, progress (line number / loop count / elapsed time), live log stream and scheduled task status — select a device and see it immediately, no manual subscription needed.

🔐

Pairing authentication

Enter a 6-digit pairing code (valid for 600s by default) to pair. The PIN never travels over the network: a PBKDF2-HMAC-SHA256 derived key plus nonce/HMAC challenge-response is used, and 5 consecutive failures lock the connection. Keys are stored in the Windows credential store, so reconnects after pairing need no PIN.

🎛️

Remote control

Run / pause / resume / stop. The controlled machine prompts for confirmation on first control (this device can be remembered). Commands are serialized and acknowledged to all controllers; every remote command and screenshot request is written to the audit log.

📦

Script distribution

Push local .xls / .xlsx / .json files to controlled machines: 64 KB chunking with dual sha256 and size verification on the final frame, leaving no leftover files on failure. Supports bulk delivery to multiple devices and "run right after push".

📱

Read-only browser panel

A built-in single-page panel served by http.server (default port 19712, off by default). Check multi-machine progress and logs straight from a phone or tablet browser; token auth (query string / cookie / bearer) with zero write operations.

🛡️

Optional TLS encryption

Encrypted channel with a self-signed certificate based on the stdlib ssl module; the peer certificate sha256 fingerprint is pinned (TOFU) and mismatches are rejected outright. Off by default, enable as needed.

NL 01 · Device Linking

All machines, one screen

Device list, run state, current script, line number / loop count / elapsed time and the live log stream all in one window — see the whole picture without switching machines.

NL 02 · Pairing

PIN + challenge-response + credential store

The controlled machine generates a 6-digit pairing code and the controller enters it to pair. Keys are never written to config.json, reconnects need no PIN after pairing, and first-time control still requires confirmation on the controlled side.

NL 03 · Browser Panel

Viewable from a phone browser

A built-in read-only web panel (default port 19712, off by default). Scan a QR code or type the address on a phone or tablet to view multi-machine progress and logs — the panel contains no write operations at all.

CHANGELOG

Release History

Continuous iteration, recently focused on the update mechanism, workflow orchestration, AI enhancement and stability. See GitHub Releases → for the full history.

Rebuilt on the v0.1.25 baseline to fix the unstable wiring introduced in v0.1.26: an undefined _update_pending made _periodic throw a NameError every 100 ms, which broke the status-bar and execution-progress refresh path and prevented the update flag from being set; and an unimported show_update_dialog made the status-bar update entry point dead on click. All v0.1.26 improvements are retained: the reworked update mechanism (multi-source fallback / semantic version comparison / sha256 verification / one-click restart self-update for the portable build / fixed version source for the packaged build), engine-level command failure semantics with workflow error propagation, and the release toolchain with build assets under management.

v0.1.26
2026-09-13

Update mechanism reworked: fixed the distorted version number after packaging (the EXE always reported an old version, breaking update checks and the About page entirely). Update checks now use multi-source fallback (GitHub Releases → raw manifest → CDN mirror) and return as soon as one source works; if a source reports a version that is not new enough, the remaining sources are probed and the highest is taken, so a stale mirror cache or a network glitch no longer yields a false "already up to date". Version comparison handles the v prefix, uneven segment counts and pre-release suffixes. Network transport is dual-stack (requests → system certificate store), fixing silent failures behind corporate TLS interception. Downloads retry multiple candidate direct links one by one, stream progress, verify sha256 and size, and re-check the VERSION inside the package, switching source automatically when a mirror serves an old package. A new in-app update window and one-click restart self-update for the portable build replace only the main program and VERSION — config, scripts, templates and logs are never touched. Also fixed "command failure silently reported as success" together with the broken stop_on_error and retry behaviour.

SECURITY · TRUST

Safe Enough to Double-Click, Open Enough to Read

The hardest question for a desktop automation tool is "should I dare install it?". ACRPA answers with: open source, local, install-free.

🔓 Open and auditable｜MIT licensed, source fully public and mirrored on GitHub and Gitee — anyone can review it and build it themselves.
🔑 Keys stay on your machine｜AI API keys are stored in the Windows credential store, never written to config.json, and your activity is never uploaded.
💻 Local-first execution｜Core automation runs on your machine with no server dependency; with AI disabled it is fully offline.
📦 Portable, no installer｜A single-file exe that runs once unzipped. It writes nothing to the system and installs no runtime — deleting the folder uninstalls it.
⚠️ On first run Windows may show "Unknown publisher" / SmartScreen. This is normal and happens because the binary is not signed with a paid code-signing certificate — click "More info → Run anyway", or add the install folder to your antivirus allowlist.

Known Limitations (Stated Honestly)

  • The current is a pre-release (beta); validate it in a test environment before putting it into production.
  • The exe is not signed with a paid certificate, so SmartScreen or antivirus software may block the first run (see the note above for how to proceed).
  • Scripts support .xls only (.xlsx is not supported yet); image assets must be PNG, and avoid non-ASCII characters in paths and filenames.
  • NetLink is designed for the local network (LAN); real-world cross-machine validation is still in progress and the web panel is off by default.
  • AI features need your own API key (DeepSeek / Qwen / OpenAI / local Ollama and other OpenAI-compatible endpoints are supported).
FAQ

Frequently Asked Questions

A few things you may want to know before downloading.

Do I need Python installed?
No. Download the portable exe and double-click to run — no Python installation required. You only need Python 3.7+ if you want to modify the source.
Which operating systems are supported?
Windows (x64) desktop only, available as a portable build and an installer. macOS and Linux are not supported at this time.
What format are scripts in?
Excel .xls spreadsheets (.xlsx is not supported yet): one command per row, with the command name in column A and parameters in the following columns. Ten templates and a recorder are built in to generate scripts automatically. Image assets must be PNG, and avoid non-ASCII characters in paths and filenames.
Is it really free? Can I use it commercially?
Completely free under the MIT license. Individuals and companies alike may use, modify and commercialize it. No feature or time limits, no ads, no in-app purchases.
Antivirus or SmartScreen flags it. What now?
Because the binary is not signed with a paid certificate, the first run may be blocked. Click "More info → Run anyway" or add the folder to your allowlist; you are also welcome to build from source and verify it yourself.
Do the AI features cost extra?
ACRPA itself is free. AI uses your own model key (DeepSeek / Qwen / OpenAI / Anthropic / local Ollama and so on) and is billed by that provider based on usage. Without AI it runs fully offline at zero cost.
How is it different from other RPA tools?
It is lighter (single file, no installation), more approachable (an Excel spreadsheet is the script, so anyone can read and write it), supports local AI visual localization, and is fully open source so you can modify the code for free.
Are my scripts and data safe?
Automation runs locally, keys are kept in the system credential store, and the program neither collects nor uploads your operational data.
